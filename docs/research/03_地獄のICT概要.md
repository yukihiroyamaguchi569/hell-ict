## 1. どんな研修か

> **「ありえないほどひどい病院に放り込まれ、AIを相棒に生き延びろ。最初に生還したチームの勝ち。」**

参加者は、複数のアウトブレイクが同時進行する架空の病院に、着任初日の感染制御チーム（Infection Control Team）として放り込まれます。次々に降りかかる難問を、**AIを使わなければ時間内に処理しきれない密度**で浴びせ続けます。

形式は**レース**です。全チーム同時にスタートし、提出物が自動判定を通過すると次のステージが解錠されます。先行チームの位置は全員のリーダーボードに表示され、焦りを演出します。最初に完走したチームが優勝です。

道中には罠が仕掛けてあります。**罠にハマると減点ではなく時間を失う**設計です。レースなので時間がもっとも痛く、速さだけで突っ走るチームは罠に沈み、疑い深いだけのチームは速度で負けます。**「速く、かつ疑え」**がこの研修の緊張構造です。

## 2. 学習目標

参加者には「最速でクリアせよ」としか伝えません。裏側で以下を習得させます。学習目標が開示されるのは最後の振り返りの時間です。

| # | 習得スキル | ゲーム内での現れ方 | |
|---|---|---|---|
| 1 | 要件を言語化してAIに渡す | 曖昧な依頼メールをAIへの指示に翻訳する | 光 |
| 2 | 汚いデータをAIで整形する | ぐちゃぐちゃのラインリストを渡される | 光 |
| 3 | 文書をAIに書かせ、読み手ごとに書き分ける | 職員通知・家族説明・報道リリース | 光 |
| 4 | 画像生成で伝わるビジュアルを作る | 面会制限ポスター | 光 |
| 5 | ソース接地型AIで根拠付き回答を得る | 院内マニュアルを読み込ませて照会 | 光 |
| 6 | **AIの出力を検証する（ハルシネーション耐性）** | AIがもっともらしい嘘の基準値を出す罠 | **影** |
| 7 | **情報を渡す／渡さないの判断** | 患者個人情報を送信すると罰ゲーム | **影** |

**光のステージで「AIはすごい、もっと使おう」と加速させたところに、影の罠を刺します。**便利さを体験した直後だからこそ罠が刺さる、という設計です。

## 3. 実施要件

| | |
|---|---|
| 対象 | 医療機関職員（ICT/ICN・検査技師・薬剤師・事務・看護管理者など）。AI初心者を想定 |
| 編成 | 3〜4人1組。**チームに1台**のノートPC |
| 所要 | 120分（本編90分＋振り返り30分） |
| 使用ツール | アプリ内蔵のGPT-4o（運営側プロキシ経由）と、参加者自身のNotebookLMアカウント |
| 会場要件 | 各チーム1台のPC、インターネット接続、スクリーン |

**AIツールを2本立てにしているのは教育設計です。**素のLLMは速いが嘘をつく、ソース接地型は根拠を示す——この使い分けを、罠にハマってから復旧する流れで体験させます。

1台のPCを3〜4人で囲む構成にしているのは、役割を「決める／打つ／疑う／照合する」として分担させ、**AIの出力を全員で検品する**時間を作るためです。速度のための並列作業ではありません。

## 4. 進行

| ステージ | 目安 | 課題 |
|---|---|---|
| Prologue 着任 | 2分 | 穏やかなBGMと歓迎メール。2分後にすべてが変わる |
| Stage 1 火の手 | 12分 | 日付形式も全角半角も混在した汚いExcelを、統一ラインリストへ整形する。手作業なら25分、AIに渡せば3分。**罠のない成功体験ステージ** |
| Stage 2 二正面 | 18分 | 別病棟でも集団発生。職員向け緊急通知・保健所への第一報・外国人家族への説明文を同時に作る。**持ち帰ってそのまま使える用例集** |
| **Stage 3 嘘**（罠） | 15分 | 消毒薬の希釈濃度と接触予防策の解除基準をまとめる。**本研修の心臓部** |
| **Stage 4 情報漏洩**（罠） | 12分 | 患者家族への返信文を作る。手元には実名・患者ID入りのカルテ抜粋（すべて架空） |
| Stage 5 ポスター工房 | 12分 | 面会制限の告知ポスターを画像生成で作る。罠疲れの後のご褒美ステージ |
| Final 記者会見 | 15分 | 同じ事実を院長・家族・職員・報道の4者に書き分ける。**ここを通過してゴール** |
| Debrief | 30分 | 表彰と種明かし |

## 5. 罠の2ステージ

### Stage 3 嘘 — ハルシネーション耐性

GPT-4oが自信満々に**嘘の基準値と存在しないガイドライン名**を出力します。レースの焦りが「そのまま提出」を誘発します。

提出すると画面が暗転し、「あなたの提出した基準で、院内感染が3名に拡大しました」と告げられ、罰ゲームとして追加の整形作業が課されます。**正解ルートは、配布されている院内感染対策マニュアルPDFをNotebookLMに読み込ませ、根拠ページ付きで照会すること**です。罠に気づいたチームは最初からこのルートを通り、大きくリードします。

罠は教材側に仕込んであり、**モデルの性能や機嫌に依存しません**。汚染教材とシステムプロンプトの二段構えで、確実に発動します。

これは意地悪ではなく**予防接種**です。安全な場で一度刺されておくことで、現場で刺されずに済みます。振り返りで必ず種明かしをします。

### Stage 4 情報漏洩 — 渡す／渡さないの判断

患者家族からの苦情まじりの問い合わせに返信文を書かせます。手元にはフルネーム・患者ID・病名入りのカルテ抜粋があります（**すべて架空のダミーデータです**）。

これをAIチャットに送信した瞬間、**送信はサーバ側でブロック**され、警報とともに「個人情報インシデント発生」となり、AIの使用がロックされた状態でインシデント報告書を自力作成させられます。正解は、固有情報を匿名化・抽象化してからAIに渡すことです。

**ダミー個人情報は外部のAIサービスへ送信される前に遮断します。**事故を安全に体験させるための設計で、実際に外部へ出ることはありません。実在の患者情報は一切使用しません。

### 罰ゲームの考え方

罰は減点ではなく時間で払わせます。内容も、追加の接触者リスト整形（＝Stage 1 の復習）やAIなしでの報告書作成（＝AIのありがたみの再認識）など、**罰の中にも学びがある**ものにしてあります。

大差がついて後続の心が折れないよう、キャッチアップ機構を用意しています。院内の相談窓口として登場するキャラクターが、一定時間停滞したチームに向こうから声をかけ、段階的にヒントを出します。ただし**罠ステージでは正解を絶対に漏らしません**。

## 6. 振り返り（Debrief）

- **表彰**：優勝（最速クリア）／監査賞（罠を最速で見抜いた）／ポスター大賞（全員投票）／名誉の負傷賞（罠に一番派手にハマった＝一番学んだ）
- **種明かし**：ここで初めて学習目標の表を見せます。「Stage 3 で嘘に気づけなかったチーム、手を挙げてください。……それが今日一番の収穫です」
- **プロンプトの振り返り**：優勝チームのプロンプトと、罠にハマった瞬間のプロンプトを、本人の了解を得たうえで画面に映して比較します
- **持ち帰り宣言**：1人1つ「明日から業務でAIにやらせること」を宣言します

## 7. 教育効果として測定できるもの

満足度アンケートで終わる研修と異なり、**測定可能な行動が設計に組み込まれている**点がこの教材の特徴です。

| 指標 | 取得方法 |
|---|---|
| Stage 3 の罠に提出前に気づけたか、復旧までの所要時間 | 提出物の自動判定 |
| Stage 4 で個人情報の送信ブロックが発火した回数 | サーバ側の検知記録 |
| ソース接地型ツール（NotebookLM）を使ったか | 提出物と操作記録 |
| 各ステージの通過時刻・完走率・総所要時間 | 進行記録 |

**AIとの対話本文（プロンプトと応答そのもの）は研究データとして取得しません。**対話本文は質問紙よりセンシティブな学習過程データにあたり、参加者自身のアカウントで動くNotebookLMを含むと外国にある事業者への情報提供の整理が必要になるためです。

なお振り返りの時間に行うプロンプトの比較は、参加者本人の了解を得たうえで行う**研修の一部**であって、研究データの取得ではありません。

## 8. 世界観とトーンの方針

舞台は聖クロノス総合病院（400床・地方中核・電子カルテは2003年製）という架空の病院です。トーンは**ブラックユーモア**で、現場の「あるある」を誇張します。

> 「院長は明日の朝、記者会見をすると言っています。誰も内容を知りません」
> 「日付が『7/3』『7月3日』『R8.7.3』『さんにち』で混在しています」

**禁止事項を明文化してあります。**実在の病院名・人物名は出さない。特定の職種を貶めない。理不尽の矛先は常に**組織と状況**へ向け、個人には向けない。罰ゲームも笑える理不尽に留め、人格を攻撃しない。

## 9. 現状

企画書 v0.3.1（2026年8月8日）まで作成済みで、シナリオ・UI設計・キャラクター設定が固まっています。現在はWebアプリケーションを開発中です。

「手作業25分の分量」「罰ゲーム3分」といった時間の見積もりは机上では当たらないため、**実測のテストプレイを2度組み込んだ**開発計画にしています。
