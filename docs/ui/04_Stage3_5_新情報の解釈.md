## 狙い

**長い論文をAIで要約し、その一語が院内の動きを変えるところまでを、6分で見せる。**

画面の役割は、論文・AIの要約・幹部への報告文を同時に見せること。参加者が「眼痛を探せ」という問題を解くのではなく、幹部から頼まれた要約を真面目に作った結果、次の感染対策に使える情報を見つける構造にする。

---

## 0. 開始：幹部からの転送メール

Stage 3の解錠後、`data-mode="crisis"`を保ったままヘッダーを `原因不明の発熱 14` に切り替える。開始演出は一通のメールだけで、全画面ブリーフィングや赤帯は使わない。

```
件名: 隣国の速報論文
差出人: 幹部

隣国の速報論文が回ってきたわ。
長いから、AIで要約して私に送って。
```

添付を開くと教材ビューアに英語の速報論文が出る。`[コピー]`を置き、AIチャットへ貼り付ける動線を塞がない。メール本文には、眼痛、発熱前、夜勤者、感染対策といった解法の手がかりを入れない。

---

## 1. 画面全体

Stage 2以降の3ペインを踏襲する。左に転送メールと論文、中央に報告欄、右にAIチャットを置く。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🏥 聖クロノス総合病院 ICT │ 原因不明の発熱 14              │ 47:16 │ B班 │
├────────────────┬────────────────────────────┬────────────────────────┤
│ 受信トレイ 1     │ ▸ 新情報の解釈                │ AIチャット              │
│ ────────────  │ ────────────────────────  │                        │
│ ● 幹部           │ 速報論文をAIで要約し、          │ 〔あなた〕論文を要約…   │
│   隣国の速報論文  │ 幹部へ報告してください。         │ 〔AI〕…                 │
│  📎 速報論文.pdf │                              │                        │
│                │ ┌─ 幹部への要約 ───────────┐ │                        │
│                │ │                              │ │                        │
│                │ └──────────────────────────┘ │ [                    ] │
│                │          [ 幹部へ報告 ]         │ [送信]                 │
├────────────────┴────────────────────────────┴────────────────────────┤
│ Prologue ─ S1 ──── S2 ──── S3 ──── ◆ ──── S4 ──── S5 ─── Final     │
└──────────────────────────────────────────────────────────────────────┘
```

中央の依頼文は「速報論文をAIで要約し、幹部へ報告してください」だけにする。抽出すべき症状や、その後の対応をUIで教えない。

---

## 2. 要約報告後の一往復

要約が条件を満たすと、院内連絡先ウィンドウが一度だけ前面に出る。幹部は常駐せず、この画面を閉じたら戻らない。

```
〔幹部〕要約は読んだわ。
〔幹部〕それで、あなたたちはこれからどうしたいの？

[                                                    ]
                                      [ 送信する ]
```

自由記述を1ターンだけ受け付ける。回答に応じて選択肢やカードを出さない。参加者が、論文から得た情報を「夜勤者に眼痛がないか確認する」という行動へ自分たちで翻訳する余地を保つためである。

具体性が足りない場合は、同じウィンドウ内で一度だけ「誰に、何を確認したいのかを教えて」と返す。眼痛という正解語は示さない。

---

## 3. クリア画面：接点が消える小さな報酬

条件を満たす行動提案を送ると、入力欄を閉じ、幹部の結果報告を表示する。

```
〔幹部〕分かった。夜勤者を確認する。
〔幹部〕……発熱はないけれど、眼痛を訴える応援看護師が一人いたわ。
〔幹部〕配置はこっちで変える。少しはやるわね。
```

続けて、中央ペインを覆う小さなクリアカードを出す。Stage 3の暗転、Stage 4の警報と見分けるため、背景は落とさず、`--ok`の緑だけを使う。

```
         接点をひとつ、減らした。

   新情報を読み解き、これ以上の拡大を防ぎました。
```

カードの背景には、応援看護師が二病棟をまたぐ予定だった配置線が消え、代替担当へ細い線が引き継がれる簡易図を置く。病原体や感染経路の図解はしない。参加者の働きで減ったのは、確定した感染連鎖ではなく、拡大しうる接点だからである。

## 実装メモ

- ステージ名は画面に **「新情報の解釈」** と表示する。全ステージの名称・番号の見直しは別作業とし、`Stage 3.5`を画面上に固定表示しない。
- 論文ビューア、`[コピー]`、AIチャットはStage 2・3の器を再利用する。新しいAI機能や新しい画面遷移は作らない。
- **実装との差分（2026-08-23テストプレイ向けブランチで確認）**:
  - 幹部の一往復は、本文が想定していた「院内連絡先（PHS・苅部さん）ウィンドウ」ではなく、**専用の
    一回きりオーバーレイ（`#ov-s35-kanbu`）**で実装されている。常駐する相談窓口（苅部さん）を
    増やさないという意図は変わらないが、UI部品としては別物——PHSの窓は流用していない。
  - リーダーボードの停留所は、Stage 3.5専用のものを追加せず、**Stage 3の停留所を共有する**。
    `TEAMS[2].pos` はStage 3.5クリア（Stage 4解錠）時にのみ進む。
  - Stage 3.5のクリア時のみ、次のシーンへ**実際に自動遷移する**（`go("s4")`）。他ステージのクリアは
    状態更新のみで留まりシーン遷移を伴わないのと異なる——devbar・URLハッシュ単体起動での配線検証に
    必要なための例外。
  - Stage 3クリア→Stage 3.5開始は自動遷移する（`stage3UnlockSequence()`が`go("s35")`を呼ぶ）。
- クリア後は通常の解錠演出へ戻し、Stage 4を開ける。ここでタイマーや罰を追加しない。
