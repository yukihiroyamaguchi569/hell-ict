# Stage 1：火の手（UI設計）

**地獄のICT UI設計 / 目安12分・`alert`・罠なし**
親企画書: [../企画書.md](../企画書.md) ｜ シナリオ: [../scenario/02_Stage1_火の手.md](../scenario/02_Stage1_火の手.md) ｜ 器: [00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md)

## 狙い

**3ペインのシェルが、初めて全部埋まる画面。** ここで参加者は
「左のメールを読み、右のAIに投げ、中央に提出する」という**本編の基本動作**を体で覚える。
Stage 2 以降はこの動作の反復と応用でしかない。

そしてシナリオ側の絶対条件——**ここで詰まらせない**。
UIの仕事は、AIを使えば3分で終わることを**画面の作りだけで示唆する**こと。ただし説明はしない。

> 📌 UI設計上の絶対条件: **判定NGを「失敗」に見せない。** 罠のないステージで敗北感を与えると、
> Stage 3 で本物の罠が来たときの落差が消える。ここでの NG は**赤ではなく橙**、
> 文言は叱責ではなく**どこを直せばよいかの提示**にする。

## 1. 左ペイン：着弾メールと添付

### メール表示

```
────────────────────────────────
件名: 至急！！MRSAのやつまとめて
差出人: 5A病棟 師長
────────────────────────────────
新しいICTの方ですよね。悪いけど急ぎで。
5A病棟でMRSA疑いが出てます。とりあえず
手元の記録、そのままのExcelで送ります。

これ、感染対策の会議で使える形にキレイに
まとめてください。日付とかバラバラです
みません、私が作ったんじゃないので。

朝の申し送りまでに疫学曲線の材料も要る
そうです。よろしく！
────────────────────────────────
📎 5A病棟_MRSA_記録_最新版(2)_コピー.xlsx
```

- 2003年の書式（[00](00_共通シェルと通奏低音.md) §8）。等幅寄り、罫線、角丸なし。
- **ファイル名を省略しない。** `最新版(2)_コピー` が笑いどころなので、
  左ペインが狭くても折り返して全部見せる。省略記号で隠したら台無し。
- Prologue の3通は既読（`○`）として残す。**消さない。**
  Stage 3 で「そういえば初日のメールに書いてあった」と戻れる導線になる。

### 添付ファイルの扱い

タップすると**教材ビューア**が中央ペインの上に開く。

```
┌─ 5A病棟_MRSA_記録_最新版(2)_コピー.xlsx ─────────── [コピー] [DL] [✕] ┐
│ ※このファイルは5A病棟師長が個人的につけている記録です。正式なものでは… │
│ 5A病棟の状況　7月分                                                │
│                                                                  │
│ 患者ＩＤ  なまえ      びょうとう  採取日      MRSA   発熱    メモ     │
│ ００１    佐藤　一郎   5A病棟     7/3        陽性   あり    個室へ    │
│ id-2     鈴木  花子              7月3日     (+)   38.2℃            │
│ no.3     高橋健      （結合）    R8.7.3     ポジ   なし             │
│ ４番     田中　みゆき            さんにち    ＋     あり    家族面会あり│
│ …                                                                │
└──────────────────────────────────────────────────────────────────┘
```

**設計の要点:**

| 項目 | 決定 | 理由 |
|---|---|---|
| 表示 | 見た目を整えない。**汚いまま出す**。白い紙として固定し、テーマに追従させない | 結合セル・全角・空行が見えないと課題が伝わらない。アプリの面で描くと「添付ファイル」に見えない（[00](00_共通シェルと通奏低音.md) §8） |
| **[コピー]ボタン** | **必ず置く** | これがこのステージの生命線。次項 |
| [DL] | 実ファイルをR2から落とせる | Excelで開きたいチーム、NotebookLMに渡したいチーム向け |
| 目印 `★` | **配布版では消す**（シナリオ側の指定） | 伏線に気づかせない |

### [コピー]ボタンが Stage 1 の生命線

**「手作業25分／AI3分」の落差は、貼り付けが一瞬でできて初めて成立する。**
教材を手で選択させたら、それだけで数分溶ける。ワンタップで全文がクリップボードに入ること。

ただし**「AIに送る」ボタンは置かない**。コピーまでで止める。
そこから先——どのAIに、どんな指示と一緒に渡すか——が**このステージで学ばせたい判断**そのもの。
自動化した瞬間に研修が消える。

## 2. 中央ペイン：課題と提出

### 課題カード

課題文は**1行**にする。

> 統一されたラインリストに整形し、疫学曲線の材料を提出せよ。

正規化ルールの表（患者ID は 001形式、採取日は ISO……）は**画面に出さない**。
出したらプロンプトにそのまま写せてしまい、「要件を言語化してAIに渡す」（企画書§2の学習目標①）が死ぬ。

代わりに提出フォームの**列見出しだけ**を示す：`患者ID / 氏名 / 病棟 / 採取日 / MRSA結果 / 発熱 / 備考`。
**何を作ればいいかは分かるが、どう作るかは自分で言語化させる。**

### 提出フォーム

- 大きなテキストエリア（CSV / TSV / 表の貼り付けを受け付ける）。
- 貼り付けると**即座に行数と列数を表示**する: `20行 × 7列 を認識しました`。
  提出前に監査役が数えられる。**判定を待たずに検品させる**のが狙い。
- [提出する] ボタンは**中央ペインの中**に置く。ヘッダーやフッターに逃がさない。
  監査役が「待って」と言える距離に、司令塔と監査役が同じ視線で見られる位置に置く。

### 提出したらフォームを1行に畳む

提出後、テキストエリアと操作ボタンを **`提出しました　20行 × 7列`** の1行に折り畳み、
空いた場所に判定を出す。

課題文・提出フォーム・判定を縦に並べたままだと、**判定結果が画面の外に出る**。
1台を3〜4人で囲んでいる状況で「結果を見るには手がスクロールする」は成立しない
——全員が同時に同じものを見られなくなる。**判定は必ず1画面に収める。**

差し戻しのときだけ [提出に戻る] を出し、フォームを元に戻す。

## 3. 判定演出

シナリオ側の判定は4項目（構造のみ・品質は問わない）。**逐次表示する。**

```
提出を確認しています…

  ✓ 必須列がすべて存在する          （200ms）
  ✓ 採取日が YYYY-MM-DD に統一      （+600ms）
  ✓ MRSA結果が 陽性/陰性 の2値      （+600ms）
  ✓ 行数が元データと一致（20行）      （+600ms）

  ─────────────────────────────
  Stage 2 を解錠しました
```

### なぜ一気に出さないか

**1項目ずつ点いていく2秒間が、チーム全員が息を止める時間になる。**
一瞬で結果が出ると、レースの緊張が1フレームで消費されてしまう。
逆に長すぎると（4秒超）「重いアプリ」になる。**合計2秒**を基準とする。

### NG時

```
  ✓ 必須列がすべて存在する
  ✓ 採取日が YYYY-MM-DD に統一
  ✗ MRSA結果が 陽性/陰性 の2値
      → 3行目に「ポジ」、5行目に「(+)」が残っています
  ─ 行数の確認は中断しました
```

| ルール | 内容 |
|---|---|
| 色 | `--warn`（橙）を使う。**`--accent`（深紅）を使わない** |
| 文言 | 何行目の何がダメかを**具体的に**言う。「形式が不正です」で突き放さない |
| 打ち切り | 最初のNGで以降の判定を中断する。全部ダメ出しすると心が折れる |
| 再提出 | 回数無制限。ペナルティなし。**罠のないステージだから** |
| 記録 | NGの回数と内容はサーバに残す（P0の実測・難易度調整の材料） |

### 解錠演出

- `unlock` オーバーレイ（[00](00_共通シェルと通奏低音.md) §9）。`--ok` の帯が横に走る。
- 続けて師長から**1通だけ**メールが届く:

  > **「え、もう？ …助かる。あなた達、話が早いわね。」**

  成功の報酬は承認（シナリオ側）。**スコアも星も出さない。** レースで返ってくるのは順位だけ。
- リーダーボードの自チームマーカー `◆` が S2 へ滑る。
- 院内状況インジケータが `原因不明の発熱 3` → `5` に**静かに変わる**（[00](00_共通シェルと通奏低音.md) §4）。
  演出をつけない。**解錠の喜びの陰で、誰も見ていない数字が増える。**

## 4. 右ペイン：AIチャット（初対面）

**このステージが、参加者とアプリ内AIの初対面。**

### 空の状態に何を置くか

プレースホルダは**極力何も言わない**:

```
（まだ何もありません）
```

使い方の例文、サジェスト、テンプレートボタンを**置かない**。
置いた瞬間に「AIすごい」が「アプリが教えてくれた」に化ける。
シナリオ側の狙いは**参加者が自分で気づいて貼り付けること**であり、
その瞬間の落差（25分 → 3分）が Stage 3 で罠を刺すための布石になる。

### 長文貼り付けへの配慮

汚いExcel全文（20行）を貼るので、入力欄が伸びる。

- 入力欄は最大3行分まで伸び、以降はスクロール。ペインが埋め尽くされない。
- 貼り付けた本文はチャット内で**折り畳んで表示**（`貼り付けたテキスト（20行）▾`）。
  展開して中身を確認できるが、既定は畳む。畳まないとAIの返答が画面外へ流れる。
- AIの応答（整形後の表）は**等幅で表示し、[コピー]を付ける**。
  そこから提出フォームへ貼るのが正規ルート。**「提出フォームへ送る」ボタンは置かない**（前述と同じ理由）。

### 送信前ゲートは Stage 1 でも通す

[00](00_共通シェルと通奏低音.md) §7 の送信前検査。Stage 1 では何も止めないが、
**同じ経路を通す**。Stage 4 で初めてこの経路が使われると、そこだけ挙動が違って見える。

## 5. 院内連絡先：情シスの田所さん

企画書§6のキャッチアップ機構。Stage 1 の担当は**情シスの田所さん（激務・皮肉屋・Excelの神）**。

### 滞留トリガー

| 経過 | 挙動 |
|---|---|
| 〜6分 | 何も起きない |
| **6分** | 未読バッジ `①` が光る。**自動で開かない**（[00](00_共通シェルと通奏低音.md) §6） |
| 9分 | 2通目。より具体的な観点へ |
| 11分 | 最終セーフティ。詰みを防ぐ（企画書§6「最終セーフティは必ず届き、詰みを防ぐ」） |

### Stage 1 は比較的親切でよい

罠のないステージなので、田所さんは**観点をはっきり示してよい**（シナリオ側「罠なし・比較的親切」）。
ただし**完成した表は作らない**。

> 〔田所〕また師長のExcelですか。あれ、日付の書き方が5種類くらいありますよね。
> 〔田所〕そういうの、手で直すもんじゃないですよ。……で、そっちにAIあるんでしょ？ うちには無いのに。

**皮肉で、AIの存在を思い出させる。** ヒントを「与える」のではなく、
「なんでそれ使わないんですか」と言わせる形にする。これなら参加者が自分でプロンプトを打つ。

## 6. このステージで**やらないこと**

| やらない | 理由 |
|---|---|
| 罠・警報・暗転 | シナリオ側の絶対条件。「**ここでは絶対に罠を出さない**」 |
| 品質採点・星・スコア表示 | 構造のみ機械判定。品質を採点すると詰まる |
| 発熱列の中身の検証 | 伏線をデータに温存する（シナリオ側「存在だけ必須」） |
| チュートリアル・ツアー | 説明した瞬間に「AI初体験の発見」が消える |
| 制限時間のカウントダウン表示 | 経過時間は出すが**残り時間は出さない**。締切を切ると詰まったチームが折れる |

## 実装メモ

- 判定は**ルールベースのみ**（企画書§7）。正規表現4本で足りる。LLMを呼ばない＝速い＝解錠が気持ちいい。
- 教材の実物（.xlsx）はP0で作成しR2へ。ビューアは**配布版**（`★`なし）を表示する。
  設計用の注釈版と取り違えると伏線が丸見えになる。**別ファイルとして管理する**（シナリオ側実装メモ）。
- 「手作業25分／AI3分」はP0で必ず実測（企画書§8）。**[コピー]ボタンの有無で所要時間が変わる**ので、
  実測時はボタンがある前提の導線で測ること。
- 滞留トリガーの分岐点（6/9/11分）は定数化する。目安12分のステージなので、実測で全部動く。
- NG提出のログはP0の難易度調整に直結する。**どの判定項目で最も落ちるか**を集計できる形で残す。
