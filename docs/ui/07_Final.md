> **レース後の振り返りステージ**へ全面改訂した。参加者に見えるステージ名は引き続き **`Final　会見`**

## 狙い

**判定の器（`.box`＋`.submit-area`・4欄）を使わない。** Stage 3 の3欄フォームを流用した旧UIは
役目を終えた。新UIの仕事は2つだけ：①S1〜S5の成果物を「対応の全体図」として視覚的に並べ直すこと、
②判定なしの一言入力を、レースの緊張から解放された落ち着いたトーンで受け止めること。

> 📌 UI設計上の絶対条件: **急かさない。** カウントダウンも、差し戻しの橙表示も、失敗に見える演出も
> 一切置かない。レースは Stage 5 で終わっている——Final は評価の場ではなく内省の場である。

---

## 0. 開始：ゴール演出からの任意遷移

Stage 5 の完走演出（ゴール画面）の中に **「振り返りへ進む」** ボタンを1つ置く。押した参加者だけが
Final へ進む——**自動遷移はしない**。急かされて次へ送られる演出ではなく、チームが望むタイミングで
振り返りを始められるようにする。

- ボタンを押さないまま画面を離れても構わない（Debrief運用上は、開始前にファシリテーターが声かけ
  してよい）。
- Final に入ると、事務長からの1通のメール（[07_Final_記者会見.md](../scenario/07_Final_記者会見.md)
  §状況が正典）が着弾する。

## 画面全体

Stage 1〜5 の3ペイン構成とは大きく異なる、**単一のボード画面**にする。左の受信トレイは残すが、
主役は中央の「対応の全体図」ボード。

> ⚠️ **2026-08-22 変更（ユーザー指示）: 右ペイン（AIチャット）は Final では表示しない。**
> 判定も罠も無い振り返りでAIへ投げる場面が一つも無く、出したままだと「まだ何か作らせるのか」と
> 読める。中央のボードは空いた幅ぶん広がる。あわせて、ステージ入場ごとのスレッド作成
> （`STAGE_THREAD_TITLES`）からも Final を外してある——開くことのできないスレッドだけが
> サーバに増えるのを避けるため。苅部さんも Final には出ない（既定）ので、院内連絡先も出さない。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🏥 聖クロノス総合病院 ICT │ 原因不明の発熱 14               │  --:--  │ B班 │
├────────────────────────────────────────────────────────────────────┤
│                     対応の全体図（振り返り）                         │
│                                                                      │
│  ┌ S1 ┐   ┌ S2 ┐   ┌ S3 ┐   ┌ S4 ┐   ┌ S5 ┐   ┌ ??? ┐              │
│  │引き継ぎ│  │統一   │  │正典に │  │保健所 │  │面会制限│  │ 引き継ぎ │              │
│  │メモ活用│  │ライン │  │基づく │  │への一覧│  │ポスター│  │ を書いて │              │
│  │       │  │リスト │  │対応方針│  │提出   │  │       │  │ ください │              │
│  └───┘   └───┘   └───┘   └───┘   └───┘   └─────┘              │
│                                                                      │

│  │ 次にこの病院へ来るICTに引き継ぎをしましょう。               │  │
│  │ 次のチームに伝えたい一言をチームで相談して入力してください。 │  │
```

- ヘッダーの経過時間表示は空欄または非表示にする（`--:--`）——レースは終わっているため、
  Stage 1〜5 と同じ経過時間タイマーを見せ続けると「まだ計測されている」という誤解を招く。
- リーダーボード帯（フッター）も、Final では表示しない。順位を左右しないことを画面の構造でも示す。

## 1. 対応の全体図：タイルが順に点灯する

シナリオ側 [07_Final_記者会見.md](../scenario/07_Final_記者会見.md) §対応の全体図 が正典。

| 項目 | 決定 | 理由 |
|---|---|---|
| タイル数 | S1〜S5の5枚固定（S3.5はS3のタイルに含める） | Stage 3.5がリーダーボードの停留所をStage 3と共有するのと同じ扱い（[04_Stage3_5_新情報の解釈.md](04_Stage3_5_新情報の解釈.md) 実装メモ） |
| 点灯順 | 画面遷移時に左から1枚ずつ、短い間隔（仮値400ms）で光らせる | 「バラバラに片付けてきた5つが、今つながる」演出。一括表示だと繋がりが伝わらない |
| タイルの文言 | チームの実際の結果（罠発火の有無・インシデント発火の有無等）に応じて出し分ける | 固定文言にすると振り返りにならない。失敗を隠さず、責めない言い方で示す（下記「文言の出し分け」） |
| 空白ピース | 最後（6枠目）に配置し、点灯済みタイルより淡い色・破線の枠にする。ラベルは「引き継ぎ」 | 「まだ埋まっていない」ことを視覚的に示す。ここに次の入力が来る |
| クリックの可否 | 点灯済みタイルはクリックしても何も起きない（読むだけ） | 振り返りは眺めるものであって、やり直す場所ではない |

### 文言の出し分け（例）

| ステージ | 成功時 | 失敗を経由した場合 |
|---|---|---|
| S1 | 「材料はあった。渡し方を知らなかっただけ」 | 同左（R1〜R3どの経路でクリアしても同じ文言でよい——Stage 1に失敗の記録は残らない設計のため） |
| S3 | 「もっともらしい過剰対応を、正典を読んで退けた」 | 「もっともらしい過剰対応に、一度は乗ってしまった」 |
| S4 | 「氏名を外し、IDだけで十分伝わる形にした」 | 「一度、氏名ごと渡しかけた」 |

> 📌 文言は責めるトーンにしない。「間違えた」ではなく「一度は～した」のように、**通過点として
> 淡々と示す**（CLAUDE.md トーンルール）。

## 2. 一言入力：判定なしのテキストエリア

```
┌──────────────────────────────────────────────────────────────┐
│ 次にこの病院へ来るICTに引き継ぎをしましょう。               │
│ 次のチームに伝えたい一言をチームで相談して入力してください。 │
└──────────────────────────────────────────────────────────────┘
                          [ ボードを完成させる ]
```

> 📌 旧設計の「明日の記者会見で、病院として最初に伝える一言」から「引き継ぎメモ」型へ改めた
> （Stage 1 の前任ICNメモと対をなす円環構成。設計意図の正典は
> [07_Final_記者会見.md](../scenario/07_Final_記者会見.md) §狙い）。

| 項目 | 決定 | 理由 |
|---|---|---|
| 判定 | **無い。** 空欄のまま提出できないことだけをUI側で防ぐ（ボタンを非活性にする） | Stage 5と同じ「なんとなく空のまま提出」防止と同じ発想だが、これは判定ではなくUI上の親切 |
| 文字数上限 | 短文を促す程度のプレースホルダ文言のみ（厳密な上限は設けない） | 「一言」という課題の性質上、長文を書かせない誘導はするが、機械的に切る必要はない |
| AIチャット | **表示しない**（2026-08-22 ユーザー指示で変更。旧: 「使える。判定への接続は無く罠・罰も無い」）。右ペインごと畳み、`sendAI()` のガードからも Final を外してある | 判定なしの振り返りにAIを使う場面が無いため（上記「画面全体」の⚠️）。**Workerの送信前PIIゲートを降ろしたわけではない**——不変条件（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §7・企画書§7）はそのままで、Finalには送信経路そのものが無いだけ |
| 提出後 | 編集不可。空白ピースが埋まり、ボードが完成する | Debriefでそのまま使うログになるため |

## 3. ボード完成演出

`unlock`（次のステージへの解錠）でも `#ov-goal`（レースの終端）でもない、**第3の締めくくり方**にする。

| 項目 | 決定 | 理由 |
|---|---|---|
| 見た目 | 空白ピースが埋まり、6枚のタイルが揃った状態のまま静止する | 「次に進む」演出ではなく「完成した」演出。自動で閉じたり遷移したりしない |
| 音 | 鳴らさない | 他のオーバーレイと同じくモックは無音のまま実装（本番はここでも音を検討する余地はあるが優先度は低い） |
| 次の画面 | エンディング（下記 §4）。それ以外は無い（Final はここで終わる。Debrief はファシリテータ運用） | レースに次のステージが無いのと同じ理由 |

## 4. エンディング：幹部の労いリレー → 感謝状

ボード完成の1拍後に始まる、判定の無い締めの2画面（設計意図の正典は
[07_Final_記者会見.md](../scenario/07_Final_記者会見.md) §エンディング）。

**① 幹部の労いリレー**（`#ov-f-relay`）: Stage 3 の一報（`#ov-s3notice`）と同じ肖像つきダイアログの器を
使い回し、院長→看護部長→事務長の順に中身だけ差し替える。

| 項目 | 決定 | 理由 |
|---|---|---|
| 送り | ［次へ］ボタン、または背景クリックでの早送り。自動タイマーは持たない | 読む速さはチームに委ねる（Stage 1 の処理結果ウィンドウと同じ流儀） |
| 最後の1人 | 事務長のボタンだけ文言と遷移先が違う（［感謝状を受け取る］→②へ）。背景クリックの早送り対象からは外す | 感謝状は明示的な操作でだけ踏ませる区切り |
| 肖像 | 各ステージで既出の3人をそのまま使う。新規の顔を出さない | 人格の連続性。美談化・別人化はしない |

**② 感謝状**（`#ov-f-handover`）: ゲームの最終状態。閉じる導線を持たず、`#final` へ再入場しても
この画面を直接復元する（アニメーションは再入場のたびに頭から再生する＝記念撮影に耐える）。

```
┌────────────────────────────────────┐
│  ┌──────────────────────────────┐  │  ← 賞状の台紙（四隅に角飾り）
│  │           感 謝 状           │  │
│  │        ──── ◆ ────           │  │
│  │  B班　御中                   │  │  ← 宛名＝参加者のチーム名
│  │ ──────────────────────────── │  │
│  │  （謝意の本文）              │  │
│  │  （申し送りの約束の本文）    │  │
│  │   ┌────────────────────┐     │  │
│  │   │ 「チームが記した一言」│     │  │  ← この画面の主役
│  │   └────────────────────┘     │  │
│  │              本日            │  │
│  │      聖クロノス総合病院  ㊞  │  │  ← 署名＋公印風の丸印
│  │      感染対策委員会          │  │
│  └──────────────────────────────┘  │
│   ──次にこの病院へ来る誰かは、    │  ← ナレーション（文書の外）
│     あなたたちが残した一言に      │
│     助けられて、始まる。          │
└────────────────────────────────────┘
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 文書の役割 | (1) 病院からチームへの謝意、(2) チームの一言を次のICTチームへ必ず申し送るという約束 | (2) が Stage 1 の前任ICNメモと対をなす円環の締め。だから一言の引用をこの画面から外さない |
| 宛名 | 参加者のチーム名＋「御中」 | 感謝状の受取人はチーム自身。名前は入室画面でチーム自身が入力したもの（[01_Prologue.md](01_Prologue.md) §①）を使い、必ず `esc()` を通す。未入室でdevbarから直接来た場合だけ既定値へ落ちる |
| 発行者 | 聖クロノス総合病院 感染対策委員会（署名＋公印風の丸印） | 個人ではなく組織として出す。実在団体印の模倣ではない |
| 一言の扱い | 必ず `esc()` を通して引用枠へ入れる | 自由記述をそのまま画面へ載せる唯一の箇所 |
| 色 | テーマ非依存の固定色（`.sysdlg`/`.viewer` と同じ流儀。紙の色・朱の印） | 院内文書という世界観を保つ。ダーク／ライト切替の影響を受けさせない |
| ナレーション | 文書の外（暗い下地の上）に置く | 演出と院内文書を混同させない |
| 閉じる導線 | 無い | `#ov-goal` と同じ「ここが最終状態」 |

## やらないこと

| やらない | 理由 |
|---|---|
| カウントダウン・締切バー | レースは既に終わっている。焦らせる理由が無い |
| `alarm`/`lock`/`blackout`/差し戻しの橙表示 | 判定そのものが無い |
| 4欄フォーム（`.box`＋`.submit-area`） | 旧設計の器。振り返り版では使わない（[07_Final_記者会見.md](../scenario/07_Final_記者会見.md) §本実装フェーズ候補（保留）に設計は残す） |
| リーダーボード帯の表示 | 順位を左右しないことを画面構造でも示す |
| タイルをクリックして編集させること | 振り返りは眺めるものであって、やり直す場所ではない |
| 一言に対する評価・添削 | 判定は無い。Debriefでの読み比べに委ねる |

## 実装メモ

- **判定ロジックは無い。** 旧・`checkFinal()`/`F_ORDER`/`F_REQUIRED`/`F_WRONG` は使わない
  （[07_Final_記者会見.md](../scenario/07_Final_記者会見.md) §本実装フェーズ候補（保留）に設計は
  保存してある）。
- タイルの出し分けに使うステージ結果（Stage 3の罠発火有無、Stage 4のインシデント発火有無等）は、
  チーム状態としてサーバに保存済みの値をそのまま参照する——新しい判定を増やさない。
- 一言の入力はサーバへ保存し、Debriefで読み上げ・一覧表示できるようにする（Stage 5のポスター大賞と
  同じ運用）。
- 教材 [`../materials/final_press_questions.md`](../materials/final_press_questions.md)は振り返り版
  では使わない。共有フォルダにも追加しない。
- **モック（`docs/ui/mock/index.html`）は反映済み**（2026-08-22）。振り返りボード（`renderFinal()`）、
  エンディング（`fStartRelay()`→`fStartHandover()`/`fShowHandover()`）まで実装してある。レースの終端
  演出 `goalSequence()` は Stage 5 側（`stage5GoalSequence()`）の専用関数になり、Final は呼ばない。
- 感謝状は `fEnded`（`go()` のリセット対象外のモジュール変数）で復元する。`fLine` と同じく、
  シーンを離れても消さない——ファシリテーターが各チームのPCから読み上げるため。
- クレッシェンドの数値（14で継続）は [00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §4 と同期させる。
