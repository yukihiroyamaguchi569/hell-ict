## 狙い

**この2分間だけ、地獄のICTは地獄に見えない。**

シナリオ側の要求は「明るいUI・穏やかなBGM・歓迎ムード」、そして2分後の落差。
UIの仕事は、**参加者に「アプリを間違えたかな」と一瞬思わせるほど平和な画面を出すこと**。
宣伝トレイラーで黒と赤の地獄を見てきた参加者が、アイボリーの画面に着地する——この裏切りが落差を最大化する。

> 設計上の絶対条件: **Prologue（①〜③）では一切の警告色を使わない。** `--accent` すら
> 控えめな青緑にする（`peace` トークン）。赤を1ドットでも出したら、後に来る転調が
> 「予告どおり」になってしまう。
>
> **Stage 1 の終わりまで禁じるのは赤だけ。** 器は `peace` のまま、平和な色で1分刻みの
> メール処理をやらせる——その居心地の悪さが Stage 1 の持ち味になる。ただし橙（`--warn`）は
> 例外として1箇所だけ使う：事務長ブリーフィングの「他の職員は5分ですが」の一句
> （[02_Stage1.md](02_Stage1.md) §0）。`peace` の `--warn` は琥珀 `#b8862b` で赤ではなく、
> **赤を温存したまま一句だけ浮かせる**ための色。ここで赤を使うと、Stage 1 の後の
> 赤帯が効かなくなる。

## 画面の流れ

```text
[① 入室] → [② ウェルカム] → [③ 受信トレイ 3通] → 【④ 事務長ブリーフィング】 → Stage 1 → 【急変】 → Stage 2
 data-mode="peace" ──────────────────────────────────────────────────────────→ ▓ 900ms ▓ → alert →
```

**急変は Prologue では起きない。** ④ のあと Stage 1（メール処理）を丸ごと挟み、
それを終えてから初めて世界が変わる。Prologue から Stage 1 の終わりまで、器はずっと `peace`。

> 📌 **なぜ急変を後ろへ回したか。** アウトブレイクの最中にメール処理を命じられると、
> 理不尽が濃すぎて「そういうゲームだ」と受け流されてしまう。**まだ何も起きていない**のに
> ICTの本業を後回しにさせられる——この平時の壊れ方を先に見せてから、片付いた一拍あとに
> 急変を落とす。段階を追って追い詰めるための順序（[02_Stage1.md](02_Stage1.md) §0）。

**④ は ③ を読み終えると自動で表示される全画面オーバーレイ。** 詳細UIは [02_Stage1.md](02_Stage1.md) §0。

Prologue の間、**リーダーボード帯は存在しない**（下部の48pxはコンテンツに使う）。
せり上がるのは事務長ブリーフィングの `[了解しました]` を押した瞬間——**押した本人は
「了解」しただけのつもりだが、その時点で競争に入っている。**

## ① 入室

```
                    ┌──────────────────────────┐
                    │                          │
                    │   🏥 聖クロノス総合病院      │
                    │      感染制御チーム         │
                    │                          │
                    │   チームコードを入力       │
                    │   ┌──┬──┬──┬──┬──┬──┐  │
                    │   │  │  │  │  │  │  │  │
                    │   └──┴──┴──┴──┴──┴──┘  │
                    │                          │
                    │        [ 入室する ]       │
                    └──────────────────────────┘
```

- 企画書§7「なしログイン。6桁チームコード入室」。**研修現場でログインさせない。**
- 6桁を1マスずつの入力にする。研修会場でファシリテーターが「Bチームは 4 8 2 1 0 3 です」と
  読み上げるのを、聞きながら打てる形。
- コード入力欄の数字は 32px 等幅。**部屋の後ろから読み上げを受ける**ため。
- 同じコードで再入室すると、そのチームの状態が復元される（企画書§9・予備機からの復帰）。
  復帰時は「おかえりなさい。Stage 2 の途中から再開します」とだけ出す。**謝らない。**

```
│      届いているメールに目を通してください。                      │

│                                                              │
│      ＼ 今日のあなたのチーム ／                                │
│      ┌──────────┐┌──────────┐┌──────────┐┌──────────┐      │
│      │ 🧠 司令塔  ││ ⌨️ 手     ││ 🔍 監査役 ││ 🎲 遊撃   │      │
│      │[      ]  ││[      ]  ││[      ]  ││[      ]  │      │
│      └──────────┘└──────────┘└──────────┘└──────────┘      │
│      役割はステージごとに交代します。PCはこの1台だけ、           │
│      触れるのは「手」の1人です。                               │
│                                                              │
│                    [ 受信トレイへ ]                           │
└──────────────────────────────────────────────────────────────┘
```

### 設計の要点

- **ヘッダーはこの時点から出ている。** 院内状況インジケータ（`原因不明の発熱 3`）を
  **最初の画面から**画面最上部に置く。ここで置かないと Debrief の回収が成立しない（[00](00_共通シェルと通奏低音.md) §4）。
- 役割カードは**名前を打ち込ませる**。打つ行為が「自分はこの役だ」という宣言になる。
  4人目の 🎲 遊撃 カードは、3人チームなら空欄のままで先へ進める。
- **操作説明を一切しない。** AIチャットの使い方も、提出の仕方も説明しない
  （シナリオ側「AI初体験はStage 1に取っておく」）。
- **AIチャットは画面に存在しない。** Prologue の間、右ペインは無い。空のチャット欄が視界にあるだけで
  意識がそちらへ逃げ、3通目の種が読まれずに終わる。登場は Stage 1（[00](00_共通シェルと通奏低音.md) §7）。
- ボタンは1つだけ。迷わせない。

### 平和の演出

- 背景に**ごく淡い動き**を置く（窓の外の光がゆっくり変わる程度）。静止画にしない。
  静止していると「読み込み中の画面」に見え、平和ではなく手持ち無沙汰になる。
- BGM: 穏やかな環境音（空調・遠くの足音）。**音楽ではなく環境音**にする。
  音楽だと2分後に止めたとき「曲が終わった」に聞こえる。環境音なら「**病院が静まり返った**」に聞こえる。

## ③ 受信トレイ（3通）

```
┌──────────────────────────────────────────────────────────────┐
│ 🏥 聖クロノス総合病院 ICT │ 在院 398/400・空床 2・原因不明の発熱 3 │
├────────────────┬─────────────────────────────────────────────┤
│ 受信トレイ  3    │  件名: 昨夜の申し送り                          │
│ ─────────────  │  差出人: 夜勤師長                             │
│ ● 人事課        │  ───────────────────────────────────────  │
│   【ようこそ】…  │  お疲れさまです。昨夜は平穏でした。              │
│                │  インフルの疑い患者もゼロです。                 │
│ ● 前任ICN      │                                             │
│   引き継ぎメモ…  │  なお、ここ数日、原因不明の発熱の患者さんが      │
│                │  数名出ていますが、まあ夏風邪でしょう。          │
│ ● 夜勤師長      │  特に対応は不要かと。                          │
│   昨夜の申し送り │                                             │
│                │  それでは、よい一日を。                        │
│                │                                             │
└────────────────┴─────────────────────────────────────────────┘
                   ↑ 右ペインは無い。中央が右端まで伸びている
```

**この画面に道具は1つも無い。** あるのは読むものだけ。
2分間の唯一の仕事は種を仕込むことなので、注意を奪うものを置かない。

### 3通は「2003年の書式」で描く

[00](00_共通シェルと通奏低音.md) §8 のルール。メール本文は等幅寄り・角丸なし・罫線区切り。
**アプリは今日のものだが、この病院から届くものは全部古い。**

### 種を読み流させるための書式ルール

シナリオ側の絶対条件は「**ここで警戒させたら設計失敗**」。UI側で守ること:

| やること | 理由 |
|---|---|
| メール3の該当文を**太字にしない・色を変えない・囲まない** | 強調した瞬間に伏線だと分かる |
| 該当文を**段落の途中に置く**（末尾の最終行にしない） | 最後の一文は記憶に残る。前後を平凡な文で挟む |
| 3通の**表示順を固定**し、種のメールを最後に置く | 最後は流し読みされる。ここでは流し読みが正しい |
| 未読マークは3通とも同じ | 「重要」フラグを付けない |

> 📌 UIが親切心を出した瞬間に、この2分間の設計が壊れる。**教えない・目立たせない・急かさない。**

### 開封状態

- 開封したメールは既読になり、`受信トレイ 3` のカウンタが減る。
- **3通すべて開封した時点で事務長ブリーフィングが発火**（＝時間より先に来ることがある）。次項。

## ④ 事務長ブリーフィング

画面の詳細・台詞・段階表示は [02_Stage1.md](02_Stage1.md) §0 が正典。ここでは発火条件だけ持つ。

### 発火条件

**「2分経過」または「3通すべて開封」のいずれか早い方。**

シナリオ側の意図は「開封が速いチームは開封トリガー、遅いチームは時間トリガーで、
**全チームほぼ同時に Stage 1 へ入らせ、レースのスタートを揃える**」。

| 実装上の注意 | |
|---|---|
| 2分の計測開始点 | **ウェルカム画面を抜けて受信トレイを開いた瞬間**。入室時刻ではない（入室はファシリの読み上げ待ちで揺れる） |
| 3通開封の判定 | 開いただけでよい。滞在時間は問わない |
| 下限 | 開封が極端に速くても、**受信トレイ表示から最低30秒**は次へ進めない。3通を1秒で連打したチームが平和を体験できないのは設計の損失 |

> ⚠️ ここで転調しない。器は `peace` のまま事務長が現れ、`peace` のまま Stage 1 が始まる。

## 急変（Stage 1 を終えたあと）

> 📌 **この節の演出が起こるのは Prologue ではない。** Stage 1（メール処理）を終え、
> 片付いたと思った一拍あとに発火する。それでも記述を Prologue 側に置いてあるのは、
> この転調が **①〜③ で作った平和と対にしてはじめて設計として読める**ため
> （切り離すと「なぜここまで平和を作り込んだのか」が失われる）。
> Stage 2 の UI設計ファイルを起こす際に、そちらへ移すこと。

### 転調のシーケンス（900ms）

```
  0ms   BGM（環境音）が プツッ と切れる。無音。
        ├─ 音を先に切る。視覚より聴覚が先に「何かあった」を伝える
  120ms 画面全体のテーマトークンが peace → alert へ補間開始（780ms かけて）
        ├─ アイボリー → チャコール、青緑 → 深紅
  300ms 全画面に赤帯がスライドイン
        │  「5A病棟より緊急連絡。MRSA疑い、拡大の可能性。」
        └─ MRSA の名がここで初めて出る。Stage 2 の師長メールに直結する
  900ms 転調完了。以降 alert 固定
```

**崩れるのは器の色だけ。** リーダーボードも経過時間も、Stage 1 の冒頭から既に動いている。
この転調で新しく始まるものは何もなく、**今あるものの色が変わる**——それだけで足りる。
すでに走っているレースの景色が、途中で暗転する形になる。

### 演出の原則

- **段階的に重ねる。同時に全部起こさない。** 一斉に変えると「画面が切り替わった」に見える。
  順に崩れていくから「**変わってしまった**」になる。
- 赤帯は**消える**（3秒後）。出しっぱなしにすると、Stage 2 の作業中ずっと警告が鳴っている画面になり、
  以降の本当の警報（Stage 3・4）が効かなくなる。**赤は使い減りする資源として扱う。**
- 転調中も**入力を止めない**。ここでロックすると「演出を見せられている」になる。
  何もできないまま世界が変わる方が怖い。

### 転調後の状態

- `data-mode="alert"` に固定。**以降、`peace` には戻らない。**
- **時計は止めない・巻き戻さない。** 経過時間は Stage 1 の `[了解しました]` から連続して
  走り続ける（`startClock()`）。急変は**レースの開始ではなく、走行中の景色の変化**。
- **Stage 2 のメールはここで落とさない。** 師長の「至急！！MRSAのやつまとめて」が届くのは
  Stage 2 の画面に入ってから。転調中に着弾させても画面遷移で消えるだけで、実装としては
  空振りになる（`transition()` は画面を切り替えずに色だけ変える）。
- **AIチャットは既にある。** Stage 1 の1回目が失敗した時点で苅部さんが渡しているため、
  Stage 2 は道具を持った状態で始まる。ここで改めて出すものは何もない
  （[02_Stage1.md](02_Stage1.md) §0・[苅部さん.md](../character/苅部さん.md) §5）。
- 院内状況インジケータは `発熱 3` のまま。**転調でも変わらない**——
  これが重要で、世界が赤くなっても**この数字だけは静かに居座っている**。

→ **転調開始から 4.2 秒**で Stage 2 へ。**参加者の操作は不要。**

赤帯は 3.3 秒でフェードを始め、3.7 秒で消えるので、**画面から赤が消えて 0.5 秒後**に
場面が変わる勘定になる（`transition()` 内の `later(…, 4200)`）。この0.5秒は、
赤が引いた画面を一瞬だけ見せるための間。

## 実装メモ

- 2分は**体感で調整**（シナリオ側・企画書 P0/P2 で実測）。転調シーケンスの各タイミングは
  ミリ秒単位で定数化し、テストプレイ後に**数値だけ差し替えられる**ようにしておく。
- 種のメール3はサーバに保存し、Debriefで「実は初日から書いてありました」と再掲する（シナリオ側実装メモ）。
  再掲画面では**逆に太字で強調してよい**。種明かしの場だから。
- 転調の発火はサーバ（チームDO）が持つ。クライアントのタイマーに任せると、
  リロードしたチームだけ平和が延長される。
- **転調済みフラグは永続化する。** 予備機から再入室したチームが `peace` の画面を見たら、
  そのチームだけ地獄が一度リセットされてしまう（[00](00_共通シェルと通奏低音.md) 実装メモ）。
