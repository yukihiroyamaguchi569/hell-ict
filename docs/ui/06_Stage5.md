> ⚠️ 参加者に見えるステージ名は **`Stage 5　掲示`**。「ポスター工房」は設計ドキュメント上の呼称。
> `stage4UnlockSequence()` が Stage 4 解錠時に既にこの副題（「掲示 — 面会制限のお知らせ」）を

## 狙い

**Stage 3・4 が使ってきた罠の器（`alarm` / `lock` / `blackout`）を、Stage 5 は1つも使わない。**
これは省略ではなく設計そのもの——罠疲れの後のご褒美ステージであることを、演出の**不在**で示す
（[../scenario/06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §狙い）。

UIの仕事は2つだけ：①同じAIチャットから初めて画像を返す形を作ること、②画像は判定せずプロンプトだけを
見る、という非対称を画面上で不自然に見せないこと。

## 1. 左ペイン：着弾メールと共有フォルダ

### 着弾メール（2通）

文面は [06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §状況が正典。2003年書式
（`--font-legacy`）は継続。

- 初期表示は**1通目（事務長）を開いた状態**にする（Stage 3・4 が最初の着弾メールを開いた状態で
  始まるのと同じ流儀）。
- **近藤さんのメール添付**（`去年の面会制限のお知らせ.txt`）は Stage 3・4 の添付ビューアと同じ仕組みで
  開く。`[コピー]` ボタンは**置かない**——Stage 3・4 の `[コピー]` は罠や課題の材料をAIへ渡す動線の
  生命線だったが、Stage 5 では去年の掲示物をそのままAIに貼っても罠は無く、判定にも影響しない。
  参考にするかどうかは自由に読ませればよく、ボタンで動線を作る必要が無い。
  「病院から届くもの」の書式ルール（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8）に従い、
  白い紙として固定する。

### 共有フォルダ：Stage 3 から常設のまま、中身を増やさない

[05_Stage4.md](05_Stage4.md) §1「Stage 3 以降 常設のまま残る」を継続する。Stage 5 でも増やさない——
去年の掲示物はメール添付だけに置き、共有フォルダには足さない（[06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md)
§配布教材と同じ理由。「これは罠ではない」ので手の届く場所を制限する動機も無いが、正典の置き場所を
むやみに増やさない、という Stage 3・4 の流儀をそのまま踏襲する）。

## 2. 中央ペイン：課題と画像候補の提出フォーム

### 課題カード

```
 面会制限のお知らせを作り、掲示用に提出せよ。
```

Stage 2〜4 と同じく1行に留める。締切バーは**置かない**（下記「やらないこと」）。必須要素
（マスク着用／面会時間／多言語 or ピクトグラム的表現）は画面に出さない——Stage 2〜4 と同じ理由。

### 提出候補の枠

```
┌──────────────────────────────────────────────┐
│                                              │
│              （提出候補：未選択）              │
│                                              │
└──────────────────────────────────────────────┘
                                  [ 提出する ]
```

右ペインで生成した画像を `[これを提出候補にする]` で選ぶと、この枠にサムネイルが表示される。

| 項目 | 決定 | 理由 |
|---|---|---|
| 表示内容 | 選択中の画像サムネイル＋それを生成したプロンプト文（読み取り専用・小さめの文字） | 「何を書いたら何が出たか」を手元で見返せるようにする。Stage 3・4 の「提出物1本」と違い、Stage 5 は生成物とプロンプトの**組**が提出物 |
| 選び直し | 何度でも可能。AIチャット側の他の候補をクリックすれば差し替わる | 生成回数の上限（`S5_GEN_LIMIT`）と提出の選び直しは別物——選び直しに追加コストは発生しない |
| `[提出する]` の活性化 | 候補が1枚も選ばれていない間は非活性 | 「なんとなく空のまま提出」を防ぐ |
| 差し戻し後 | 選択中の候補・プロンプト表示ともに保持する | Stage 3・4 §NG時「中身は保持する」と同じ理由 |

## 3. 右ペイン：AIチャットが初めて画像を返す

企画書 §5・§7「GPT-4oと同じチャットから gpt-image-1 を呼ぶ」。右ペインの見た目・位置・スレッドタブは
Stage 2 以降と完全に同じ（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §7）。**新しいチャット欄を
作らない。**

### 生成の流れ

```
送信ボタン押下
   │
   ▼
上限（S5_GEN_LIMIT）に達しているか
   │
   ├─ 達していない ─▶ 自分の吹き出し → 生成中プレースホルダ（S5_GEN_MS）
   │                    → 画像の吹き出し＋[これを提出候補にする]
   │                    → 残り生成回数の表示を更新
   │
   └─ 達している ───▶ 自分の吹き出し → 苅部さんの2段目が光る（生成はしない）
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 送信前ゲート（PII検知） | **働かせない** | Stage 4 の検知対象は患者の固有情報。掲示物のプロンプトに患者情報を書く動線が無いので、ここで検査しても何も起きない |
| 生成中の見た目 | 吹き出しの中にプログレス（`S5_GEN_MS`、仮値2.5秒） | 「呼んでいる」ことを実感させる。即座に出すと gpt-image-1 を呼んでいる感じが消える |
| 出し分けの根拠 | プロンプト文中のタグ一致（`S5_POSTERS`。詳細は `docs/ui/mock/README.md` Stage 5 節） | モックはAPIを呼ばない。事前生成した候補画像をキーワードで出し分ける |
| 残り生成回数の表示 | AIチャット下部に小さく常設（`生成: n/S5_GEN_LIMIT 回`） | 上限が近いことを参加者自身が把握できるようにする。隠すと「なぜ急に生成されなくなったか」が分からず混乱する |

- AIチャットのペインは Stage 3・4 と同じく alert/crisis モードでも明るいまま
  （[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §7「alertモードでも、ここだけが明るい」）。
  Stage 5 に罰は無いので**灰色に沈める演出（`locked`）は一度も使わない**。

## やらないこと

| やらない | 理由 |
|---|---|
| カウントダウン・締切バー | 実カウントダウンは Stage 4 だけの特権（焦りが罠の発火率に直結するステージだから）。焦らせる理由の無いここで使うと Stage 4 の演出の意味が薄まる |
| `alarm`/`lock`/`blackout` | Stage 5 に罠も罰も無い。使った瞬間「これも罠か」という警戒を誘発してしまう |
| 画像の自動品質判定 | ルールベースで画像の良し悪しを見る手段が無い。判定はプロンプト文字列だけを見る（企画書 §5・§7） |
| 添付ビューアに `[コピー]` を置くこと | 去年の掲示物をそのままAIに貼っても罠は発生しない。ボタンで動線を作る必要が無い |
| 苅部さんにデザインの良し悪しを言わせること | 「弱い領域」の境界（[苅部さん.md](../character/苅部さん.md) §2）そのもの。ここを破るとキャラの一貫性が壊れる |
| 必須要素を画面に列挙すること | Stage 2〜4 と同じ理由。2通のメールを読んで自分で言語化する動機を残す |
| 生成回数の上限で提出を止めること | 敗北条件は作らない（企画書 §6）。上限後も生成済み候補はいつでも提出できる |

## 実装メモ

- 判定は**ルールベースのみ**（企画書 §7）。プロンプト文字列に対する正規表現/キーワードマッチ。
  LLMを呼ばない設計は Stage 2〜4 と同じ。
- 教材の正典は [`../materials/stage5_notice_old.md`](../materials/stage5_notice_old.md)（去年の掲示物。
  Markdown が正典、添付テキストは派生物）。
- **画像候補の出し分けタグと、判定の必須要素キーワードの対応表は `docs/ui/mock/README.md` Stage 5 節に
  1箇所だけ持つ。** Stage 3 が踏んだ負債（教材と判定が食い違って静かに壊れる）を繰り返さない。
- 定数は `S5_GEN_LIMIT`（生成回数上限・仮値5回）、`S5_GEN_MS`（生成待ちの演出時間・仮値2.5秒）、
  `S5_KARUBE_DELAY`（通常値に戻す）。すべて仮値、P0実測で確定。
- クレッシェンドの数値（14で継続）は `docs/ui/00_共通シェルと通奏低音.md` §4 と同期させる。
- **画像アセットが未制作でもモックが壊れないようにする。** `<img>` に `onerror` フォールバックを入れ、
  ファイルが読めない間は候補の枠と代替テキストだけを表示する。画像が揃い次第、コードを変更せずに
  差し替わる。
