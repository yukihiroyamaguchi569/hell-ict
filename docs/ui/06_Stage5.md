## 狙い

**Stage 3・4 が使ってきた罠の器（`alarm` / `lock` / `blackout`）を、Stage 5 は1つも使わない。**
これは省略ではなく設計そのもの——罠疲れの後のご褒美ステージであることを、演出の**不在**で示す
（[../scenario/06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §狙い）。

> 📌 **設計変更（2026-08-23テストプレイ向け）**: 当初「提出に一切の関門を作らない」だったが、
> 実装では**判定を導入した**（下記「4. 解錠」）。`alarm`/`lock`/`blackout` を使わないという
> 罠・罰の不在は変わらないが、Stage 2〜4 と同じ「失敗に見せない橙表示」の差し戻しは Stage 5 にも
> ある。

UIの仕事は2つだけ：①同じAIチャットから初めて画像を返す形を作ること、②**判定を持ちながらも詰まらせ
ないこと**——候補の種類とプロンプトの累積だけを見る軽い判定にとどめ、罠・罰・回数制限を持ち込まない。

## 2. 中央ペイン：課題と画像候補の提出フォーム

### 課題カード

```
 面会制限のお知らせを作り、掲示用に提出せよ。
```

Stage 2〜4 と同じく1行に留める。締切バーは**置かない**（下記「やらないこと」）。必須要素
（マスク着用／面会時間／多言語 or ピクトグラム的表現）は画面に出さない——Stage 2〜4 と同じ理由。
**ただし判定はこの3点を実際に見る**（下記「4. 解錠」）。画面に出さないのは要件を自分で言語化
させるためであって、判定そのものが無いわけではない。

> ⚠️ **左ペインの依頼メールを丸写しでAIへ貼った場合は、画像を生成せずに差し戻す**（2026-08-22追加）。
> メール本文には3点が揃って書いてあるので、貼るだけで判定を通れてしまい、この節の「自分で言語化
> させる」が丸ごと空振りになる。AIが「お知らせのメールそのままのようです。ポスターに何を、
> どのように描くかの指示にしていただけますか」と返し、生成回数も消費しない。閾値と、短い引用を
> 咎めない理由は [`../scenario/06_Stage5_ポスター工房.md`](../scenario/06_Stage5_ポスター工房.md)
> §判定 の ⚠️ を正典とする。

### 提出候補の枠

```
┌──────────────────────────────────────────────┐
│                                              │
│              （提出候補：未選択）              │
│                                              │
└──────────────────────────────────────────────┘
                                  [ 提出する ]
```

右ペインで生成した画像を `[これを提出候補にする]` で選ぶと、この枠にサムネイルが表示される。

| 項目 | 決定 | 理由 |
|---|---|---|
| 表示内容 | 選択中の画像サムネイル＋それを生成したプロンプト文（読み取り専用・小さめの文字） | 「何を書いたら何が出たか」を手元で見返せるようにする。Stage 3・4 の「提出物1本」と違い、Stage 5 は生成物とプロンプトの**組**が提出物 |
| 選び直し | 何度でも可能。AIチャット側の他の候補をクリックすれば差し替わる | 生成回数の上限（`S5_GEN_LIMIT`）と提出の選び直しは別物——選び直しに追加コストは発生しない |
| `[提出する]` の活性化 | 候補が1枚も選ばれていない間は非活性 | 「なんとなく空のまま提出」を防ぐ——これはUI上の親切であって、下記「4. 解錠」の判定そのものではない |
| 差し戻し時の枠 | `.warn`（橙）を一時的に付ける | Stage 2〜4 と同じ「失敗に見せない橙」のトーンを踏襲する |

## 3. 右ペイン：AIチャットが初めて画像を返す

企画書 §5・§7「GPT-4oと同じチャットから gpt-image-1 を呼ぶ」。右ペインの見た目・位置・スレッドタブは
Stage 1のヘルプ第1段階以降と完全に同じ（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8）。**新しいチャット欄を
作らない。**

### 生成の流れ

```
送信ボタン押下
   │
   ▼
上限（S5_GEN_LIMIT）に達しているか
   │
   ├─ 達していない ─▶ 自分の吹き出し → 生成中プレースホルダ（S5_GEN_MS）
   │                    → 画像の吹き出し＋[これを提出候補にする]
   │                    → 残り生成回数の表示を更新
   │
   └─ 達している ───▶ 自分の吹き出し → 苅部さんの2段目が光る（生成はしない）
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 送信前ゲート（PII検知） | **働かせない** | Stage 4 の検知対象は患者の固有情報。掲示物のプロンプトに患者情報を書く動線が無いので、ここで検査しても何も起きない |
| 生成中の見た目 | 吹き出しの中にプログレス（`S5_GEN_MS`、仮値2.5秒） | 「呼んでいる」ことを実感させる。即座に出すと gpt-image-1 を呼んでいる感じが消える |
| 出し分けの根拠 | プロンプト文中のタグ一致（`S5_POSTERS`。詳細は `docs/ui/mock/README.md` Stage 5 節） | モックはAPIを呼ばない。事前生成した候補画像をキーワードで出し分ける |
| タグに一致しない差分指示 | 直前候補の様式（`type`）を継承する | 実際のAIチャットは文脈を保持するので、「マスクも入れて」のようなタグ無し指示のたびに標準案へ巻き戻ると不自然——参加者が同じ様式の差し戻しループにハマる事故を防ぐ |
| 残り生成回数の表示 | AIチャット下部に小さく常設（`生成: n/S5_GEN_LIMIT 回`） | 上限が近いことを参加者自身が把握できるようにする。隠すと「なぜ急に生成されなくなったか」が分からず混乱する |
| 送信した指示の記録 | `s5PromptLog` にこのステージで送った全指示を累積し、判定（下記「4. 解錠」）はこの累積に対して行う | 選択候補を生んだ1本のプロンプト単体に全要件を要求すると、要素を足すたび前の要素が消えて永遠ループする（2026-08-21のテストプレイで実際に発生）。累積で見ることでこれを防ぐ |

- AIチャットのペインは Stage 3・4 と同じく alert/crisis モードでも明るいまま
  （[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8「alertモードでも、ここだけが明るい」）。
  Stage 5 に罰は無いので**灰色に沈める演出（`locked`）は一度も使わない**。

## 4. 解錠：差し戻しのみ・罠なし・罰なし・回数無制限

シナリオ側 [06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §判定が正典。
`checkStage5()` が2段で見て、最初に引っかかった1件だけを近藤さんの台詞で返す。

```
[提出する] 押下
   │
   ▼
候補の種類が textheavy／default か
   │
   ├─ はい ─▶ 差し戻し（「これ……去年のと同じになってません……?」等）
   │
   └─ いいえ（pictogram／multilingual）
        │
        ▼
      このステージで送った指示の累積（s5PromptLog）に
      マスク・面会時間の言及があるか
        │
        ├─ 無い ─▶ 差し戻し（「マスク着用のお願いが入っていないようです」等）
        │
        └─ 両方ある ─▶ 解錠
```

| 結果 | 条件 | 演出 |
|---|---|---|
| 差し戻し | 候補の種類が `textheavy`／`default`、または累積プロンプトにマスク・面会時間いずれかの言及が無い | `.warn`（橙）＋近藤さんの台詞。候補・生成済み画像は保持し、選び直し・再提出は無制限 |
| 解錠 | pictogram/multilingual候補が選ばれ、かつマスク・面会時間の両方に触れた状態で `[提出する]` を押す | `unlock`（副題は Stage 4 解錠時に予約済みの「掲示 — 面会制限のお知らせ」をそのまま使う） |

- **差し戻しは Stage 2〜4 と同じ「失敗に見せない橙」。** `alarm`/`lock` は一度も使わない——
  Stage 5 に罠・罰は無いという設計は変わらない。差し戻し回数の上限も設けない。
- 解錠時、師長・近藤さんいずれからも祝いの一言は出さない（[06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md)
  §演出・時間）。
- **2026-08-23テストプレイでは、この `unlock` の代わりに Final の `goalSequence()`（`#ov-goal`）を
  副題だけ差し替えて流用し、テストプレイ完走を示す**（Final は当日実施しないため。
  [06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §演出・時間の📌参照）。

## やらないこと

| やらない | 理由 |
|---|---|
| カウントダウン・締切バー | 実カウントダウンは Stage 4 だけの特権（焦りが罠の発火率に直結するステージだから）。焦らせる理由の無いここで使うと Stage 4 の演出の意味が薄まる |
| `alarm`/`lock`/`blackout` | Stage 5 に罠も罰も無い。使った瞬間「これも罠か」という警戒を誘発してしまう |
| 画像そのものの自動判定 | 見た目の良し悪しは判定しない。品質評価は Debrief の投票（「ポスター大賞」）に一任する |
| 差し戻し回数の上限・罰 | 判定はあるが、回数無制限・無罰。詰まらせない設計は維持する（上記「4. 解錠」） |
| 添付ビューアに `[コピー]` を置くこと | 去年の掲示物をそのままAIに貼っても罠は発生しない。ボタンで動線を作る必要が無い |
| 苅部さんにデザインの良し悪しを言わせること | 「弱い領域」の境界（[苅部さん.md](../character/苅部さん.md) §2）そのもの。ここを破るとキャラの一貫性が壊れる |
| 必須要素を画面に列挙すること | Stage 2〜4 と同じ理由。2通のメールを読んで自分で言語化する動機を残す |
| 生成回数の上限で提出を止めること | 敗北条件は作らない（企画書 §6）。上限後も生成済み候補はいつでも提出できる |

## 実装メモ

- **判定は実装済み**（`docs/ui/mock/index.html` `checkStage5()`）。①候補の種類（`textheavy`/`default`
  は無条件で差し戻し）②累積プロンプト（`s5PromptLog`）に対する `S5_REQUIRED`（マスク・面会時間）の
  順で見る。差し戻しのみ・罠なし・罰なし・回数無制限。
- 教材の正典は [`../materials/stage5_notice_old.md`](../materials/stage5_notice_old.md)（去年の掲示物。
  Markdown が正典、添付テキストは派生物）。
- **画像候補の出し分け（プロンプト文中のタグ一致）は提出の可否とは別のロジック。** どのタグにも
  一致しなくても標準案の画像が返るので、生成が失敗することは無い。タグ無しの差分指示は直前候補の
  様式を継承する（`s5Generate()`）。
- **マスク・面会時間の判定語（`S5_REQUIRED`）は自然な言い回しを広く拾う。** 「面会は14時から
  16時まで」のように「面会時間」という文字列そのものが無い書き方を2026-08-21のテストプレイで
  誤って差し戻したため、`面会.{0,20}(時間|制限|\d{1,2}\s*時|分以内)` 等へ語彙を広げた。
- 定数は `S5_GEN_LIMIT`（生成回数上限・仮値5回）、`S5_GEN_MS`（生成待ちの演出時間・仮値2.5秒）、
  `S5_KARUBE_DELAY`（通常値に戻す）。すべて2026-08-23テストプレイ向けの仮値、P0実測で確定。
- **クリア時は `stage5GoalSequence()` が Final の `goalSequence()`（`#ov-goal`）を副題だけ差し替えて
  呼ぶ。** Final は当日実施しないため、Stage 5 通過をテストプレイの完走演出として扱う
  （[../scenario/06_Stage5_ポスター工房.md](../scenario/06_Stage5_ポスター工房.md) §演出・時間）。
  Final自体のコード・devbarからの単体起動経路は変更しない。
- クレッシェンドの数値（14で継続）は `docs/ui/00_共通シェルと通奏低音.md` §4 と同期させる。
- **画像アセットが未制作でもモックが壊れないようにする。** `<img>` に `onerror` フォールバックを入れ、
  ファイルが読めない間は候補の枠と代替テキストだけを表示する。画像が揃い次第、コードを変更せずに
  差し替わる。
