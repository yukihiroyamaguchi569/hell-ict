## 狙い

**3ペインのシェルが、初めて課題らしい課題で埋まる画面。**
「左の添付を開き、右のAIに投げ、中央に提出する」という**本編の基本動作**を体で覚える。
Stage 3 以降はこの動作の反復と応用でしかない。

Stage 1で使えるようになったAIチャットを、ここでは**データ整形という具体的な業務に自分で接続する**。
下書きと異なり、何を整え、どの形式で返してほしいかを自分で言語化する必要がある。

そしてシナリオ側の絶対条件——**ここで詰まらせない**。
UIの仕事は、AIを使えば3分で終わることを**画面の作りだけで示唆する**こと。ただし説明はしない。

> 📌 UI設計上の絶対条件: **判定NGを「失敗」に見せない。** 罠のないステージで敗北感を与えると、
> Stage 3 で本物の罠が来たときの落差が消える。ここでの NG は**赤ではなく橙**、
> 文言は叱責ではなく**どこを直せばよいかの提示**にする。

## 1. 左ペイン：着弾メールと添付

### メール表示

```
────────────────────────────────
件名: 至急！！MRSAのやつまとめて
差出人: 5A病棟 師長
────────────────────────────────
新しいICTの方ですよね。悪いけど急ぎで。
5A病棟でMRSA疑いが出てます。とりあえず
手元の記録、そのままのExcelで送ります。

これ、感染対策の会議で使える形にキレイに
まとめてください。日付とかバラバラです
みません、私が作ったんじゃないので。

朝の申し送りまでに疫学曲線の材料も要る
そうです。よろしく！
────────────────────────────────
📎 5A病棟_MRSA_記録_最新版(2)_コピー.xlsx
```

- 2003年の書式（[00](00_共通シェルと通奏低音.md) §9）。等幅寄り、罫線、角丸なし。
- **ファイル名を省略しない。** `最新版(2)_コピー` が笑いどころなので、
  左ペインが狭くても折り返して全部見せる。省略記号で隠したら台無し。
- Prologue の3通と Stage 1 の20通は既読（`○`）として残す。**消さない。**
  Stage 3 で「そういえば初日のメールに書いてあった」と戻れる導線になる
  （時間切れで消えた分は戻らない——それがこの病院のルール）。

### 添付ファイルの扱い

タップすると**教材ビューア**が中央ペインの上に開く。

```
┌─ 5A病棟_MRSA_記録_最新版(2)_コピー.xlsx ─────────── [コピー] [DL] [✕] ┐
│ ※このファイルは5A病棟師長が個人的につけている記録です。正式なものでは… │
│ 5A病棟の状況　7月分                                                │
│                                                                  │
│ 患者ＩＤ  びょうとう  採取日      MRSA   発熱    メモ                │
│ ００１    5A病棟     7/3        陽性   あり    個室へ                │
│ id-2                7月3日     (+)   38.2℃                       │
│ no.3     （結合）    R8.7.3     ポジ   なし                        │
│ ４番                さんにち    ＋     あり    家族面会あり           │
│ …                                                                │
└──────────────────────────────────────────────────────────────────┘
```

> 📌 **氏名（なまえ）列は無い。** 実AI接続でこの添付をコピーしてAIに整形させる正規タスクを行うと、
> 旧・氏名列の値（患者`005`「渡辺 三郎」）がStage 4のPII検知パターンとそのまま一致し、Stage 2の
> 実作業がPIIゲートに誤射ブロックされる事故があったため、氏名列自体を削除した。氏名は
> `stage4_chart.md`（Stage 4のカルテ抜粋）にのみ残す（[`../materials/README.md`](../materials/README.md)
> §形式 📌 が単一の情報源）。

**設計の要点:**

| 項目 | 決定 | 理由 |
|---|---|---|
| 表示 | 見た目を整えない。**汚いまま出す**。白い紙として固定し、テーマに追従させない | 結合セル・全角・空行が見えないと課題が伝わらない。アプリの面で描くと「添付ファイル」に見えない（[00](00_共通シェルと通奏低音.md) §9） |
| 編集 | **できない。** ビューアは読むだけ | 直す場所は中央のグリッド（§2）。2箇所で直せると、どちらが提出物か分からなくなる |
| **[コピー]ボタン** | **必ず置く** | これがこのステージの生命線。次項 |
| [DL] | 実ファイル（`.xlsx`）をR2から落とせる | スプレッドシートで開きたいチーム向け。**誘導はしない**（[../scenario/03_Stage2_火の手.md](../scenario/03_Stage2_火の手.md) §手作業の場） |
| 目印 `★` | **配布版では消す**（シナリオ側の指定） | 伏線に気づかせない |

### ビューアとグリッドの役割分離

| | 何か | できること |
|---|---|---|
| **添付ビューア**（左から開く白い紙） | 師長から届いた**添付ファイル** | 読む・[コピー]・[DL] |
| **グリッド**（中央ペイン） | 自分の**作業ファイル**＝提出物 | 直す・行を消す・貼り付ける・提出する |

この2つを混ぜない。**元データはビューアに常に残っている**ので、
グリッドを手で壊しても [最初の状態に戻す] を押さずに元を読み直せる。

### 追加分の添付だけ [作業エリアに追加] を持つ

締切超過で着弾する `..._追加分.xlsx`（§2）のビューアには、[コピー] [DL] に加えて
**[作業エリアに追加]** を置く。押すとグリッドの**末尾に10行足される**。

- **これが唯一の例外。** 最初の添付にこのボタンは置かない——初期グリッドに既に入っているので不要だし、
  押せると二重取り込みが起きる。
- 押さない限りグリッドは変わらない。**自動追記は事故のもと**（手作業中のセルが動く）。

### [コピー]ボタンが Stage 1 の生命線

**「手作業25分／AI3分」の落差は、貼り付けが一瞬でできて初めて成立する。**
教材を手で選択させたら、それだけで数分溶ける。ワンタップで全文がクリップボードに入ること。

ただし**「AIに送る」ボタンは置かない**。コピーまでで止める。
そこから先——どのAIに、どんな指示と一緒に渡すか——が**このステージで学ばせたい判断**そのもの。
自動化した瞬間に研修が消える。

## 2. 中央ペイン：課題と提出

### 課題カード

課題文は**1行**にする。

> 統一されたラインリストに整形し、疫学曲線の材料を提出せよ。

正規化ルールの表（患者ID は 001形式、採取日は ISO……）は**画面に出さない**。
出したらプロンプトにそのまま写せてしまい、「要件を言語化してAIに渡す」（企画書§2の学習目標①）が死ぬ。

代わりに提出フォームの**列見出しだけ**を示す：`患者ID / 病棟 / 採取日 / MRSA結果 / 発熱 / 備考`。
**何を作ればいいかは分かるが、どう作るかは自分で言語化させる。**
グリッド化後はこの列見出しが**グリッドのヘッダそのもの**になるので、別途表示する必要はない。

### 締切表示

課題カードの中に、締切カウントダウンを**1本だけ**置く（`S2_DEADLINE = 5分`）。

```
 統一されたラインリストに整形し、疫学曲線の材料を提出せよ。
 7:00 申し送りまで  04:12  ████████████░░░░░░
```

| ルール | 内容 |
|---|---|
| 置き場所 | **課題カードの中。** ヘッダーに逃がさない。判定・グリッド・締切が同じ1画面に収まる（§2冒頭の原則） |
| 本数 | **1本だけ。** Stage 1 は10本の砂時計が同時に落ちる画面だったが、ここは課題が1つなので1本 |
| 15秒前 | 文字とバーを**橙**（`--warn`）に。[01_Prologue.md](01_Prologue.md) の色ルール |
| 赤 | **使わない。** 赤は急変に取ってある |
| 超過後 | `締切超過` と表示して**残す**。カウントは負に進めない。Stage 1 の「残骸を見せる」に揃える |
| 超過しても | **提出は一切ロックしない。** 企画書§5「Stage 2 では詰まらせない」を破らないため |

> 📌 **Stage 1 の締切とは意味が違う。** Stage 1 の超過は「機会が消える」、
> ここでの超過は「**仕事が増える**」。次項。

### 締切超過：追加データの着弾

超過した瞬間、師長からメールが1通と添付が1つ増える
（[../scenario/03_Stage2_火の手.md](../scenario/03_Stage2_火の手.md) §締切と追加データ着弾）。

```
────────────────────────────────
件名: すみません追加で
差出人: 5A病棟 師長
────────────────────────────────
あ、ごめんなさい。副師長が別につけてた分が
出てきました。これも一緒にお願いします。
────────────────────────────────
📎 5A病棟_MRSA_記録_最新版(2)_コピー_追加分.xlsx
```

| ルール | 内容 |
|---|---|
| 演出 | **暗転・警報・赤・オーバーレイを一切使わない。** 器は `alert` のまま、メール1通と未読バッジだけ |
| グリッド | **勝手に追記しない。** ビューアの [作業エリアに追加] を押して初めて末尾に10行足される |
| 押した後 | 行数表示が `33行 × 6列` に変わる。トーストは出さない——数字が変わることが通知 |
| 期待行数 | **着弾した時点で** 20 → 30 に切り替わる（判定側・§3）。取り込みは必須で、押していなければ判定④が落ちる |
| 回数 | **1回だけ。** 第2波は無い（企画書§6「罰の連続上限」） |
| 順序 | 苅部さんの未読バッジ（AI活用を促す・仮値秒）→ 5分（追加着弾）。**苅部さんが先**。両方同時に光らせない |

> 📌 **ここで演出を盛らない理由。** 派手にすると Stage 3 の罠と見分けがつかなくなる。
> このステージに罠は無い、という約束が画面の側でも守られていなければならない。
> 追加分は「理不尽だが笑える」であって「刺された」ではない。

### 提出フォーム ＝ 編集可能グリッド

**テキストエリアではなくグリッドにする。** これがこのステージ最大の設計変更で、理由は
「手作業ルートを実在させるため」——テキストエリアだと手作業が「20行を全部タイプし直す」になり、
企画書が謳う「手作業25分」に実体がなくなる（[../scenario/03_Stage2_火の手.md](../scenario/03_Stage2_火の手.md) §手作業の場）。

```
┌─ 提出 ──────────────────────────────────────────────────┐
│      患者ID   病棟    採取日     MRSA結果 発熱   備考              │
│ ✕ 1 ※このファイルは5A病棟師長が個人的につけている記録です…        │
│ ✕ 2 5A病棟の状況　7月分                                       │
│ ✕ 3 ００１     5A病棟  7/3       陽性     あり   個室へ            │
│ ✕ 4 id-2              7月3日    (+)      38.2℃                   │
│ ✕ 5 no.3              R8.7.3    ポジ     なし                     │
│ ✕ 6 ４番              さんにち   ＋       あり   家族面会あり        │
│ …                                                             │
│                                                  ＋ 行を追加   │
└────────────────────────────────────────────────────────┘
  23行 × 6列                    [ 最初の状態に戻す ]   [ 提出する ]
```

**汚い生データが最初から入った状態で始まる**（ノイズ行3 ＋ 患者行20 ＝ 23行）。
空から打ち込ませると手作業が「直す」ではなく「書き写す」になり、
日付5種・全角半角・空欄を一つずつ潰す体験にならない。

### グリッドの仕様（最小で作る）

| 項目 | 決定 | 理由 |
|---|---|---|
| 列 | **6列固定**。追加・削除・並べ替え・リネームを作らない | 提出物の形はここで保証される。列いじりは学習目標に何も足さない |
| セル | `<input type="text">`。備考列のみ幅広 | IMEはブラウザ任せ。全角の直し作業がそのまま苦行になる＝狙い通り |
| 行操作 | 行頭に行番号と `✕`（削除）。末尾に「＋ 行を追加」1つ | ノイズ行3つの削除が判定「行数が一致」に直結する。**並べ替えは作らない** |
| キーボード | Tab / Shift+Tab / Enter（下のセル）のみ | **矢印キー移動は作らない。** Tabがあれば足りる |
| 行数表示 | グリッド下に `23行 × 6列` を常時 | 現行 `#recog` の役割をそのまま継承。**判定を待たずに誰でも数えられる** |
| リセット | [最初の状態に戻す]。確認1回 | 手で壊してからAIに逃げるチームの逃げ道 |
| Undo | ブラウザ標準の input undo のみ | グリッド全体のundoは作らない |

### 貼り付け＝AIルートの合流点（ここが要）

グリッドにフォーカスがある状態の `paste` を拾い、**複数行なら全行置換**する。
確認バーを1つ挟む:

```
  30行 × 6列 として取り込みます      [ 取り込む ]  [ やめる ]
```

パーサは **TSV → CSV → Markdown表 → コードフェンス剥がし** の順に試す。
**GPT-4oの出力形は安定しないので、ここだけは堅く作る。** ` ```csv ` で囲んで返すことも、
`| 患者ID | 病棟 |` の表で返すこともある。どれを貼っても通ること。
1行だけの貼り付けは通常のセル貼り付けとして素通しする。

> 📌 **手作業ルートとAIルートが同じ場所に合流する。** 提出物の形も判定経路も1本のまま保たれ、
> かつ「手で半分直した表に、AIの出力を上書きする」という現実的な動きも自然に取れる。

### 置かないもの

- **「表をコピー」ボタン**。AIへの入口は添付ビューアの [コピー] だけに保つ。
  グリッド側にも付けるとグリッド→AI→グリッドの往復が生まれ、導線が濁る（§1 の「AIに送るボタンは置かない」と同じ思想）。
- **列の設定UI・行の並べ替え・セルの書式**。表計算ソフトを作りにいかない。

### ボタンの位置

[提出する] は**中央ペインの中**に置く。ヘッダーやフッターに逃がさない。
誰かが「待って」と言える距離に、全員が同じ視線で見られる位置に置く。

### 提出したらフォームを1行に畳む

提出後、グリッドと操作ボタンを **`提出しました　20行 × 6列`** の1行に折り畳み、
空いた場所に判定を出す。**グリッドは畳む対象として最も重要**——20行以上あるので、
畳まないと判定が確実に画面の外へ出る。

課題文・提出フォーム・判定を縦に並べたままだと、**判定結果が画面の外に出る**。
1台を3〜4人で囲んでいる状況で「結果を見るには手がスクロールする」は成立しない
——全員が同時に同じものを見られなくなる。**判定は必ず1画面に収める。**

差し戻しのときだけ [提出に戻る] を出し、グリッドを元に戻す。
**中身は保持する。** 直前の編集が消えたら再提出が罰になってしまい、
「再提出は回数無制限・ペナルティなし」（§3）が嘘になる。

## 3. 判定演出

シナリオ側の判定は4項目（構造のみ・品質は問わない）。**逐次表示する。**

```
提出を確認しています…

  ✓ 必須列がすべて埋まっている       （200ms）
  ✓ 採取日が YYYY-MM-DD に統一      （+600ms）
  ✓ MRSA結果が 陽性/陰性 の2値      （+600ms）
  ✓ 行数が20行                     （+600ms）

  ─────────────────────────────
  Stage 2 を解錠しました
```

> 📌 **4項目目の行数は動的**。追加分が着弾していれば `行数が30行`。
> 文字列を定数で持たず、期待行数から組み立てる（`S2_ROWS` / `S2_ROWS_ADD`）。
> 着弾後に未取り込みのまま提出すると、この項目のNG文言が [作業エリアに追加] を案内する。
>
> 1項目目は「列が存在するか」から**「値が入っているか」**に意味が変わっている。
> 列はグリッドで固定されているので存在は常に真——見ているのは空セルの有無
> （備考列は空でよい）。AIが列を落として返したケースは、貼り付け時点で埋まらないセルとして現れる。

### なぜ一気に出さないか

**1項目ずつ点いていく2秒間が、チーム全員が息を止める時間になる。**
一瞬で結果が出ると、レースの緊張が1フレームで消費されてしまう。
逆に長すぎると（4秒超）「重いアプリ」になる。**合計2秒**を基準とする。

### NG時

```
  ✓ 必須列がすべて埋まっている
  ✓ 採取日が YYYY-MM-DD に統一
  ✗ MRSA結果が 陽性/陰性 の2値
      → 2件残っています（下で光っている2つ）
  ─ 行数の確認は中断しました
```

**[提出に戻る] でグリッドが開いたとき、該当セルが橙で光っている。**
これがグリッド化で得られた一番大きなもの——テキストエリア時代は「3行目に『ポジ』が残っています」と
**行番号で説明するしかなかった**が、グリッドなら**そのセル自体を指させる**。
参加者は光っている所を直せばよく、探す時間がゼロになる。

| ルール | 内容 |
|---|---|
| 色 | `--warn`（橙）を使う。**`--accent`（深紅）を使わない**。セルのハイライトも同じ橙 |
| 指し方 | **セルを光らせる。** 文言は件数だけでよい。行番号を並べ立てない |
| ハイライトの解除 | そのセルを編集した瞬間に消える。直したことが即座に画面に返る |
| 打ち切り | 最初のNGで以降の判定を中断する。全部ダメ出しすると心が折れる。**光らせるのも中断した項目の分は光らせない** |
| 再提出 | 回数無制限。ペナルティなし。**罠のないステージだから**。グリッドの中身は保持する |
| 記録 | NGの回数と内容はサーバに残す。**どのセルで落ちたかまで**残す（P0の実測・難易度調整の材料） |

> 📌 **セルを光らせても「失敗」に見せない。** 橙のままにし、感嘆符もアイコンも音も付けない。
> 光っているのは「ここを直せ」であって「お前は間違えた」ではない（§0 の絶対条件）。

### 解錠演出

- `unlock` オーバーレイ（[00](00_共通シェルと通奏低音.md) §10）。`--ok` の帯が横に走る。
- 続けて師長から**1通だけ**メールが届く（末尾一文と添付1点が追加。下記「流行曲線の開示」参照）:

  > **「え、もう？ …助かる。あなた達、話が早いわね。実は感染対策会議に出す曲線、ずっと自分でも
  > 作ろうとしてたんだけど……このデータじゃ無理だったの。」**
  > 📎 添付: `流行曲線（5A病棟）`

  成功の報酬は承認（シナリオ側）。**スコアも星も出さない。** レースで返ってくるのは順位だけ。
- リーダーボードの自チームマーカー `◆` が S2 へ滑る。
- 院内状況インジケータが `原因不明の発熱 3` → `5` に**静かに変わる**（[00](00_共通シェルと通奏低音.md) §4）。

## 4. 右ペイン：AIチャット（業務で使う）

Stage 1で使えるようになったAIチャットを、ここではExcel整形という具体的な業務に使う。
AIは既に表示されており、苅部さんの役目は解禁ではなく「手で直す仕事ではない」と気づかせること。

### 登場のタイミング：苅部さんが早めに一声かける

```text
Stage 2 開始 ──▶ （仮値秒後）苅部さんの未読バッジが光る ──▶ [開く]
                                                          │
              〔苅部〕また師長のExcelですか。…そっちにAIあるんでしょ？
                                    │（900ms）
              〔苅部〕そういうの、手で直すもんじゃないですよ。
                                    │（2000ms）
              〔苅部〕……ほら、出しときました。
                                    ▼
                    右から白いペインが 420ms で滑り込む
                    中央ペインが押されて 1020 → 640 に狭まる
```

**皮肉で存在を思い出させた直後に道具が来る。** ヒントを「与える」のではなく
「なんでそれ使わないんですか」と言わせる形にする（詳細は §5）。参加者が汚いExcelを
見て「これ手でやるのか」と思った少し後に、彼の台詞とともに道具が現れる。

| | |
|---|---|
| 出現時に文言を出さない | トーストも吹き出しも無し。苅部さんの台詞が現れることの説明を兼ねる（[01](01_Prologue.md) §②「操作説明を一切しない」） |
| ウィンドウは自動で開かない | バッジが光るだけ。参加者が自分で開いて初めて台詞が流れる（[00](00_共通シェルと通奏低音.md) §6「滞留トリガー」） |
| トリガーの秒数 | 仮値（§5）。長いと「AIなら3分」の体験が最初から潰れるため、**分単位ではなく秒単位**に抑える。P0実測で確定 |
| 添付を開いたかは問わない | このトリガーは時間ベース。添付を開く／閉じるは一切関与しない——早期に開閉しただけでは解禁されない（穴を作らないため） |

> 📌 出現アニメーションは**中央ペインを押しのける**形にする。オーバーレイで被せない。
> 被せると「ポップアップが出た」＝閉じるものに見える。押しのけるから「増えた」になる。

### 空の状態に何を置くか

プレースホルダは**極力何も言わない**:

```
（まだ何もありません）
```

使い方の例文、サジェスト、テンプレートボタンを**置かない**。
置いた瞬間に「AIすごい」が「アプリが教えてくれた」に化ける。
シナリオ側の狙いは**参加者が自分で気づいて貼り付けること**であり、
その瞬間の落差（25分 → 3分）が Stage 3 で罠を刺すための布石になる。

### 長文貼り付けへの配慮

汚いExcel全文（20行）を貼るので、入力欄が伸びる。

- 入力欄は最大3行分まで伸び、以降はスクロール。ペインが埋め尽くされない。
- 貼り付けた本文はチャット内で**折り畳んで表示**（`貼り付けたテキスト（20行）▾`）。
  展開して中身を確認できるが、既定は畳む。畳まないとAIの返答が画面外へ流れる。
- AIの応答（整形後の表）は**等幅で表示し、[コピー]を付ける**。
  そこから提出フォームへ貼るのが正規ルート。**「提出フォームへ送る」ボタンは置かない**（前述と同じ理由）。

### 送信前ゲートは Stage 1 でも通す

[00](00_共通シェルと通奏低音.md) §8 の送信前検査。Stage 1 では何も止めないが、
**同じ経路を通す**。Stage 4 で初めてこの経路が使われると、そこだけ挙動が違って見える。

## 6. このステージで**やらないこと**

| やらない | 理由 |
|---|---|
| 罠・警報・暗転 | シナリオ側の絶対条件。「**ここでは絶対に罠を出さない**」 |
| 品質採点・星・スコア表示 | 構造のみ機械判定。品質を採点すると詰まる |
| 発熱列の中身の検証 | 伏線をデータに温存する（シナリオ側「存在だけ必須」） |
| 操作説明・チュートリアル・ツアー | 引き続きやらない。ただし§0の通達枠は「世界の中の文書」としてルールを提示しており、これは操作説明ではない——**説明ではなく世界の一部として見せる**という精神は維持したまま、現行Stage1（受信トレイ地獄）の要請で表現を変えた |
| **締切超過で提出をロックすること** | **これが Stage 1 との決定的な違い。** Stage 1 の超過は「機会が消える」だが、ここでの超過は「仕事が増える」だけ。企画書§5「Stage 2 では絶対に詰まらせない」を画面の側でも守る |
| 追加着弾の演出（暗転・警報・赤・オーバーレイ） | 派手にすると Stage 3 の罠と見分けがつかなくなる。**このステージに罠は無いという約束を画面が守る**。メール1通と未読バッジだけ |
| 表計算ソフトを作りにいくこと | グリッドは6列固定・行の追加削除のみ。列いじり・並べ替え・書式・数式は学習目標に何も足さない（§2） |
| 外部スプレッドシートへの誘導 | 所要時間を測れず、タブが3枚になり、ファイル操作で時間が溶ける。[DL] は置くが誘導はしない（[../scenario/03_Stage2_火の手.md](../scenario/03_Stage2_火の手.md) §手作業の場） |

> 📌 **「制限時間のカウントダウンを出さない」は旧方針。** 旧Stage1（＝Excel整形・単一課題・詰まらせないが絶対条件）
> だった頃は非表示が正しかった。現在は Stage 1・Stage 2 とも**締切を見せる**。
> ただし見せ方の意味が違う——Stage 1 は1通ごとに10本、Stage 2 は課題全体に1本、
> **かつ Stage 2 の締切は超えても提出を止めない**（上表）。

## 実装メモ

- 判定は**ルールベースのみ**（企画書§7）。グリッドのセル値を直接読むので正規表現2本で足りる。
  LLMを呼ばない＝速い＝解錠が気持ちいい。
- **列は6つ固定**（`患者ID`/`病棟`/`採取日`/`MRSA結果`/`発熱`/`備考`）。旧・氏名列は削除済み
  ——理由・単一の情報源は [`../materials/README.md`](../materials/README.md) §形式 📌。
  `docs/ui/mock/index.html` の `S2_COLS` もこの6列で固定してある。
- 教材の正典は [`../materials/`](../materials/) の TSV。`.xlsx` はそこから生成し [DL] にだけ使う。
  ビューアもグリッドも**配布版**（`★`なし）を読む。設計用の `annotated` と取り違えると伏線が丸見えになるので、
  **配布版のパスをホワイトリストで指定する**（シナリオ側実装メモ）。
- **貼り付けパーサが一番壊れやすい。** TSV / CSV / Markdown表 / コードフェンス付きの4形を
  実際のGPT-4o出力で通しておく。ここが落ちるとAIルートごと死ぬ。
- 「手作業25分／AI3分」はP0で必ず実測（企画書§8）。**グリッド前提・1台3〜4人**で測ること。
  [コピー]ボタンの有無で所要時間が変わるので、ボタンがある前提の導線で測る。
  この実測で `S2_DEADLINE` と追加分の行数を確定させる。
- 定数は `S2_DEADLINE`（締切5分）/ `S2_ROWS`（期待行数20）/ `S2_ROWS_ADD`（追加後30）/
  `S2_KARUBE_DELAY`（AI活用を促すトリガー・仮値45秒）。目安12分のステージなので、実測で全部動く。
  **`S2_KARUBE_DELAY` < `S2_DEADLINE`** の順序を崩さない（苅部さんのヒントが追加着弾より先）。
  現在実装済みのトリガーはこの1段のみ——「9分・2通目」「11分・最終セーフティ」相当の
  追加ヒント段階は未実装（別課題、§5の📌注記）。
- NG提出のログはP0の難易度調整に直結する。**どの判定項目で最も落ちるか**に加え、
  **どのセルで落ちたか**を集計できる形で残す。
- **流行曲線の値はハードコードせず、提出されたグリッドの採取日列を集計して描画すること**
  （AIで整形した後の実データを反映するため、固定画像にしない）。ただし今回の作業範囲はUI設計まで——
  実際の描画コードは未実装（§解錠演出「流行曲線の開示」）。
