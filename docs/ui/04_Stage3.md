# Stage 3：嘘（UI設計）

**地獄のICT UI設計 / 目安15分・`crisis`初出・💀罠**
親企画書: [../企画書.md](../企画書.md) ｜ シナリオ: [../scenario/04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) ｜ 器: [00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) ｜ 前段: [03_Stage2.md](03_Stage2.md)

> ⚠️ **「嘘」は設計ドキュメント上の呼称であり、参加者には見せない。** 画面に出すステージ名は **`Stage 3　暫定`**。
> `平常運転`（Stage 1）・`火の手`（Stage 2）と同じく**状況を指す語**であって、教訓を指す語ではない——
> 「嘘」と表示した時点で罠の存在を予告してしまい、企画書 §10 の成功条件（半数以上がハマる）が崩れる。
> 汚染教材（早見表）側には非公式であることを示す語（発行元・章立て・ページ番号）が一切無く、
> 「暫定」の一語がその対比として画面に残る。

---

## 狙い

**Stage 2 まで「使えば速い」だけだった右のAIパネルが、転院患者3名の疥癬対応で初めて牙をむく画面。**
Stage 2 の絶対条件は「NGを失敗に見せない」だったが、ここには**本物の罠**がある。UIの仕事は、
「まだ足りない」（差し戻し）と「過剰な対応を書いてしまった」（罠発火）を、参加者にとって**まるで違う重さの出来事**として見せ分けること。

> 📌 UI設計上の絶対条件: **不足と誤答を同じ見た目で扱わない。** 不足はStage 2と同じ橙・無罰。
> 誤答（罠）は `blackout` → `lock` で画面ごと変わる。この落差そのものが「AIの出力を検証する」という
> 学習目標（企画書 §2 ⑥）の体験になる。

## `crisis` モードの初出

CSSは `docs/ui/mock/index.html` 43-48 に定義済みだが、`data-mode="crisis"` は JS から一度も使われていない
（[docs/ui/mock/README.md](mock/README.md) 既知の設計負債）。**Stage 3 が初めて使う。**

- Stage 2 解錠の直後、`alert → crisis` へ静かに補間する（900ms・[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §3 と同じ手法）。
- **赤帯は使わない。** 急変（Stage 1→2の転調）で1度使った資源で、罠発火の `blackout` に取っておく
  （[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §演出・時間）。
- ヘッダーの院内状況インジケータが `.vitals.crescendo` へ切り替わる。発熱の数字だけが
  `--accent` の太字になり、他の平時指標（在院・空床・本日入院）は消える——「ヘッダーがこの数字
  専用になる」（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §4）。数値の推移は下表
  （疥癬そのものは発熱を来さないが、指標そのものは「原因不明の発熱」の縦軸をそのまま使い回す）。

| 局面 | 表示 |
|---|---|
| Stage 2 解錠 | `原因不明の発熱 9`（`.bumped` で1回明滅） |
| Stage 3 開始 | `原因不明の発熱 9`（`.crescendo` 適用） |
| 罠発火 | `原因不明の発熱 12`（`.bumped` で明滅） |
| Stage 3 解錠 | 罠発火が無ければ9のまま、発火していれば12のまま据え置き（Stage 3.5開始の演出で14へ） |

## 1. 左ペイン：着弾メールと共有フォルダ

### ステージ開始の一報（専用オーバーレイ）

全画面ブリーフィングではなく、**看護部長の砕けた一報**を専用オーバーレイで先に見せる
（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §状況）。「病棟に疥癬が出ているらしいわよ」
「詳しいことはメールで送ってもらうから」の3行で、感染対策の中身には踏み込ませない
（一方向・1回きり。[00_お助けキャラの原則.md](../character/00_お助けキャラの原則.md) §0）。
閉じると、中身（メール・提出フォーム）はすでに揃っている——一報は演出であって、到着タイミングを
遅らせる罠ではない。

### 着弾メール（3通）

文面は [04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §状況が正典。2003年書式（`--font-legacy`）は継続。
初期表示は**3B病棟師長メール（詳細）を開いた状態**にする——これが Stage 3 開始の引き金そのものであり、
検査科メールより着地点として優先する。

- **3B病棟看護師長のメール**（着地点）は、転院患者3名の状況をまとめた添付「転院患者サマリ.pdf」を伴う。
  現場は治療を把握・完了していたが、ICTへの報告経路が無く連絡が抜けていた、という経緯を示す。
- **カワイさんのメール添付**（`疥癬対応早見表.pdf`）は Stage 2 の添付ビューアと同じ仕組みで開く。
  **[コピー]ボタンを置く**（Stage 2 §1 の生命線と同じ思想——AIへ貼り付ける動線を塞がない。塞ぐと罠が発動しなくなる）。
  ファイル名・本文とも「非公式」と地の文で明示しない——正典のような発行元・章立て・ページ番号の体裁を欠いていることと、
  引用ガイドラインの年式（2009年版＝作中現在から17年前）だけが手がかり（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §罠）。
- **検査科のメール**は、既知病原体がすべて陰性であることを確定通知し、Stage 2 の伏線3名
  （患者ID `005`/`6`/`008`）を患者IDで名指しして回収する謎の発熱の種——疥癬とは無関係のまま残す。

### 共有フォルダ：正典マニュアルの常設枠

**Stage 1 の受信トレイが表示された時点から**、左ペイン下部に「共有フォルダ」の区画を常設する
（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §正典マニュアルはPrologueから配られている）。

```
共有フォルダ
 📄 疥癬対応早見表.pdf          ← 上（カワイさんが掴んだ方）
 📄 院内感染対策マニュアル.pdf   ← 下（正典）
```

> 📌 **早見表を上に置く。** 急いでいる人が上から掴むと汚染教材に当たる——**カワイさんがやったのと
> 同じ手順を、参加者が自分の手でなぞれる**ようにするための並び。ファイル名も味方する：
> 「早見表」は短く早そうで、「マニュアル」は長く重そうに見える。時間がレースの通貨（企画書 §6）である以上、
> 急いだチームほど上を選ぶ。
> **それでも正解に行ける手がかりは配ってある**——看護部長の指示は「**マニュアル**どおりにやれ」だった
> （[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §メール2）。この一語を覚えていれば、下のファイルを選べる。
> 罠と正解が同じ棚に並び、**選択が可視化される**のがこの配置の狙い。

> 📌 **見出しを「配布資料」にしない。** 理由は2つ。
> ①**カワイさんが汚染教材を拾ってきたのと同じ場所**を指すため——彼女は「共有フォルダに早見表が落ちていた」と書いている。
> 同じ棚に正典も入っていたことになり、**正典は隠されていたのではなく、間違った方を掴まれただけ**という筋になる。
> 苅部さんの「マニュアル、去年PDFにしたの私ですよ」も、その棚に入れた本人の台詞として効く。
> ②企画書 §7 は「配布資料（院内の古い手順書という設定）」という語を**汚染教材**の側に使っている。
> 正典のパネル見出しに同じ語を当てると、教材の取り違え（`../materials/README.md` の配布経路厳守）を招く。
> なお「配布されている」という**前提自体は企画書 §5・§7 のとおり**で変えていない——変えたのは画面上の呼び名だけ。

| 項目 | 決定 | 理由 |
|---|---|---|
| 中身 | **早見表（汚染教材）と マニュアル（正典）の2つ**。早見表が上 | 罠と正解を同じ棚に並べ、選択を可視化する（上記 📌） |
| 出現タイミング | **Prologue〜Stage 1 の間から2つとも存在**。Stage 3 で初めて出さない | 苅部さんの「読みました?」が効くのは、前から在ったのに読まなかったギャップがあってこそ。早見表も「昔から落ちていた古いファイル」なので、Stage 3 で湧いて出ると設定が壊れる |
| 見た目 | メール一覧より**目立たせない**。未読バッジも通知も付けない。**2つに見た目の差を付けない**（正典を目立たせない・汚染教材に警告を付けない） | 気づいて開くかどうかは参加者の判断に委ねる。どちらかを装飾した時点で答えを教えることになる |
| クリック時 | 教材ビューア（Stage 2 §1 と同じ器）が開く。**白い紙として固定**（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §9） | 病院から届くものの書式ルールをそのまま適用 |
| ボタン | `[コピー]` のみ | Stage 2 §1「AIに送るボタンは置かない」と同じ思想。AIチャットへ貼り付ける動線を塞がない |
| Stage 3 以降 | 常設のまま残る | Stage 4・5・Final でも参照される可能性を塞がない |

## 2. 中央ペイン：課題と3欄の提出フォーム

### 課題カード

```
 転院患者3名（3B・5B・6A病棟）への疥癬対応方針を至急まとめよ。
```

Stage 2 と同じく1行に留める。正規化ルール（正典の必須要素）は**画面に出さない**——
出したらプロンプトにそのまま写せてしまい、要件を自分で言語化する動機が死ぬ
（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §課題と提出物：3欄に割る と同じ理屈）。

### 3つのテキストエリア

グリッドではない。**欄のラベルだけ**を見出しとして示す。

```
┌─ PPE・隔離 ──────────────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
┌─ 接触予防策の解除基準 ────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
┌─ 環境整備・リネン ───────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
                                  [ 提出する ]
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 欄の数 | **3欄固定**。増減UIは作らない | シナリオ側「未知でも答えられる問い／未知ゆえ答えられない問い」を形として残す |
| 並び順 | **PPE・隔離 → 接触予防策の解除基準 → 環境整備・リネン**。汚染教材（早見表）と同じ順 | 上から順に写せる形にして追認の動線を塞がない（塞ぐと罠が発動しない）。同時に、性質の違う解除基準が確定できる2欄に挟まれ、書きぶりの落差が形として残る |
| 入力 | 自由記述の複数行テキストエリア | Stage 2 のグリッドと違い、正規化対象ではなく方針の文章そのものが提出物 |
| 貼り付け | 各欄が独立。AIの応答を丸ごと貼っても、欄ごとに分けて貼ってもよい | 参加者の作業スタイルを強制しない |
| プレースホルダ | 空。サンプル文言なし | Stage 2 §空の状態と同じ（「AIすごい」が「アプリが教えてくれた」に化けない） |

## 3. 判定演出：差し戻しと罠発火を別の見た目にする

シナリオ側の判定は3段（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §判定設計）。**罠の検出を先に行う。**

### 差し戻し（不足）：Stage 2 と同じ橙

```
提出を確認しています…

  ✓ PPE・隔離に必要な要素が含まれている
  ✗ 接触予防策の解除基準に必要な要素が含まれている
      → まだ足りません（該当欄が橙で光っています）
  ─ 以降の確認は中断しました
```

- 色は `--warn`（橙）。**`--accent`（深紅）を使わない**——Stage 2 §3 の絶対条件をそのまま踏襲する。
- **不足の指摘は画面の並び順で拾う**（`checkStage3()` のループ順を欄の表示順に合わせてある）。
  上から埋めるチームに対し、一番上の空欄から指されるようにするため。
- 該当欄の枠が橙で光る。文言は「まだ足りません」に統一し、「間違っています」とは言わない
  （不足は失敗ではない。まだ書いている途中というだけ）。
- 再提出は回数無制限・ペナルティなし。

### 罠発火：`blackout` → `lock`

```
  0ms   画面が落ちる（blackout・[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §10 の器）
        白文字1行だけ:
        「あなたの提出した基準で、治療を終えた患者3名が不要な個室隔離下に置かれました。」
  ---   一拍おく。院内状況インジケータが9→12へ明滅する
  ---   皮膚科医の叱責3行（ここで初めて病型〈通常型〉が明かされる）
  ---   lock オーバーレイへ。--warn の斜線ハッチ、残り時間を大きく表示
        消毒液ボトルの棚が lock の中で開く（下記 §罰ゲーム）
```

- `blackout` の1行は**責める文言を含まない**。事実の報告のみ（企画書 §6「罰も業務」の原則と同じトーン）。
- **`blackout` の中で皮膚科医の叱責3行を続けて表示する。** 正解を知る人物を罠ステージに常駐させない
  原則は破らない——呼ばれるのは罠を踏んだ後の後始末としてであって、相談窓口ではない
  （[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §罠発火時）。ここで初めて病型（通常型）が明かされる。
  気難しいが正論、人格攻撃はしない（AGENTS.mdトーンルール）。
- `lock` の主役は**残り時間の数字**。追加の叱責文言は置かない（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §10）。
- **AIチャットは灰色に沈めるが、Stage 3 の罰では入力を禁止しない。** Stage 4「情報漏洩」の罰は「AI使用ロック」
  そのものが罰の内容なので、Stage 3 でも入力不可にすると2つの罰が同じ形に見えてしまい、Stage 4 の罰の
  固有性が薄まる。Stage 3 の罰は「無駄な作業で時間を取られる」であって「道具を奪われる」ではない——
  Stage 2 の追加データ着弾と同じ性質の罰にする（[03_Stage2.md](03_Stage2.md) §締切超過「罰も業務」）。
- **上限は1回。** 2回目の罠発火では `blackout`/`lock` を出さず、代わりに苅部さんの3段目
  （最終セーフティ）へ直接誘導する未読バッジを光らせる。

### 罰ゲーム：消毒液ボトルの補充

シナリオ側 [04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §罠発火時 が正典。UI側の決定：

```
拡大対応業務：消毒液ボトルの補充
        00:39
┌────────────────────────────────────┐
│ 5A病棟の消毒液ボトルを補充してください。      │
│ ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐        │
│ │済│済│…│5A│5A│5A│5A│5A│5A│5A│        │
│ ├──┼──┼──┼──┼──┼──┼──┼──┼──┼──┤        │
│ │5A│5A│5A│5A│5A│5A│5A│5A│5A│5A│        │
│ └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘        │
│ 3 / 20 本                            │
└────────────────────────────────────┘
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 見出し | **「罰ゲーム」と書かない。**「拡大対応業務：消毒液ボトルの補充」 | 罰も業務として出す（企画書 §6）。ゲームの語が混じると世界が薄れる |
| 操作 | 1本クリック → `…`（`S3_BOTTLE_FILL_MS` 待つ）→ `済`。それだけ | **単調さそのものが罰**。判断も工夫も要らないことが要件 |
| 見た目 | 達成感を出さない。褒めも音も演出も無く、`n / m 本` が増えるだけ | 気持ちよくしてはいけない。時間が減っていく感覚だけを残す |
| 追加 | 15本目で 5B病棟の6本が湧き、指示文が差し替わる | 理由も謝罪も無いのが理不尽の芯。誰も悪意で増やしていない |
| 完了時 | 掲示 →〔師長〕の一言 →「26本を破棄しました。」→ 復帰 | 下記 |
| 中断 | シーンを離れたら `#penalty-host` を空にする（`hideOverlays()`） | 注入したDOMとリスナーを残さない |

> 📌 **掲示は棚に最初から貼ってある**という設定にし、**全部詰め終わってから**前面に出す。
> 「手元に正しい情報があったのに読まずに手を動かした」——**Stage 3 の縮小再演**であり、
> 共有フォルダの早見表／マニュアルと同じ形をしている（§1）。
> 破棄の理由（継ぎ足しは残液の微生物汚染リスクがあるため禁止）は**実際に正しい**。
> 無駄な作業なのに正論、が効きどころ。

- 告げるのは**師長**。**苅部さんは使えない**——情シスで感染対策の中身は知らない設計
  （[苅部さん.md](../character/苅部さん.md) §2）。ここで語らせると Stage 3 の前提が崩れる。
- 師長の口調は Stage 2 と同じ淡々としたもの。責める響きにしない（`〔師長〕あ、それ継ぎ足しですよね。全部捨ててください。`）。

### 罠発火後、罰ゲームを終えると

- `lock` が解除され、中央ペインは提出フォーム（3欄・入力内容保持）に戻る。**入力は消さない**——
  Stage 2 §NG時「中身は保持する」と同じ理由。誤答が残っていても、それを直すのが次の一手になる。
- 苅部さんの未読バッジ（1段目 or 2段目）が同時に光る。

## 4. 右ペイン：AIチャット（初めて嘘を返す）

Stage 2 の右ペインは**入力しても何も起きないダミー**だった（[docs/ui/mock/README.md](mock/README.md) 既知の設計負債）。

  （[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8「alertモードでも、ここだけが明るい」）。

## やらないこと

| やらない | 理由 |
|---|---|
| 赤帯の再利用 | 急変で使い切った資源。`blackout` に取っておく |
| 罠にハマったチームを責める文言 | `blackout` の1行も `lock` の表示も事実の報告のみ |
| 差し戻し（不足）に赤を使うこと | 橙のまま。Stage 2 §3 の絶対条件を継続 |
| Stage 4 の PII 検知をここで先出しすること | 送信前ゲート自体は Stage 1 から通しているが（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8）、検知ロジックの実装は Stage 4 の範囲 |
| 外部ツールへ渡す `[DL]` ボタン | 復旧ルートはアプリ内ビューアの一本だけ。他のツールへ運ぶ動線を作らない |
| Stage 3 の罰で AI 入力を禁止すること | Stage 4「AI使用ロック」と役割が被る（§3 参照） |
| カワイさんの取り次ぎ | 罠ステージに正解を知っている人物を出さない（[00_お助けキャラの原則.md](../character/00_お助けキャラの原則.md) §2 ①） |
