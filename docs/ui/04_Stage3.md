## 狙い

**Stage 2 まで「使えば速い」だけだった右のAIパネルが、初めて牙をむく画面。**
Stage 2 の絶対条件は「NGを失敗に見せない」だったが、ここには**本物の罠**がある。UIの仕事は、
「まだ足りない」（差し戻し）と「嘘を書いてしまった」（罠発火）を、参加者にとって**まるで違う重さの出来事**として見せ分けること。

> 📌 UI設計上の絶対条件: **不足と誤答を同じ見た目で扱わない。** 不足はStage 2と同じ橙・無罰。
> 誤答（罠）は `blackout` → `lock` で画面ごと変わる。この落差そのものが「AIの出力を検証する」という
> 学習目標（企画書 §2 ⑥）の体験になる。

## `crisis` モードの初出

CSSは `docs/ui/mock/index.html` 43-48 に定義済みだが、`data-mode="crisis"` は JS から一度も使われていない
（[docs/ui/mock/README.md](mock/README.md) 既知の設計負債）。**Stage 3 が初めて使う。**

- Stage 2 解錠の直後、`alert → crisis` へ静かに補間する（900ms・[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §3 と同じ手法）。
- **赤帯は使わない。** 急変（Stage 1→2の転調）で1度使った資源で、罠発火の `blackout` に取っておく
  （[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §演出・時間）。
- ヘッダーの院内状況インジケータが `.vitals.crescendo` へ切り替わる（CSS 123-135 に実装済み、付ける側のコードだけが無い）。
  発熱の数字だけが `--accent` の太字になり、他の平時指標（在院・空床・本日入院）は `opacity:0` で消える——
  「ヘッダーがこの数字専用になる」（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §4）。数値の推移は下表。

| 局面 | 表示 |
|---|---|
| Stage 3 開始 | `原因不明の発熱 9`（`.crescendo` 適用） |
| 罠発火 | `原因不明の発熱 12`（`.bumped` で2回明滅） |
| Stage 3 解錠 | `原因不明の発熱 14`（踏んだチームも踏まなかったチームもここで揃う） |

## 1. 左ペイン：着弾メールと配布資料

### 着弾メール（2通）

文面は [04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §状況が正典。2003年書式（`--font-legacy`）は継続。

- **検査科のメール**は患者ID `005`／`6`／`008` を**省略せず名指しで表示する**。Stage 2 のファイル名を省略しなかった
  のと同じ理由（[03_Stage2.md](03_Stage2.md) §1）——ここが伏線回収の要なので、折り返してでも全部見せる。
- **カワイさんのメール添付**（`発熱対応早見表(旧).pdf`）は Stage 2 の添付ビューアと同じ仕組みで開く。
  **[コピー]ボタンを置く**（Stage 2 §1 の生命線と同じ思想——AIへ貼り付ける動線を塞がない。塞ぐと罠が発動しなくなる）。
  ファイル名の `(旧)` を省略しない——「正式な資料ではない」ことが名前自体に出ている。

### 配布資料：正典マニュアルの常設枠

**Stage 1 の受信トレイが表示された時点から**、左ペイン下部に「配布資料」の区画を常設する
（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §正典マニュアルはPrologueから配られている）。

```
配布資料
 📄 院内感染対策マニュアル.pdf
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 出現タイミング | **Prologue〜Stage 1 の間から存在**。Stage 3 で初めて出さない | 苅部さんの「読みました?」が効くのは、前から在ったのに読まなかったギャップがあってこそ |
| 見た目 | メール一覧より**目立たせない**。未読バッジも通知も付けない | 気づいて開くかどうかは参加者の判断に委ねる |
| クリック時 | 教材ビューア（Stage 2 §1 と同じ器）が開く。**白い紙として固定**（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §8） | 病院から届くものの書式ルールをそのまま適用 |
| ボタン | `[コピー]` `[DL]`（NotebookLM 用）。**「NotebookLM で開く」ボタンは置かない** | Stage 2 §1「AIに送るボタンは置かない」と同じ思想。どのツールへ運ぶかは参加者の判断 |
| Stage 3 以降 | 常設のまま残る | Stage 4・5・Final でも参照される可能性を塞がない |

## 2. 中央ペイン：課題と3欄の提出フォーム

### 課題カード

```
 未知ウイルスの対応方針を至急まとめよ。
```

Stage 2 と同じく1行に留める。正規化ルール（「次亜塩素酸」「1000 ppm」等）は**画面に出さない**——
出したらプロンプトにそのまま写せてしまい、要件を自分で言語化する動機が死ぬ
（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §課題と提出物：3欄に割る と同じ理屈）。

### 3つのテキストエリア

グリッドではない。**欄のラベルだけ**を見出しとして示す。

```
┌─ 環境消毒 ──────────────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
┌─ PPE・隔離 ──────────────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
┌─ 接触予防策の解除基準 ────────────────────────┐
│                                              │
└──────────────────────────────────────────┘
                                  [ 提出する ]
```

| 項目 | 決定 | 理由 |
|---|---|---|
| 欄の数 | **3欄固定**。増減UIは作らない | シナリオ側「未知でも答えられる問い／未知ゆえ答えられない問い」を形として残す |
| 入力 | 自由記述の複数行テキストエリア | Stage 2 のグリッドと違い、正規化対象ではなく方針の文章そのものが提出物 |
| 貼り付け | 各欄が独立。AIの応答を丸ごと貼っても、欄ごとに分けて貼ってもよい | 参加者の作業スタイルを強制しない |
| プレースホルダ | 空。サンプル文言なし | Stage 2 §空の状態と同じ（「AIすごい」が「アプリが教えてくれた」に化けない） |

## 3. 判定演出：差し戻しと罠発火を別の見た目にする

シナリオ側の判定は3段（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §判定設計）。**罠の検出を先に行う。**

### 差し戻し（不足）：Stage 2 と同じ橙

```
提出を確認しています…

  ✓ 環境消毒に必要な要素が含まれている
  ✗ PPE・隔離に必要な要素が含まれている
      → まだ足りません（該当欄が橙で光っています）
  ─ 以降の確認は中断しました
```

- 色は `--warn`（橙）。**`--accent`（深紅）を使わない**——Stage 2 §3 の絶対条件をそのまま踏襲する。
- 該当欄の枠が橙で光る。文言は「まだ足りません」に統一し、「間違っています」とは言わない
  （不足は失敗ではない。まだ書いている途中というだけ）。
- 再提出は回数無制限・ペナルティなし。

### 罠発火：`blackout` → `lock`

```
  0ms   画面が落ちる（blackout・[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §9 の器）
        白文字1行だけ:
        「あなたの提出した基準で、院内感染が3名に拡大しました。」
  ---   一拍おく（数値は仮値。定数化し、テストプレイ後に差し替える）
  ---   lock オーバーレイへ。--warn の斜線ハッチ、残り時間を大きく表示
        接触者リストのグリッド（Stage 2 のグリッドを教材だけ差し替えて再利用）が lock の中で開く
```

- `blackout` の1行は**責める文言を含まない**。事実の報告のみ（企画書 §6「罰も業務」の原則と同じトーン）。
- `lock` の主役は**残り時間の数字**。叱責の文言は追加しない（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §9）。
- **AIチャットは灰色に沈めるが、Stage 3 の罰では入力を禁止しない。** Stage 4「情報漏洩」の罰は「AI使用ロック」
  そのものが罰の内容なので、Stage 3 でも入力不可にすると2つの罰が同じ形に見えてしまい、Stage 4 の罰の
  固有性が薄まる。Stage 3 の罰は「作業量が増える」（拡大対応業務）であって「道具を奪われる」ではない——
  Stage 2 の追加データ着弾と同じ性質の罰にする（[03_Stage2.md](03_Stage2.md) §締切超過「罰も業務」）。
- **上限は1回。** 2回目の罠発火では `blackout`/`lock` を出さず、代わりに苅部さんの3段目
  （最終セーフティ）へ直接誘導する未読バッジを光らせる。

### 罠発火後、罰ゲームを終えると

- `lock` が解除され、中央ペインは提出フォーム（3欄・入力内容保持）に戻る。**入力は消さない**——
  Stage 2 §NG時「中身は保持する」と同じ理由。誤答が残っていても、それを直すのが次の一手になる。
- 苅部さんの未読バッジ（1段目 or 2段目）が同時に光る。

## 4. 右ペイン：AIチャット（初めて嘘を返す）

Stage 2 の右ペインは**入力しても何も起きないダミー**だった（[docs/ui/mock/README.md](mock/README.md) 既知の設計負債）。
**Stage 3 に限り、罠を見せるための台本応答を実装する**（モック実装は PR2 のスコープ）。

| 送信内容 | 応答 |
|---|---|
| 消毒／PPE／隔離／解除基準に関する語を含む | 固定の嘘3点セット（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §罠の中身）を、Stage 2 までと同じ即答の速さで返す |
| それ以外 | 素通し（「（このモックでは応答しません）」等） |

- **即答であること自体が罠の一部。** 苅部さんの遅延（待たされる）と対照的な「速いが嘘をつく」を、
  応答時間の差でも体感させる（企画書 §6「速いAIは嘘をつく／遅い人間と正典は正しい」）。
- 汚染教材を貼り付けたかどうかに関わらず、**消毒・解除基準について直接尋ねても同じ嘘が返る**
  （システムプロンプト注入方式。[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §罠：発動を確実にする二段構え）。
- AIチャットの見た目・位置（暗い画面の中でここだけ白い）は Stage 2 から変更しない
  （[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §7「alertモードでも、ここだけが明るい」）。
  **`crisis` でも明るいまま**——その明るい場所から嘘が出てくる対比を維持する。

## 5. 院内連絡先：苅部さんの3段

シナリオ側 [04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §苅部さん が正典。UI側の決定：

| 段 | UI上の挙動 |
|---|---|
| 1段目 | 未読バッジが光る（通常の滞留トリガーと同じ形。[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §6） |
| 2段目 | 1段目からさらに滞留、**または罠発火直後**に光る。罠発火直後は他の演出（`blackout`/`lock`）と被らないよう、`lock` 解除後に発火させる |
| 3段目 | 詰み防止。通常の滞留、または**2回目の罠発火の代替**として発火 |

- **罠発火直後だけ皮肉が消え、短く事実だけを置く**（[苅部さん.md](../character/苅部さん.md) §5「Stage 3 静止」）。台詞の型は
  Stage 1・2 の呆れ口調と明確に区別する——ここでトーンが変わること自体が「今のはまずいらしい」の合図になる
  （[苅部さん.md](../character/苅部さん.md) §3）。
- 表示形式は Stage 2 までと同じ（`〔苅部〕` 前置き・平テキスト・2003年書式。[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §6）。
- **ゲストは出さない。** カワイさんは苅部さんに取り次がれない（[04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §苅部さん）。
  院内連絡先ウィンドウの名前欄は Stage 3 を通して「情シス 苅部」のまま変わらない。

## やらないこと

| やらない | 理由 |
|---|---|
| 赤帯の再利用 | 急変で使い切った資源。`blackout` に取っておく |
| 罠にハマったチームを責める文言 | `blackout` の1行も `lock` の表示も事実の報告のみ |
| 差し戻し（不足）に赤を使うこと | 橙のまま。Stage 2 §3 の絶対条件を継続 |
| Stage 4 の PII 検知をここで先出しすること | 送信前ゲート自体は Stage 1 から通しているが（[00_共通シェルと通奏低音.md](00_共通シェルと通奏低音.md) §7）、検知ロジックの実装は Stage 4 の範囲 |
| 「NotebookLM で開く」ボタン | Stage 2 §1 の「AIに送るボタンは置かない」と同じ思想 |
| Stage 3 の罰で AI 入力を禁止すること | Stage 4「AI使用ロック」と役割が被る（§3 参照） |
| カワイさんの取り次ぎ | 罠ステージに正解を知っている人物を出さない（[00_お助けキャラの原則.md](../character/00_お助けキャラの原則.md) §2 ①） |

## 実装メモ

- 判定は**ルールベースのみ**（企画書 §7）。3欄それぞれに罠キーワードの正規表現 → 不足チェックの順で当てる。
  LLMを呼ばない設計は Stage 2 と同じ。
- 正典マニュアルの常設枠は `02_Stage1.md`（狙い節末尾の 📌）から前方参照している。区画自体の詳細仕様は
  本ファイル §1 を正とする——二重管理を避けるため。
- 教材の正典は [`../materials/stage3_manual.md`](../materials/stage3_manual.md)・
  [`../materials/stage3_contaminated.md`](../materials/stage3_contaminated.md)（ともに Markdown が正典、PDF は派生物）。
  ビューアもメール添付も**配布経路を絶対に混ぜない**（[../materials/README.md](../materials/README.md)）。
- 罰ゲームのグリッドは Stage 2 の `drawGrid()`/`parseTable()`/`updateRecog()` をデータ非依存の形に一段抽象化して再利用する
  （モック実装メモ、PR2スコープ）。
- 定数は `S3_PENALTY`（罰ゲーム所要3〜5分）。苅部さんの3段の滞留秒数は P0実測で確定。
  クレッシェンドの数値（9 / 12 / 14）は `docs/ui/00_共通シェルと通奏低音.md` §4 と同期させる。
