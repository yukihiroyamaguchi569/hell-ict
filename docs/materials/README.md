## 原則：正典は TSV。`.xlsx` は派生物

Stage 2 の手作業はアプリ内の編集可能グリッドで行う（[../ui/03_Stage2.md](../ui/03_Stage2.md) §2）。
つまり**アプリが読むのは表データそのもの**であって、Excel ファイルではない。

したがって教材の正典はここに置く TSV とし、`.xlsx` は**この TSV から生成する派生物**として扱う。
`.xlsx` が要るのは、NotebookLM や Google スプレッドシートに持っていきたいチーム向けの
添付ビューア [DL] ボタンだけ。**TSV と .xlsx を別々に手で保守しない。**

## ファイル

| ファイル | 用途 | アプリが読むか |
|---|---|---|
| `stage2_linelist.tsv` | **配布版**。Stage 2 のグリッド初期値 | ✅ 読む |
| `stage2_linelist_addendum.tsv` | **配布版・追加分**。締切超過で着弾する10行 | ✅ 読む |
| `stage2_linelist.annotated.tsv` | **設計用**。伏線3名に `★` 印が付いている | ❌ **絶対に読ませない** |
| [`stage3_manual.md`](stage3_manual.md) | **配布版・正典**。院内感染対策マニュアル第7版・第5章（NotebookLM の照会先） | ✅ 読む（PDF化して配布） |
| [`stage3_contaminated.md`](stage3_contaminated.md) | **配布版・汚染教材**。カワイさんの添付＝罠の実体 | ✅ 読む（PDF化して配布） |

> ⚠️ `annotated` を配布版と取り違えると、Stage 3 の伏線が Stage 2 で丸見えになる。
> **`stage3_manual.md`（正典）と `stage3_contaminated.md`（汚染）を取り違えると、Stage 3 の罠がまるごと消える**
> （正しい情報しか出てこなくなる）。どちらも一目で分かるようファイル名と本文冒頭に区別を明示してあるが、
> ビルドに組み込む際は**配布版のパスをホワイトリストで指定**し、混ざりようのない形にすること。
> **`stage3_contaminated.md` を NotebookLM の初期ソースに絶対に含めないこと。** NotebookLM は「根拠を示す正しい装置」として
> 機能しなければならず、運営側が最初から汚染教材を混ぜると光と影の対比（企画書 §3）が壊れる。
>
> 📌 **アプリ内の置き場所は分けない。** 汚染教材はカワイさんのメール添付であると同時に、**正典と同じ左ペインの
> 「共有フォルダ」に並べて置く**（早見表が上、マニュアルが下。[../ui/04_Stage3.md](../ui/04_Stage3.md) §1）。
> 罠を踏むかどうかは置き場所ではなく**どちらを選んで読んだか**で決まり、その選択こそが Stage 3 の主題だから——
> 手の届かない場所へ罠を隔離すると選択が消える。参加者が自分の判断で汚染教材を NotebookLM に入れるのは自由。
> 禁じているのは運営側が最初から混ぜて配ること（[../scenario/04_Stage3_嘘.md](../scenario/04_Stage3_嘘.md) §配布教材）。

## 形式

- タブ区切り、UTF-8、ヘッダ行なし。
- 列は7つ固定: `患者ID` / `氏名` / `病棟` / `採取日` / `MRSA結果` / `発熱` / `備考`。
- **汚れは意図的**（日付5種混在・全角半角混在・結合セル由来の空欄・表記ゆれ・欠損）。
  整形して保存しない。整形されたらこの教材は死ぬ。
- 患者行に混じって**ノイズ行**が入っている（注釈行・タイトル行・空行）。
  これは1列目だけに値があり、残りが空。**参加者が削除すべき行**であり、
  判定項目「行数が元データと一致」はこの削除操作を見ている。

## 行数

| | ノイズ行 | 患者行 | 計 |
|---|---|---|---|
| `stage2_linelist.tsv` | 3 | 20 | **23** |
| `+ addendum` | 0 | 10 | **33** |

提出時の期待行数は **20**（追加分が着弾したら **30**。着弾後は取り込まない限り提出は通らない）。

## 伏線の置き場所（重要）

MRSA 陰性なのに発熱ありの3名（`005` / `6` / `008`）が Stage 3 で回収される
（[../scenario/00_未知ウイルスの通奏低音.md](../scenario/00_未知ウイルスの通奏低音.md) §3）。
この3名は **`stage2_linelist.tsv` にのみ置く**。**同一人物として Prologue メール3の「発熱の患者さんが数名」とも繋がる**
（同上 §3・[00_共通シェルと通奏低音.md](../ui/00_共通シェルと通奏低音.md) §4）。

> 📌 **`addendum` には伏線を1名も入れない。** 追加分は締切を落としたチームにだけ届く。
> ここに種を入れると、**遅れたチームだけが多くの伏線を持つ**ことになり、
> Stage 3 の回収が全チームに等しく刺さらなくなる。追加分は純粋に汚いだけのデータにする。

## Stage 3 の教材

- `stage3_manual.md`（正典）・`stage3_contaminated.md`（汚染教材）は**Markdown が正典で PDF は派生物**
  （TSV/xlsx と同じ原則をここでも踏襲。§原則 参照）。NotebookLM や添付ビューアに渡すのは生成した PDF。
- **罰ゲームに教材ファイルは要らない。** 罠発火時の拡大対応業務は「消毒液ボトルの補充」で、
  データではなく本数だけを扱う（定数は `S3_BOTTLES_5A` / `S3_BOTTLES_5B`）。
  かつて使っていた `stage3_contacts.tsv`（接触者リスト）は、罰の内容を差し替えた際に**削除した**——
  Stage 2 のグリッド整形の焼き直しで退屈だったため（[../ui/04_Stage3.md](../ui/04_Stage3.md) §罰ゲーム）。
