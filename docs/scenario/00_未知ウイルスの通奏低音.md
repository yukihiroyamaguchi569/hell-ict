# 通奏低音：未知ウイルス（縦軸設計）

**地獄のICT シナリオ設計 / 全ステージを貫く背骨**
親企画書: [../企画書.md](../企画書.md)

---

## 0. これは何か

**MRSA（Stage 2）と疥癬（Stage 3）は、既知で対処できる別々の火事**。
対して**原因不明の発熱は全編を貫く縦軸**であり、各部署が目の前の火事に追われる間にも静かに残る。

このファイルは、未知ウイルスを「Prologueの片隅の発熱数名」から「Finalの記者会見の主役」まで、
**どのステージで・どれだけ・どんな文言で露出させるか**を一元管理する台帳。
各ステージのシナリオを書くときは、必ずここの「クレッシェンド表」と整合を取る。

---

## 1. 確定設定と、あえて保留する設定

神は細部に宿るが、**未知ウイルスの臨床像を早く固めすぎると、後段の自由度が死ぬ**。
現場も最初は「発熱の集団」しか分からない——この不確実性こそ教材価値なので、**意図的に保留する**。

| 項目 | 状態 | 内容 |
|---|---|---|
| 主症状 | **確定** | **発熱**（38℃台〜。Prologueの「数名の発熱」から一本の線で繋がる） |
| 感染経路 | **保留** | 飛沫/接触/エアロゾル/体液——**最後まで割らない**。だからこそ「解除基準が決まらない」 |
| 病原体の正体 | **保留** | ウイルスか否かすら確定させない。既知検査は全て陰性、とだけ決める |
| 潜伏期・致死率 | **保留** | 記者会見で「まだ分かっていません」と言わせるための余白 |
| 追加症状 | **段階開示** | 必要になったステージで小出しに足す（呼吸苦・下痢等）。**先に決めない** |

> **原則: 「発熱」以外は、そのステージのシナリオを書く瞬間に、必要な分だけ足す。**
> 保留リストに手を入れたら、必ずこのファイルに追記して全ステージ間の齟齬を防ぐ。

### 「既知検査は全て陰性」だけは早期に固定する理由

Finalで「分かっていないことを分かっていないと書けるか」を問うためである。Stage 3の罠は、
未知の病原体ではなく**既知の疥癬対応でも、AIがもっともらしく過剰に答える**ことを学ばせる。

## 2. 命名の物語的処理（ブラックユーモア）

正体不明のものに正式名はつかない。**命名がグダグダに転がる様子そのものを笑いにする。**

- **Stage 3まで**: 電子カルテ（2003年製）の病名選択肢に該当なし。現場は **「例の発熱」「例のアレ」** と呼ぶ。
- **Final直前**: 記者会見のために名前が要る、と事務が慌てる。
  院長の一存で仮称 **「聖クロノス熱（仮）」** が爆誕。**誰も学名を知らないまま会見に臨む。**
- Debriefで回収: 「最後まで、これが何なのか誰も分かりませんでした。**でもAIは毎回、堂々と答えましたね。**」

> 命名を最後まで宙吊りにすることが、テーマ「分からないことを分からないと言えるか」の演出装置。

## 3. クレッシェンド表（各ステージでの露出設計）

発熱ノイズを **「気配 → 無視できない → 爆発 → 世間の注目」** と単調増加させる。
各ステージのシナリオ執筆時は、この「露出文言」を実際の画面テキスト/メールに埋め込む。

| ステージ | 露出量 | プレイヤーの認識 | 仕込む具体（文言・オブジェクト） |
|---|---|---|---|
| **Prologue** | ● 種 | 気に留めない | 申し送りメール末尾に一文: 「なお発熱の患者さんが数名出ていますが、インフル・コロナ検査は陰性でした」 |
| **Stage 1 平常運転** | ● 種 | 事務処理に追われて読み飛ばす | 8通目・検査科メールの3行目に「**なお、今月は培養提出が少し増えております**」。返信すべき用件は別のこと（報告書の送付方法）にしておく |
| **Stage 2 火の手** | ●● 気配 | MRSAに夢中で忘れる | 整形対象のラインリストに、**MRSA陰性なのに発熱ありの患者**を3名混ぜる（患者ID `005` / `6` / `008`）。解錠時にヘッダーの `発熱` が 3→5 へ静かに動く（増分の2名はこの3名とは別・[00_共通シェルと通奏低音.md](../ui/00_共通シェルと通奏低音.md) §4） |
| **Stage 3 嘘** 💀 | ● 背景 | 別件の火事に追われる | 平尾台医療センターからの転院患者3名（通常疥癬・治療完了済み）への過剰対応の罠が主課題。**疥癬は発熱を来さない**ため、原因不明の発熱の縦軸とは症状面で交わらない——検査科メールが既知検査すべて陰性であることを確定通知し、伏線3名（`005`/`6`/`008`）を患者IDで名指しして触れるだけで、疥癬とは無関係のまま背景に残す。詳細は [04_Stage3_嘘.md](04_Stage3_嘘.md) |
| **Stage 3.5 新情報の解釈** | ●●● 先回り | 発熱前の兆候を初めて知る | 隣国の速報論文をAIで要約する。発熱の8〜18時間前の眼痛・羞明という観察結果を拾い、夜勤者への確認を幹部に提案する。病原体・感染経路・当院との関連は未確定のまま、眼痛を訴える応援看護師の複数病棟配置を見合わせ、接点を減らす。詳細は [04_Stage3_5_新情報の解釈.md](04_Stage3_5_新情報の解釈.md) |
| **Stage 4 情報漏洩** 💀 | ●●●● 爆発 | 「あの発熱患者の件だ」 | 患者005の家族から問い合わせ→PII罠。Prologue・Stage 2の発熱の種をここで個人情報の扱いとともに回収する |
| **Stage 5 ポスター** | ●●● 継続 | 面会制限の理由 | 面会制限ポスターの掲示理由が未知ウイルス。**正体不明のまま「念のため」で制限**する皮肉 |
| **Final 記者会見** | ●●●●● 頂点 | 世間の注目の的 | 「聖クロノス熱（仮）」として4読み手に書き分け。**分かっていないことを、どう誠実に書くか**。インジケータの値は Stage 3 解錠時の14で据え置く——会見の論点そのものになる数字を動かさない（[00_共通シェルと通奏低音.md](../ui/00_共通シェルと通奏低音.md) §4「Final：継続」） |

### 決定：Prologue の3名 ＝ Stage 2 の3名（同一人物）

`docs/ui/00_共通シェルと通奏低音.md` §4 が「本ファイル単独で決めない」としていた保留事項。**同一人物として扱う。**

- Prologue の夜勤師長メールが指す「発熱の患者さんが数名」＝ Stage 2 の配布ラインリストに紛れ込ませた
  患者ID `005` / `6` / `008`（MRSA陰性なのに発熱あり）。
- 参加者は Prologue とStage 2 で**同じ3人を2回見逃す**。この伏線はStage 4で患者005の家族からの問い合わせとして
  初めて前面化し、Prologue のメールまで一気に繋がる。
- Stage 2 解錠時のインジケータ増分（3 → 5）は**この3名とは別の新規2名**による。伏線の3名は
  Prologue の時点で既に数えられており、Stage 4で再浮上するまで値としては動かない。

## 4. Stage 3の核心：AIの過剰対応に「正典の正しい対応」を対置する

疥癬という既知の感染症でも、**AIの答えをそのまま採用してよい理由にはならない**。
Stage 3のゴールは、AIのもっともらしい過剰対応に対して正典に書かれた確たる正しい対応を
突き合わせて正すこと。復旧したチームの手元には、最終的に**"正しい情報"が残る**——ここがStage 3の着地。
正典を自分で読んで照合することが「過剰対応の解毒剤」として機能する、という企画書の思想はここで完成する。

### 「知っているつもり」を正典で検証する

| 問い | 性質 | 正典の正しい答え |
|---|---|---|
| リネン・寝具はどう扱うか | **通常の洗濯でよい**。殺虫剤は不要 |
| PPE・隔離はどこまで | 標準予防策（通常のケアに準じる）。個室隔離は不要 |
| 接触予防策をいつ解除するか | 治療完了・最終治療から**24時間**経過をもって標準予防策のみに戻す |

### AIの過剰対応 vs 正典（非対称）
| | AI（素のGPT-4o） | 正典（院内マニュアル＝アプリ内ビューアで照会） |
|---|---|---|
| 態度 | 「分からない」と言えず、**病型を確認せず、最も厳重な対策を断定的に返す** | 病型（通常疥癬か角化型か）と治療の進捗を確認したうえで対応を選ぶよう明記する |
| 環境・リネン | 「殺虫剤処理または50℃以上の熱処理」＋病室への殺虫剤散布（**角化型向けの過剰対応**） | **通常の洗濯でよい。殺虫剤は不要**（正しい確定値） |
| 解除 | 「治療後も当面（2週間程度）接触予防策を継続」（**過剰に慎重な判断**） | **治療完了後24時間で標準予防策のみに戻す** |

> 罠の怖さは**「もっともらしい過剰対応」**であること。焦ったチームは、
> **より厳重＝安全側の判断**だと思い込み、過剰対応にそのまま飛びつく。速さの誘惑と検証の緊張が
> ここで最大化する。
>
> 個々の対応（個室隔離・予防衣・殺虫剤処理・熱処理）は単体では医学的な誤りではない——
> **角化型（痂皮型）疥癬に対してなら概ね正しい。** 「病型を確認しないまま最も厳重な対策を
> 一律適用していること」こそが誤りの本体であり、「楽な方が罠」という当たりの付け方を封じる
> （[04_Stage3_嘘.md](04_Stage3_嘘.md) §罠）。

### 正典マニュアルPDFの構成（正しい情報を"用意する"）
配布する院内感染対策マニュアルPDF（正典）に、上記の正しい対応を**確たる形で明記**する:
- 「**第5章 疥癬（かいせん）への対応**」に、病型ごとの違い（通常疥癬／角化型疥癬）とそれぞれの対応を**具体的に**記載。
- 解除基準は「通常疥癬は、治療完了後24時間が経過した時点で標準予防策のみに戻す」と明記する。
- AIは病型を確認せず、もっともらしい早見表を整える。正典に戻って検証することが、この対比の核である。

### 自動判定（正しい要素で解錠する）
- **クリア（OK）**: 提出に正典由来の必須要素を規定数含む——
  「標準予防策 ＋ 個室不要」「通常の洗濯 ＋ 殺虫剤不要」「治療完了 ＋ 24時間」。
- **罠発火（NG）**: 個室隔離・予防衣常時着用（「不要」「標準予防策」を伴わない）、殺虫剤処理・熱処理
  （「不要」を伴わない）、治療後も当面（2週間程度）接触予防策を継続（「24時間」を伴わない）、
  教材が用意した捏造出典名の文字列 → 罠発火。
- どちらも正規表現/キーワードマッチで判定可能。**モデル性能に依存しない**（企画書§7の思想を踏襲）。
- **罠の検出はすべて「罠語があり、かつ正解語が無い」形にする。** 正典を読んだ上で「角化型ではないので
  個室隔離・予防衣は不要」「通常疥癬なので標準予防策のみで対応する」と**正しく否定して書いた提出を
  誤爆させない**ため——否定形は罠ではなく理解の証拠（罠語だけを見ると、正しく書いたチームほど
  引っかかる逆転が起きる）。
- **書き漏らしは罠にしない。** 書けていなくても「過剰対応を書いた」ではないので差し戻し（無罰）に
  留める（[04_Stage3_嘘.md](04_Stage3_嘘.md) §判定と罰ゲーム）。

> つまり復旧ルートは「正典を読み、AIのもっともらしい過剰対応を、確たる正しい対応で上書きする」。
> **最終的に、チームの手元には"正しい情報"が残る。** 既知の感染症であっても、
> AIの回答を正典で検証する必要があることを教える。

## 5. 正体を割らない方針とDebriefでの回収

- **ゲーム中、未知ウイルスの正体は最後まで明かさない。**（保留設定を守る＝自由度と緊張感の両立）
- Debriefでの種明かしは、病原体の正体ではなく**「AIの態度」**に向ける:
  - 全チームのAIログを見せ、「疥癬対応について、AIは病型を確かめずに答えを整えていませんでしたか？」と問う。
  - 「皆さんは Stage 3 で、AIのもっともらしい答えを検証せずに採用しかけた。現場でこれをやると院内感染が広がる。」
  - 「一方で、**正典（院内マニュアル）にはちゃんと正しい対応が書いてあった。**ちゃんと読めば正せた。嘘には解毒剤がある——共有フォルダの中に、最初から。」
  - **本当の学び**: 光のステージ（1・2）でAIを万能と錯覚した直後、既知の感染症でさえ検証を省けば誤ると体験させる。

## 6. このファイルの使い方（執筆ルール）

1. 各ステージのシナリオを書く前に、必ず本ファイルの**クレッシェンド表**の当該行を確認する。
2. 未知ウイルスの**保留設定**に手を入れたら（追加症状の開示など）、必ず§1の表に追記する。
3. Stage 3を書くときは§4の判定設計を実装仕様に落とす。
4. 矛盾を見つけたら、個別ステージではなく**本ファイルを正**として直す。
