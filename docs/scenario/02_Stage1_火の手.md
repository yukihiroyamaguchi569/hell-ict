## §0. 事務長ブリーフィング（Stage 1 の冒頭・全画面）

3通を読み終えた参加者を迎えるのは、事務長からの一方向の通達。
**参加者は前任ICNの急な退職に伴う派遣ICT**（企画書§1）——
この経緯があるからこそ、以下の台詞が成立する。着任初日の新人には言えない。

> ⚠️ **この時点でアウトブレイクは起きていない。** 急変（赤帯・MRSA疑い）が来るのは
> Stage 1 を終えたあと。事務長は 5A について何も知らないし、言及もしない。

```text
病院執行部　事務長

——ああ、派遣の皆さん。本日からでしたね。ご足労さまです。
さっそくですが、まずはメール処理をお願いします。
現場から問い合わせが山ほど来ていますので。感染対策は、その後で結構です。

あ、ひとつだけ。うちのメールは、返信しないと消えます。
他の職員は5分ですが——優秀な皆さんなら、1分もあれば十分でしょう？

では、よろしくお願いします。

┌ 院内メールシステムのご利用について（総務課） ──────────┐
│ ・受信から60秒を経過したメールは自動的に削除されます。      │
│ ・削除されたメールへの返信はできません。                    │
│ ・督促および再送は行いません。                              │
│ ※上記は外部支援スタッフ向けの設定値です。                   │
└────────────────────────────────────┘

                                          [ 了解しました ]
```

**設計意図**:

- **理由はバグではなく制度。** 1分ルールが電子カルテと同じ老朽システムの不具合なら、
  誰のせいでもない。「他の職員は5分」という**差別的な基準**にすることで、
  怒りの矛先が明確な「組織と状況」に向く（CLAUDE.mdトーンルール）。
- **事務長は悪人ではない。** 丁寧で、悪気がなく、これを心底褒め言葉だと思っている。
  笑いどころは「感染対策は、その後で結構です」と**平時に**言い切れてしまう優先順位の壊れ方で
  あって、事務長個人の性格の悪さではない。
- **何も起きていないことが効く。** アウトブレイクの最中なら「非常時だから仕方ない」と
  情状酌量の余地が生まれ、理不尽が薄まる。**何も起きていないのに ICT の本業が後回しにされる**
  から、これが**この病院の平常運転**だと分かる。急変を Stage 1 の後ろへ回したのはこのため。
- **[了解しました] を押した瞬間から Stage 1 の締切カウントが始まる。** 読んでいる時間は
  参加者の持ち時間を削らない（実装は `s1Init()` の呼び出しをブリーフィング終了時まで遅延）。
  同時に**レースも始まる**——押した本人は「了解」しただけのつもりでいる。
- **「5分ルール」は Stage 1 の1回目失敗後、苅部さんが実在すると認める。**
  推測ではなく彼が知っている院内制度の歴史として（[苅部さん.md](../character/苅部さん.md) §5）。
- 通達文は台詞ではなく2003年書式の院内文書として提示する。`docs/ui/02_Stage1.md` の
  「チュートリアルを置かない」方針との整合は同ファイル §0 参照。

## §∞. Stage 1 を終えたあとの急変（Stage 2 への継ぎ目）

**メールを片付け終えた、その1.1秒後に発火する。**

- BGMが**プツッと切れる**。器が `peace` → `alert` へ落ちる（アイボリー → チャコール）。
- 全画面に赤い帯: **「5A病棟より緊急連絡。MRSA疑い、拡大の可能性。」**
- 赤帯は3秒で引き上げ、さらに一拍おいて Stage 2 へ。参加者の操作は不要。

**設計意図**:

- **「終わった」と思った瞬間に落とす。** 1分刻みのメールを捌き切り、息をついたところへ来る。
  ここまで画面はずっと明るかったので、落差は Prologue から通算して最大になる。
- **MRSA の名が出るのはここが初めて。** 直後の Stage 2 冒頭で師長の
  「至急！！MRSAのやつまとめて」がそれを受ける。赤帯は Stage 2 の**予告ではなく前振り**。
- **遡って意味が変わる。** さっきまでやっていた在庫・研修・面会制限のメール処理が、
  「これが始まる直前に、我々は何をやらされていたのか」に化ける。事務長の
  「感染対策は、その後で結構です」が、ここで二度目の刃になる。
- **レースはここでは始まらない。** 経過時間もリーダーボードも Stage 1 の冒頭から動いている。
  この転調で変わるのは**器の色だけ**（UI詳細は [../ui/01_Prologue.md](../ui/01_Prologue.md)
  「急変（Stage 1 を終えたあと）」）。

## 配布教材：汚いExcel の仕様

**ファイル名からして地獄**（`最新版(2)_コピー` ＝どれが本物か分からない）。中身に以下の"汚れ"を全部盛る。

| 汚れの種類 | 具体 |
|---|---|
| 日付形式の混在 | `7/3` `7月3日` `R8.7.3` `2026/07/03` `7.3` `さんにち`（手書き転記ミス設定） |
| 全角・半角の混在 | `ＩＤ００１` と `id-2`、全角スペース、全角数字 |
| 結合セル | 病棟名 `5A病棟` が縦方向に結合され、途中から空欄 |
| 表記ゆれ（結果） | `陽性` `(+)` `ポジ` `＋` ／ `陰性` `(-)` `ネガ` `－` |
| 氏名の揺れ | 姓名間が全角スペース/半角/詰め、ミドルの表記ゆれ |
| 余計な行 | 先頭に「※このファイルは師長が個人的に作成」等の注釈行、途中に空行 |
| 欠損 | 採取日や結果の空欄がぽつぽつ |

### サンプル行（教材の実物イメージ・抜粋）

```
※このファイルは5A病棟師長が個人的につけている記録です。正式なものではありません。
5A病棟の状況　7月分

患者ＩＤ	なまえ	びょうとう	採取日	MRSA	発熱	メモ
００１	佐藤　一郎	5A病棟	7/3	陽性	あり	個室へ
id-2	鈴木  花子		7月3日	(+)	38.2℃	
no.3	高橋健	（結合）	R8.7.3	ポジ	なし	
４番	田中　みゆき		さんにち	＋	あり	家族面会あり
005	渡辺 三郎	5A	7.3	陰性	37.9℃	★MRSAは陰性だが熱が続く
6	いとう		2026/07/04	－	あり	★これも陰性なのに発熱
007	山本　和子	5A病棟	7/4	陰性	なし	
008	中村太郎		７月４日	ネガ	38.5℃	★陰性・発熱
（空行）
009	小林　愛	5A	7/5	陽性	あり	接触者調査中
…（以下、全20行程度）
```

> 📌 **仕込み（縦軸§3「Stage 1＝種」）**: `005` `6` `008` の3名は **MRSA陰性なのに発熱あり**。
> メモ欄の `★` は**教材設計用の目印で、配布版では消す**（プレイヤーには気づかせない）。
> MRSAに集中しているチームは、この3名を「陰性だから関係ない」と流す。だが整形後のデータには発熱記録として残り、
> **Stage 3で「あの発熱患者たち＝未知ウイルスの初期クラスタだった」と回収される。**

## 課題と提出物

**課題**: バラバラのExcelを、感染対策会議で使える**統一ラインリスト**に整形し、疫学曲線の材料を提出せよ。

**提出物**: 下記の列を持つ整形済みテーブル（アプリの提出フォームに貼付 or CSV）。

| 列名 | 正規化ルール |
|---|---|
| `患者ID` | 半角英数の連番（`001` 形式）に統一 |
| `氏名` | 姓名の間を半角スペース1つに統一、全角→半角の混在解消 |
| `病棟` | 結合セル・略記を `5A` に統一（全行に補完） |
| `採取日` | **ISO形式 `YYYY-MM-DD` に統一**（`さんにち`＝要文脈補完 or 要確認フラグ） |
| `MRSA結果` | `陽性` / `陰性` の2値に正規化 |
| `発熱` | `あり` / `なし` に正規化（体温表記は「あり」に寄せる or 体温列を分離） |
| `備考` | そのまま（メモは残す） |

## 判定設計（ルールベース・罠なし）

品質採点はせず、**構造の正しさだけ**を機械判定する（詰まらせないため閾値は甘め）。

- ✅ **必須列がすべて存在**（患者ID・氏名・病棟・採取日・MRSA結果・発熱）。
- ✅ **採取日が ISO `\d{4}-\d{2}-\d{2}` に統一**（許容: 1件だけ「要確認」フラグ可＝`さんにち`対応）。
- ✅ **MRSA結果が {陽性, 陰性} の2値のみ**（`(+)` `ポジ` 等が残っていたらNG）。
- ✅ **行数が元データと一致**（空行・注釈行は除外、患者行の欠落/重複なし）。
- 上記を満たせば解錠 → Stage 2 へ。**発熱列の中身の正誤は問わない**（伏線をデータに温存するため、存在だけ必須）。
