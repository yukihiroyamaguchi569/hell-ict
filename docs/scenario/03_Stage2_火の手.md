## 狙い

**AIの本当の破壊力を見せるステージ。ここに罠はない。**

- 手作業なら約25分の分量を、アプリ内GPT-4oに貼れば3分で片付く——この落差を体で覚えさせる。
  Stage 1 で配られたAIは「下書きボタン」だったが、ここでは**自分で要件を言語化して使う**。
  **手作業ルートは実在させる**——アプリ内の編集可能グリッドで、実際にセルを1つずつ直せる（§手作業の場）。
  直せるからこそ、直しきれないことが分かる。
- 未知ウイルスの**第二の種**を、整形対象のデータに紛れ込ませる（後でStage 3が回収する伏線）。
  第一の種は Prologue のメール3、第一.五は Stage 1 の検査科メール。
- レースの差が開き始める。Stage 1 は全チームがほぼ同時に終わるが、ここから離れていく。

> 設計上の絶対条件: **ここで詰まらせない。** 成功体験を確実に配ることが、Stage 3で罠を刺すための布石。

## 配布教材：汚いExcel の仕様

**ファイル名からして地獄**（`最新版(2)_コピー` ＝どれが本物か分からない）。中身に以下の"汚れ"を全部盛る。

| 汚れの種類 | 具体 |
|---|---|
| 日付形式の混在 | `7/3` `7月3日` `R8.7.3` `2026/07/03` `7.3` `さんにち`（手書き転記ミス設定） |
| 全角・半角の混在 | `ＩＤ００１` と `id-2`、全角スペース、全角数字 |
| 結合セル | 病棟名 `5A病棟` が縦方向に結合され、途中から空欄 |
| 表記ゆれ（結果） | `陽性` `(+)` `ポジ` `＋` ／ `陰性` `(-)` `ネガ` `－` |
| 氏名の揺れ | 姓名間が全角スペース/半角/詰め、ミドルの表記ゆれ |
| 余計な行 | 先頭に「※このファイルは師長が個人的に作成」等の注釈行、途中に空行 |
| 欠損 | 採取日や結果の空欄がぽつぽつ |

### 教材の実体（正典）

**正典は TSV。`.xlsx` はそこから生成する派生物。**
Stage 2 の手作業はアプリ内グリッドで行うので、アプリが読むのは表データそのものであって
Excel ファイルではない（[../materials/README.md](../materials/README.md)）。

| ファイル | 中身 |
|---|---|
| [`../materials/stage2_linelist.tsv`](../materials/stage2_linelist.tsv) | **配布版**。ノイズ行3 ＋ 患者行20 ＝ **23行** |
| [`../materials/stage2_linelist_addendum.tsv`](../materials/stage2_linelist_addendum.tsv) | **追加分**。患者行10（締切超過で着弾） |
| [`../materials/stage2_linelist.annotated.tsv`](../materials/stage2_linelist.annotated.tsv) | **設計用**。伏線3名に `★` 付き。**配布しない・アプリに読ませない** |

冒頭はこう始まる（配布版の実物）:

```
※このファイルは5A病棟師長が個人的につけている記録です。正式なものではありません。
5A病棟の状況　7月分
００１	佐藤　一郎	5A病棟	7/3	陽性	あり	個室へ
id-2	鈴木  花子		7月3日	(+)	38.2℃
no.3	高橋健		R8.7.3	ポジ	なし
４番	田中　みゆき		さんにち	＋	あり	家族面会あり
005	渡辺 三郎	5A	7.3	陰性	37.9℃
…
```

**ノイズ行3つ**（注釈行・タイトル行・途中の空行）は1列目にしか値がなく、
**参加者が削除すべき行**。判定項目「行数が元データと一致」はこの削除操作を見ている。
元ファイルのヘッダ行（`患者ＩＤ / なまえ / びょうとう / …`）はグリッドの列見出しに吸収されるので、
データ行としては現れない。

> 📌 **仕込み（縦軸§3「Stage 2＝種」）**: `005` `6` `008` の3名は **MRSA陰性なのに発熱あり**。
> `annotated` 版ではメモ欄に `★` が付いているが、**配布版ではメモごと消してある**（プレイヤーには気づかせない）。
> MRSAに集中しているチームは、この3名を「陰性だから関係ない」と流す。だが整形後のデータには発熱記録として残り、
> **Stage 3で「あの発熱患者たち＝未知ウイルスの初期クラスタだった」と回収される。**
>
> ⚠️ **追加分（addendum）には伏線を1名も入れない。** 追加分は締切を落としたチームにしか届かない。
> ここに種を入れると**遅れたチームだけが多くの伏線を持つ**ことになり、Stage 3 の回収が
> 全チームに等しく刺さらなくなる。追加分は純粋に汚いだけのデータにする。

## 手作業の場：アプリ内グリッド

**参加者の端末は Chromebook。だが「表計算ができない」から手作業が成立しないのではない。**
Google スプレッドシートは使える（NotebookLM 用に Google アカウントは全チーム必須）。
それでも**外部の表計算ソフトには誘導しない**——理由は3つ。

1. 手作業の所要時間をログできない。企画書§8 の「手作業25分」の実測が成立しなくなる。
2. タブが3枚になる（アプリ／NotebookLM／スプレッドシート）。1台を3〜4人で囲む前提で破綻する。
3. `.xlsx` を開いて取り込む操作自体に数分溶ける。それは**「手作業の地獄」ではなく「ファイル操作の地獄」**であり、
   このステージが体験させたいものではない。

代わりに、**中央ペインの提出フォームそのものを編集可能なグリッドにする**。
汚い生データ23行が最初から入っていて、参加者はセルを1つずつ直し、余計な行を `✕` で消せる。
AIに投げたチームは、返ってきた表を**同じグリッドに貼り付けて一括上書き**する——
手作業ルートとAIルートが同じ場所に合流するので、提出物の形と判定経路は1本のまま。

UI仕様は [../ui/03_Stage2.md](../ui/03_Stage2.md) §2 が正典。

> 📌 **グリッドは空ではなく汚いデータ入りで始まる。** 空から打ち込ませると手作業が「直す」ではなく
> 「書き写す」になり、日付5種・全角半角・結合セル由来の空欄を**一つずつ潰す**という体験にならない。
> 潰す作業だからこそ「これ全部やるのか」が来る。

## 締切と追加データ着弾

師長メールの「7時の申し送りまで」を、**ステージ内の可視カウントダウン**にする（`S2_DEADLINE = 5分`）。

**Stage 1 の締切とは性質が違う。** Stage 1 は超過＝返信不可（機会が消える）だったが、
ここでは**超過しても提出は一切止まらない**。企画書§5 の絶対条件「Stage 2 では詰まらせない」を破らないため。

### 超過したときに起きること

師長からメールが1通、添付が1つ増える。

> 件名: すみません追加で
> 本文: あ、ごめんなさい。副師長が別につけてた分が出てきました。これも一緒にお願いします。
> 📎 添付: `5A病棟_MRSA_記録_最新版(2)_コピー_追加分.xlsx`

- 中身は患者10行、汚れは同じ全部盛り。**伏線は入っていない**（前述）。
- **自動でグリッドに追記しない。** 添付ビューアの [作業エリアに追加] を押して初めて末尾に足される。
  手作業中のセルが勝手に動くと事故になる。
- 提出に必要な行数が 20 → 30 になる。**手作業組は積み上がった分をやり直す羽目になり、
  AIに投げたチームは同じ3分で片付ける。** これがこのステージで一番はっきり出る落差。

### なぜこれが「罰」として正しいか

| 原則（企画書§6） | この設計での現れ方 |
|---|---|
| 通貨は時間 | 減点も星も無い。増えるのは作業量＝時間だけ |
| 罰も業務 | 「追加分が出てきた」は病院で実際に起きること。世界観を壊さない |
| 上限を設ける | **第2波は無い。** 着弾は1回だけ |
| 詰みを防ぐ | 提出はロックされない。AIを使えば追加分込みでも3分で終わる |

- **罠ではないので、暗転・警報・赤を使わない。** 器は `alert` のまま、メール1通と未読バッジだけ。
  ここで演出を盛ると Stage 3 の罠と見分けがつかなくなる。
- 5分で終わらないチームは、既存の滞留トリガー（6分の苅部さん）が続けて拾う。順序は 5分（追加着弾）→ 6分（苅部さん）。

## 課題と提出物

**課題**: バラバラのExcelを、感染対策会議で使える**統一ラインリスト**に整形し、疫学曲線の材料を提出せよ。

**提出物**: 下記7列に整形されたグリッドの中身。列はグリッド側で固定されているので、
参加者が作るのは**中身だけ**——手でセルを直しても、AIの出力を貼り付けて上書きしても、提出物は同じ形になる。

| 列名 | 正規化ルール |
|---|---|
| `患者ID` | 半角英数の連番（`001` 形式）に統一 |
| `氏名` | 姓名の間を半角スペース1つに統一、全角→半角の混在解消 |
| `病棟` | 結合セル・略記を `5A` に統一（全行に補完） |
| `採取日` | **ISO形式 `YYYY-MM-DD` に統一**（`さんにち`＝要文脈補完 or 要確認フラグ） |
| `MRSA結果` | `陽性` / `陰性` の2値に正規化 |
| `発熱` | `あり` / `なし` に正規化（体温表記は「あり」に寄せる or 体温列を分離） |
| `備考` | そのまま（メモは残す） |

## 判定設計（ルールベース・罠なし）

品質採点はせず、**構造の正しさだけ**を機械判定する（詰まらせないため閾値は甘め）。
グリッドのセル値を直接読むので、判定はどれも数行で書ける。

- ✅ **必須列がすべて埋まっている**（患者ID・氏名・病棟・採取日・MRSA結果・発熱に空セルが無い。備考は空でよい）。
  列そのものはグリッドで固定されているので存在は常に真——**この項目が見ているのは「値が入っているか」**。
- ✅ **採取日が ISO `\d{4}-\d{2}-\d{2}` に統一**（許容: 1件だけ「要確認」フラグ可＝`さんにち`対応）。
- ✅ **MRSA結果が {陽性, 陰性} の2値のみ**（`(+)` `ポジ` 等が残っていたらNG）。
- ✅ **行数が期待値と一致**——**期待値は動的**。追加分を取り込んでいなければ **20**、取り込んでいれば **30**
  （ノイズ行3つは削除済みであること、患者行の欠落/重複なし）。
- 上記を満たせば解錠 → Stage 3 へ。**発熱列の中身の正誤は問わない**（伏線をデータに温存するため、存在だけ必須）。

> 📌 **NG は行番号ではなくセルで指す。** グリッドなら「3行目に『ポジ』が残っています」と言う代わりに
> **そのセル自体を橙で光らせられる**。UI設計側の絶対条件「NGを失敗に見せない」がこれで効く
> （[../ui/03_Stage2.md](../ui/03_Stage2.md) §3）。再提出は回数無制限・ペナルティなし。

## 実装メモ

- 教材の正典は [`../materials/`](../materials/) の TSV。`.xlsx` はそこから生成し、
  添付ビューアの [DL]（NotebookLM やスプレッドシートに持っていきたいチーム向け）にだけ使う。**二重管理しない。**
- **`annotated` 版をアプリに読ませない。** 配布版のパスをホワイトリストで指定し、混ざりようのない形にする。
  取り違えると Stage 3 の伏線が Stage 2 で丸見えになる。
- 「手作業25分／AI3分」はP0で**必ず実測**（企画書§8）。**グリッド前提・1台3〜4人で測る。**
  この実測で `S2_DEADLINE`（5分）と追加分の行数（10行）を確定させる。今の数字は仮置き。
- 定数は `S2_DEADLINE`（締切5分）/ `S2_ROWS`（期待行数20）/ `S2_ROWS_ADD`（追加後30）。
- 伏線3名（005/6/008）の存在は縦軸§1「既知検査は全て陰性」設定と接続。Stage 3執筆時にこの患者IDを引用して回収する。
- NG提出のログは**どのセルで落ちたか**まで残す。P0の難易度調整に直結する。
