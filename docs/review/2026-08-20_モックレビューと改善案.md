# 「地獄のICT」は、ステージ追加より因果の回収とFinalの強化でさらに面白くなる

作成日: 2026-08-20

対象: 企画書、シナリオ、UI設計、`docs/ui/mock/index.html`

## このメモの目的

現在のモックと設計文書を確認し、企画の良さを残したまま体験をさらに面白くする案を整理する。

現時点で最も効果が大きいと考えるのは、ステージを増やすことではない。参加者の過去の行動を後半で回収すること、成果によって病院の様子が変わること、Finalを実際の記者会見として盛り上げることの3点である。

このメモは改善案の提示までを対象とし、実装方法や工数の確定は扱わない。

## 現在の企画は、感情の流れと伏線の回収が強い

企画の芯はかなり強い。特に「AIなしの苦痛 → AIの快感 → AIの嘘 → 情報漏洩 → 創作 → 総合戦」という感情の流れが明快で、ステージごとにメール処理、表の整形、出典確認、匿名化、画像生成、文書作成と操作も変わる。学習項目を順番に消化しているだけには見えない。

患者005、画面上部の発熱人数、情シスの苅部さんが複数のステージをまたいで登場するため、個々の課題が同じ病院で起きている出来事としてつながっている。罰ゲームにも意味がある。Stage 3全体を縮小して再演する「消毒液の継ぎ足し」や、Stage 4の学びを手作業で確認する「黒塗り」が用意されている。

この土台があるため、新しい課題をさらに足すより、すでに置かれている因果関係を強く見せるほうが効果は大きい。

## 最も強く推したい案

### Finalを資料提出で終わらせず、短い模擬記者会見まで行う

現行のFinalは、院長向け想定問答、ご家族向け説明文、職員向け通知、報道機関向けリリースの4欄を埋める構成になっている。学習上は妥当だが、画面体験としてはStage 3の暗転やStage 4の警報より静かで、最終局面としての高揚感が弱い。

4資料の提出後、記者から3問だけ質問が飛んでくる構成を提案する。

- 「院内感染は終息したと言えるのですか」
- 「患者名を公表しない理由は何ですか」
- 「AIで作った資料を信用してよいのですか」

回答時間は各20秒程度とし、新しい知識は問わない。作成済みの資料と、それまでに確認した事実から回答させる。最後の質問を切り抜けた瞬間にゴール演出を出せば、「会見を乗り切って生還した」という実感のある終わり方になる。

### 過去の提出物をFinalで証拠として突きつける

Stage 4で作成した家族向け返信や、Stage 3で最初に提出した誤った基準をFinalの記者が引用する。

> 先ほどご家族には「安全を確認している」と回答していますが、何を確認したのですか。

この仕掛けが入ると、Finalでは自分たちが積み重ねた判断に答えることになる。罠を踏んだか、どのような書き方をしたかによって質問が変わるため、各チームに固有の物語も生まれる。

AIログと提出物をDebriefで再生する構想はすでにある。このログをゲーム中にも一度だけ使う案であり、企画との相性が良い。

### 病院を「生きた盤面」にする

現在は画面上部の発熱人数が主な変化だが、各ステージの成果を院内図や背景へ反映すると達成感が増す。

- Stage 2では、整形したデータから流行曲線が立ち上がる。
- Stage 3.5では、応援看護師が病棟間を移動する予定線が消える。
- Stage 4では、患者相談窓口の問い合わせ滞留件数が減る。
- Stage 5では、自分たちのポスターがロビーと病棟入口に掲示される。
- Finalでは、病院正面に報道カメラが集まる。

数値スコアや星を増やす必要はない。自分たちの成果によって病院の状態が変わったと見せるほうが、この企画の世界観に合っている。

## 次に検討したい案

### Stage 3の罠を「AIが意図的に嘘をつく」より「出典選択を間違える」体験へ寄せる

現在は、汚染教材に加えてシステムプロンプトでもAIの誤答を固定する設計になっている。罠を確実に発火させられる反面、種明かし後に「研修用にAIをわざと壊しただけ」と受け取られる可能性がある。

より現実に近いのは、AIが古い早見表を優先して回答し、出典名、発行年、最新版かどうかを確認すると矛盾が見える構成である。罠の確実性は汚染教材で担保しつつ、学びを「AIは嘘つき」で止めず、「速い回答ほど出典管理が必要」まで深められる。

### Stage 3.5を「初めて病院を救えた瞬間」として強く見せる

Stage 3.5の「接点をひとつ、減らした」は非常に良い追加である。6分の小課題として通過するだけでなく、参加者の判断によって患者や職員を初めて守れた瞬間として扱う価値がある。

配置線が消える演出に加え、後のメールで「あの応援看護師は別病棟へ行かなかった」と再確認できるようにする。結果がFinalまで残れば、自分たちの行動が病院を変えた実感が強まる。

### 苅部さんにチーム固有の記憶を持たせる

苅部さんは、120分を通して関係が育つ設計になっている。過去の行動を一度だけ引用すると、その関係性がさらに生きる。

- 正典を先に読んだチームには「今回は先に読みましたね」。
- 罠を踏んだチームには「前回みたいに、先に手を動かさないでくださいよ」。
- 個人情報の送信を止めたチームには「珍しく送る前に止まりましたね」。
- Finalでは「最初の日、メール10通で詰んでいた人たちとは思えませんね」。

称賛しすぎず、苅部さんらしい皮肉で返す。長い説明を追加しなくても、同じ人物と付き合ってきた感覚を出せる。

### Stage 5の作品を院内に実際に掲示する

画像を提出した後、病院ロビーの画面へ自動的に合成して見せる。外国人家族や高齢者が一瞬立ち止まる演出を入れると、「画像を生成した」から「相手に伝わる掲示を作った」へ意味が変わる。

他チームの作品はレース中には見せない。全チームの完走後、Debriefで壁一面に並べてポスター大賞の投票へつなげる。レース中の模倣を防ぎながら、作品を会場全体の成果として回収できる。

## ブラックユーモアは各ステージに一つ程度がちょうどよい

本筋を邪魔しない範囲で、次のような小ネタを挟める。

- Stage 1で返信した名札サイズが誤発注され、Final直前に巨大な名札が届く。
- ポスターの承認欄に「内容未確認」の印が押されている。
- 記者会見直前、仮称が「聖クロノス熱（仮）（正式）」へ更新される。
- 流行曲線のファイル名が `最新版_本当の最終版_修正2.xlsx` になっている。
- 緊急時ほど苅部さんのPHSの電池残量が減っている。

小ネタを増やしすぎると、参加者が読むべき情報と冗談の区別がつかなくなる。各ステージ一つ程度に抑え、後で回収できるものを優先したい。

## 最新設計と動くモックには同期差がある

改善案を比較する前に、評価対象を揃える必要がある。直近の設計変更は、動くモックへまだ反映されていない。

- モックのStage 3は旧「5A病棟・原因不明の発熱」版である。
- 最新設計のStage 3は「5B病棟・ノロウイルス」版である。
- Stage 3.5はシナリオとUI設計があるが、モックには未配置である。
- モック内のStage 3説明には旧罰ゲーム「接触者リスト整形」が残っているが、実装は「消毒液ボトルの補充」へ変わっている。
- 企画書には「全7ステージのモック完成」とあるが、Stage 3.5追加後の構成とは一致しない。

最新のStage 3シナリオにも、モックが旧版であることが明記されている。現状のモックをそのままテストすると、一世代前の体験が評価対象になってしまう。

## 次の議論で決めたいこと

現時点では、次の順に判断するのがよいと考える。

1. Finalに短い模擬記者会見を加えるか。
2. 過去の提出物をFinalの質問や苅部さんの台詞へ反映するか。
3. 各ステージの成果を院内図や背景の変化として見せるか。
4. Stage 3の罠を、意図的な誤答より出典選択の失敗へ寄せるか。
5. 最新のStage 3とStage 3.5を反映したモックを、次のテストプレイの基準版にするか。

自分は、まずFinalの模擬記者会見と過去提出物の引用を採用する案に傾いている。現在ある教材とログを最も活かせるうえ、ゲーム全体を「個別課題の連続」から「自分たちの判断が最後に問われる一つの事件」へ変えられるためである。
