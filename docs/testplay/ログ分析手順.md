# ログ分析手順

開催後に、D1 `hell-ict-testplay` へ溜まったログをSQLで読むための手順。前作「地獄のAI」Event 91の分析（`docs/前作分析/2026-08-28_Event91ログ分析.md`）と同じ観点——ステージ到達時刻、AIの使い方、ボトルネック——を『地獄のICT』でも取れるようにしてある。

## テーブル

| テーブル | 中身 | 書き手 |
|---|---|---|
| `progress_events` | チームの位置（`pos` 0〜7＝Prologue〜Final）と `kind`（`entry` / `clear` / `jump`） | クライアント（`POST /api/progress`） |
| `activity_events` | 発言・提出・判定を1件1行 | Worker（`chat.*` / `thread.create`）とクライアント（`POST /api/teams/:code/activity`） |

`activity_events.created_at` はミリ秒精度のISO 8601（`2026-09-03T02:14:07.482Z`）で、行を書いた瞬間に刻まれる。前作は保存時に一括で書いていたため発言単位の時刻が取れなかった。ここが今回の要点で、会話の間合いや1ステージの滞留時間を後から復元できる。

`event_id` は開催回の識別子（`apps/worker/wrangler.jsonc` の `vars.EVENT_ID`）。複数回分が同じDBに混ざるので、開催回をまたいで集計するときは必ず絞る。以下のクエリでは `EVENT_ID = 'dev'` を例に使う。

コマンドは `apps/worker` で実行する。`--remote` を付けないと本番ではなくローカルのD1を読む。

## 1. チーム別のステージ到達時刻

どのチームがいつ各ステージへ入り、どこで止まったか。前作の「ステージ進行の中央値」に相当する。

```bash
npx wrangler d1 execute hell-ict-testplay --remote --json \
  --command "SELECT team_code, pos, kind, view, MIN(created_at) AS first_at FROM progress_events WHERE kind <> 'jump' GROUP BY team_code, pos, kind ORDER BY team_code, pos"
```

## 2. チーム別のAI発言数と平均長

AIをどれだけ使い、1発言にどれだけ書いたか。`chat.user` が参加者の発言、`chat.assistant` がAIの応答。

```bash
npx wrangler d1 execute hell-ict-testplay --remote --json \
  --command "SELECT team_code, kind, COUNT(*) AS n, ROUND(AVG(LENGTH(text)), 1) AS avg_len, MIN(created_at) AS first_at, MAX(created_at) AS last_at FROM activity_events WHERE event_id = 'dev' AND kind IN ('chat.user', 'chat.assistant') GROUP BY team_code, kind ORDER BY team_code, kind"
```

## 3. kind別の件数

全体の傾向を1枚で見る。`chat.pii_blocked` や `trap.s3` / `trap.s4` の発火数、`verdict.*` の回数から、罠と判定がどれだけ効いたかが分かる。

```bash
npx wrangler d1 execute hell-ict-testplay --remote --json \
  --command "SELECT kind, COUNT(*) AS n, COUNT(DISTINCT team_code) AS teams FROM activity_events WHERE event_id = 'dev' GROUP BY kind ORDER BY n DESC"
```

## 4. 1チームの会話を時系列で読む

較正の判断材料は結局これ。`chat.*` だけでなく提出と判定も同じ時間軸に並ぶので、「どんなやり取りの末に何を出して、どう判定されたか」がそのまま読める。

```bash
npx wrangler d1 execute hell-ict-testplay --remote --json \
  --command "SELECT created_at, kind, thread_id, role, view, meta, text FROM activity_events WHERE event_id = 'dev' AND team_code = '100001' ORDER BY id"
```

`thread_id` で束ねるとスレッドごとの文脈が追える（Stage 2のタスク別文脈分離が使われたかどうかはここで分かる）。

## 読むときの注意

- **PIIを含む本文は保存していない。** 送信前ゲートで止まった行は `chat.pii_blocked`、クライアント記録で検知した行は `meta.piiRedacted = true` になり、いずれも `text` が空になる。本文が空でも「発言が起きたこと」自体は記録されている。
- **同じ `command_id` の再送は行を増やさない。** `(command_id, kind)` のUNIQUEとINSERT OR IGNOREで潰しているので、件数はそのまま実際の発言数として数えてよい。
- **ログの欠落はありうる。** サーバ側の記録は `waitUntil` で非同期に書き、失敗しても握り潰す（記録のためにゲームを止めない設計）。件数の突き合わせが合わない場合はまずこれを疑う。
