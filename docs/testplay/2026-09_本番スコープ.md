# 2026年9月 本番（山口大学）スコープ

2026-09-03に決めた、本番までの約3週間で何を作り、何を作らないかの記録。[テストプレイ振り返り](2026-08-23_振り返り.md)と[反映タスク](2026-08-23_反映タスク.md)から、期限に間に合うものだけを切り出した。

## 前提

- 本番は8/23と同じモック配信ビルド（`pnpm build:testplay` → `wrangler deploy`）で実施する。Reactへの画面移植は10月以降に始める。
- 理由は3つ。テストプレイで実際に回った実装を捨てて未検証の実装で本番を迎えない。振り返りの反映と移植を並行すると両方が中途半端になる。タブ型シェルへの再設計（反映タスクE）が控えており、今の画面構造を移植しても作り直しになる。
- 移植で得たい価値は、判定と罠のテスト可能化、ゲーム状態のサーバ正、ステージごとの会話の文脈分離（サーバ側）、活動ログの自動蓄積の4つで、いずれも画面ではなくサーバとドメイン層の話である。10月の移植はドメイン層 → Durable Objects → ログ → 画面の順で進める。

## 9月に作るもの

### 1. サーバ正のゲーム状態（TeamRoom Durable Object）

- **チェックポイント**: モックが現在のステージ・位置・経過時間・罠の使用済みフラグ・ステージ固有データを Durable Object へ保存し、入室時に取り出して自動復帰する。8/23の進行台本§5-1「リロードで状態が消えたらファシリテーターが手動でジャンプし、そのステージの最初からやり直し」を無くす。
- 罠フラグはサーバ側で後退を拒否する。リロードで罠をリセットする抜け道を塞ぐ（企画書§6「連続罰は1回まで」）。
- **全チームのライブリーダーボード**: 8/22に自チームのみへ落とした帯を、D1の進捗集計（`GET /api/progress/summary`）から全チーム表示へ戻す。

### 2. ステージごとの会話の文脈分離

タブと「＋」は廃止し、**AIチャットは今のステージの会話だけを表示する**（2026-09-05決定）。前のステージの会話は表示しない。参加者が会話を選ぶ操作を持たないので、複数画面で現在地を見失う要因（[課題一覧](2026-08-23_課題一覧.md) 課題4）を1つ減らせる。文脈をステージごとに分けること自体はサーバ側（ステージ入場で新しい会話へ切り替え、Durable Objectに保存）で保つ——予備PCからの復帰とログ分析がこれに乗る。

### 3. 活動ログの自動蓄積（D1 `activity_events`）

- AIとのやり取り（ユーザー発言・AI応答・失敗・拒否・PIIブロック）をWorker側で発言ごとに記録する。前作の反省として、時刻はミリ秒精度で発言単位に残す。
- 提出物と判定結果（各ステージの提出、判定、罠発動、Finalの一言）をモックから `POST /api/teams/:code/activity` で記録する。
- PIIを含む本文はD1にも残さない。
- 分析手順は `ログ分析手順.md` に置き、前作Event91と同じ集計を再現できるようにする。

### 4. 公開APIの防御（前作Hell-AI-v2の教訓）

- `/api/*` 全体へのOriginチェック（許可リストは環境変数、未設定なら同一オリジンのみ）。
- チームコードの規則判定（`[開催回2桁][チーム番号4桁]`。開催回は環境変数`EVENT_NO`、チーム番号の上限は`TEAM_MAX`（既定100）。規則外は404）。事前登録が要らないので、予備コードは次の番号を配るだけで済む。
- チーム単位のチャット送信レート制限（1分あたり既定20通、超過は429、OpenAIを呼ばない）。
- 前作で管理系APIに検証漏れがあったため、入口で一律にかける。
- ゲームマスターのリセット（`ADMIN_TOKEN`を持つリクエストだけが通る`POST /api/gm/teams/.../reset`と、ダッシュボードの`#gm`モード）。リハーサルのやり直しと当日の事故復旧用で、手順は[開発ハーネス](../development-harness.md)にある。

### 5. 学習と無関係なUI障害の除去（反映タスク§8の優先1・2）

- Stage 2のコピー＆貼り戻し導線（G）
- Stage 4（旧Stage 3.5）の院長対話をポップアップから埋め込みへ（E）
- ミッションバー（B）と導入画面（A）
- 文字サイズの拡大（F）

### 6. 運営準備（最終週、実装は凍結）

- 仮値の閾値較正（S1_MIN_LEN=70、締切60秒、S1_CTX_MIN=100）、devbarのプレビューボタン削除
- 通しリハーサル1回。人手で所要時間を計測する
- デブリーフィング資料（各ステージのスクショ、発熱漸増の種明かし、「少し先の未来」のメッセージ）、導入説明の台本、辞令カード・チームコード・アンケートQRの更新
