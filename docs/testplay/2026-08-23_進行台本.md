2. **Stage 1は新設計**（2026-08-22の通しプレイ検証で実機動作を確認済み）: 3ラウンド×6通＋前任ICNの引き継ぎメモを使う。R1はそっけない返信で失敗（判定は分量70字＋丁寧語）。R2はAI下書きありだが1分締切に間に合わず失敗。苅部さんが「引き継ぎメモをコンテキスト欄へ丸ごと貼る」を指南し、R3で即クリア。

5. **Stage 6には判定がある**（docsの「判定なし」から変更）。textheavy/default候補の提出は差し戻し、pictogram/multilingual候補＋プロンプトにマスク・面会時間が入っていれば通過。
6. **Stage 5は再設計版（2026-08-22。同日の通しプレイ検証で実機動作を確認済み）**。「家族への返信」を廃止し「保健所への発熱患者一覧（14名）提出」へ変更、画面呼称は「回答」→「報告」。患者相談窓口・近藤さんはStage 5から退場しStage 6で初登場。氏名（14名分）を含む送信はPIIブロック＋罰（黒塗り・AI使用ロック）、**患者IDのみはPII扱いしない**。**保健所への提出期限（可視カウントダウン）は維持**し、超過時の着信ポップアップは話者を近藤さん→事務長（保健所からの督促を取り次ぐ）へ差し替え。
7. **リーダーボードは手動運用**。画面のレース表示は当てにせず、ファシリテーターが目視で記録する（§4）。
8. **実AI（GPT-4o）を呼ぶのは Stage 1 の「AIに下書きさせる」ボタンと、Stage 3・4・5 の右ペインAIチャット**。Stage 5は氏名等のPIIを送るとブロック＋罰（AI使用ロック）。**Finalは右ペイン（AIチャット）ごと畳んであり、送信経路そのものが無い**（[../ui/07_Final.md](../ui/07_Final.md) §1）。**Stage 2・6は実APIを呼ばない**——Stage 6のポスター候補は事前生成画像からの出し分け（`s5Generate()`）、**Stage 2は用意済みの整形結果（タブ区切りの表）を必ず返す**（2026-08-22 ユーザー決定。実GPTだと出力形式が安定せず、グリッドへ貼り戻せない形で返る事故があるため）。どちらも生成に数十秒待たされることはない。Stage 2はチームが何を書いて送っても同じ表が返るので、**「AIの返し方が悪い」で詰まることはない**——観察の焦点は、要件を言語化して送れたか・返ってきた表をコピーしてグリッドへ貼り戻せたかに置く。送信前PIIゲート自体はWorker側で全ステージ共通に効いている（Stage 5以外は罰が出ず、ブロックの告知だけが出る）。
9. 判定閾値・締切秒数は仮値。当日朝の通しプレイで較正した値に置き換える。

> 📌 **実行環境について**: このテストプレイは `docs/ui/mock/index.html`（ブラウザ内状態のみ）に、Workers経由の実OpenAI API（GPT-4o）を接続した構成で動く。`pnpm build:testplay` が `docs/ui/mock/index.html` と `assets/images/production/` を `apps/worker/public/` へ書き出し、`wrangler dev`（または実デプロイ）が配信する。**（2026-09-05 更新: チェックポイント導入）ゲーム進行の状態（どのステージまで進んだか・経過時間・罠と罰の状況）はサーバ（Durable Object）へ自動保存され、同じチームコードで再入室すれば自動で復帰する。** リロードしても、別のPCへ移っても、保存済みステージの先頭から再開できる。AIチャットの会話ログも同じくサーバ側に保存される（**Stage 2 と Stage 6 は実APIを通らないので例外**——リロードするとそのタブの履歴は空に戻る。どちらも同じ応答を何度でも出せるので支障はない）。**復帰しないのはステージ内の未提出の作業だけ**（グリッドの編集内容・入力途中の提出文・生成済みポスター）——戻る先は「そのステージの先頭」であり、途中の入力までは戻らない。この前提が§5のトラブル対応の土台になる。

## 3. ステージ別進行メモ

各ステージ、①参加者に見える課題 ②裏で起きること（罠・仕掛け） ③詰まったときの介入台詞（苅部さんの流儀：答えを言わず在り処を指す） ④絶対に先に言ってはいけないこと、の順で記す。

### Prologue（着任）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | チームコードとチーム名を入れて入室→ウェルカム画面→受信トレイ3通を読む。提出・判定なし |
| ② 裏で起きること | メール3（夜勤師長の申し送り）末尾に未知ウイルスの種「原因不明の発熱の患者さんが数名」を仕込んである。**3通とも開封してから7秒**（または受信トレイ表示から2分経過）で事務長ブリーフィングへ自動遷移し、Stage 1が始まる |
| ③ 介入台詞 | 基本的に苅部さんは登場しない。ファシリテーターは操作の最小限の案内のみ（AI体験はまだ先） |
| ④ 言ってはいけないこと | メール3の発熱の一文を指差さない。「これは伏線です」と匂わせない。この後に事務処理を命じられることも予告しない——**何も起きていないのに理不尽が来る**、という驚きがこのステージの核 |

### Stage 1（平常運転・3ラウンド新設計）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | 事務長ブリーフィング（他職員5分、派遣は1分）を読んで了解。R1で6通の平時事務メールに手打ちで返信する。判定は分量70字以上＋丁寧語 |
| ② 裏で起きること | **R1はほぼ確実に失敗する**（そっけない返信のまま時間切れになる想定）。失敗結果はメールスレッド形式のオーバーレイで表示し、OKボタンで閉じる。直後に苅部さんが登場しAIを渡す。**R2はAI下書きが使えるが、要点を自分で手打ちする手間があり、1分の締切に間に合わず失敗する**設計。ここで苅部さんが「前任ICNの引き継ぎメモをまるごとAIのコンテキスト欄へ貼る」を指南する。**R3でそのとおりにやると即クリア**する |
| ②-例外 | R1を丁寧語の長文で全通完走してしまう（AI無しで速いチームが実在する）場合は、そのまま苅部さんのオチ台詞で通過させる。ズルとして止めない |
| ③ 介入台詞 | R1失敗後: 「……全部は無理でしたね。1人でやる量じゃないです」「……ああ、あれ本当ですよ。派遣の方だけ1分。去年、事務長が決めました」「うち、AI入ってます。使えるようにしました」。R2失敗後: 引き継ぎメモの在り処と使い方（丸ごとコンテキストへ貼る）を指す。文面そのものは書かない |
| ④ 言ってはいけないこと | 返信メールの文面を代わりに書かない。「70字」「丁寧語」という判定基準の数値を先に明かさない（体感で掴ませる）。1分ルールを「バグ」と言わない——組織が決めた理不尽として扱う。R1・R2が失敗する設計であることを事前に明かさない |

> 観察の重点: **R1が本当に「ほぼ全チーム失敗」するか**（判定閾値70字が実文例に対して妥当か）、R2が「AI下書き＋手打ちの要点入力」で本当に間に合わないボリュームか、R3の「引き継ぎメモ貼り付け」で本当に一気にクリアできるか。3点ともP0で最優先の確認事項。

### Stage 2（火の手）

| | 内容 |

## 5. トラブル対応

### 5-1. リロード・PC切替からの復帰（2026-09-05 更新: チェックポイント導入）

**前提**: ステージ進行はサーバへ自動保存されている。**同じチームコードで入室し直せば自動で復帰する**——
ファシリテーターの手動ジャンプは要らない。

復帰したときの状態:

- **戻る先は保存済みステージの先頭。** ステージ内の未提出の作業（グリッドの編集内容・入力途中の提出文・
  生成済みポスター）は戻らない。ステージ冒頭の演出（赤帯・一報オーバーレイ）は再生される
  （Stage 1 の長いブリーフィングだけは飛ばす）。
- **経過時計は止まらない。** 離席していた分も加算されて再開する。レースなので「詰まったらリロード」が
  得にならないようにしてある——**ファシリテーターが時計を調整する必要は無い**。
- **罠は再発動しない。罰ゲームは最初からやり直しになる。** 罰の途中で落ちた場合、復帰後にもう一度
  最初から払ってもらう（時間で払う罰なので、途中からの再開はしない）。
- AIチャットの会話ログも復帰する（Stage 2・6 は実APIを通らないため例外。§1の📌参照）。

対応手順:

1. チームに「同じチームコードとチーム名で入室し直してください」と案内する。チーム名は同一PCなら自動で
   復元される（別PCでは入力し直し）。
2. 入室後、そのチームの現在地が復帰前と合っているかを画面で確認する。
3. §4の記録表に「リロードあり」と一言添える（**経過時間の調整は不要**）。

**入室画面にメッセージが出て入れないとき:**

| 表示 | 意味 | 手順 |
|---|---|---|
| 接続を確認しています… | 起動時の疎通確認中（最大5秒） | そのまま待つ |
| サーバに接続できません。… | APIへ届いていない | ［再試行］を押す。復旧しなければ下記の台本モード |
| 進行状況を取得できません。… | 保存済みの進行を読めない | ［再試行］を押す。**welcomeへ進めないのは正しい挙動**——ここで無理に進めると進行が失われる |

> ⚠️ **［オフラインで進める（台本モード）］は最後の手段。** 押すと入室できるが、**AI・保存・帯がすべて
> 動かない**（画面下に「AI・保存・帯は動きません」と出る）。そのチームの**進行は記録されず、順位も
> ログ分析の対象にならない**ので、押した場合は§4の記録表に必ず残し、そのチームの計測は無効として扱う。
> 押す前に、まず［再試行］とネットワークの確認を尽くすこと。

**自動復帰が失敗したとき（最後の手段）:**

自動復帰が効かない・現在地がずれている場合に限り、ファシリテーターが手動で送る。

1. URLハッシュ（`#s1` `#s2` `#s3` `#s4` `#s5` `#final` 等）で該当ステージを直接開く。**リロードを伴うので、
   ブラウザのアドレスバーにURL＋ハッシュを入れてEnterでよい。**
2. 開発用スイッチャ（devbar）のボタンで送りたい場合は、**先に隠しトグルで表示させる**——アドレスバーの
   URL末尾に **`#devbar`** を付けてEnterを押すと、リロードなしで開発用の枠（見出し・スイッチャ・
   ステージ解説）が現れる。もう一度同じ操作で消える。**参加者に見せている画面では、用が済んだら必ず消す**
   ——ステージ解説には罠の種明かしがそのまま書いてある。**同じトグルで画面右端の縦中央にもつまみ（「JUMP」）が
   出る**ので、引き出しからもステージへジャンプできる（押すと飛んで自動で閉じる。ゲーム画面から視線を外さずに
   送れるぶん、こちらのほうが速い）。
3. **ジャンプするとそのステージの最初からやり直しになる**（提出済みの内容は復元されない）。既に通過済みの
   ステージへ戻さないよう、必ずそのチームの現在地に対応するハッシュ/ボタンを選ぶ。
4. 手動ジャンプで送った場合は、その旨を§4の記録表に残す（自動復帰が効かなかった＝不具合の可能性がある）。

> ⚠️ devbarのボタン構成（`STEPS`テーブル）は開発の進行に伴って変わりうる。**当日朝の通しプレイで、実際に使うdevbarのボタン名とURLハッシュの対応を一度確認し、紙にメモしておく。**
>
> 📌 **通常進行でdevbarを使う場面は無い**（2026-08-22の自動遷移化）。Prologue→Stage 1、Stage 2→3、
> Stage 3→4、Stage 5→6 は画面側が自動で送る。**Stage 4→5 だけはチームが院長の結果報告と
> クリアカードの［確認した（次へ）］を順に押して進む**（2026-08-22変更。演出を読み切れないという指摘への対応で、
> 押すまで画面はクリアカードのまま止まる——止まっていても異常ではない）。devbarは自動復帰が失敗したときと、
> 朝の通しプレイでの部分確認のためだけに使う。

### 5-2. AI応答が遅い・失敗するとき

このテストプレイは実際のOpenAI API（GPT-4o）を呼ぶため、本物の遅延・タイムアウト・レート制限が起こりうる。

- 応答待ちが数秒〜十数秒かかることは正常。参加者には「少し待ってください」と案内する。
- 30秒以上応答が返らない、または複数チームで同時に遅延・失敗が起きている場合は、OpenAI側かネットワーク側の障害を疑う。ファシリテーターPCから疎通確認し、必要なら**全チーム同条件でレース時計を止めて**復旧を待つ（企画書§9のWi-Fi停止対応と同じ扱い）。
- 個別チームのみ失敗する場合は、同じ内容で再送してもらう。連続して失敗するなら予備PC・別ブラウザタブでの再入室を案内する。

### 5-3. PIIブロック（Stage 5）が誤爆したと思われるとき

検知対象は発熱患者一覧14名分の氏名・生年月日・電話番号の固定パターン（`packages/domain/src/pii.ts`
`feverLinelistPatientNames` が単一の情報源。**患者IDそのものは検知対象外**）。

1. 送信しようとした文面を確認し、上記の固有情報（生年月日・電話番号は表記ゆれも含む汎用書式で拾う）が含まれていないか照合する。患者IDのみの送信でブロックされた場合は、それ自体が実装側の不具合である。
2. 含まれていれば正しい発火であり、誤爆ではない。参加者には「個人情報が入っていた」ことを事実として伝える。
3. 含まれていないのにブロックされた場合は、実装側の検知パターンの問題である可能性が高い。その場ではチームに詫び、内容を少し変えて再送するよう案内しつつ、**発生時刻・チーム・送信文面を必ず記録する**（観察メモ§6・開発チームへのフィードバック用）。罰ゲームを免除するかどうかは運営判断とし、免除した場合もその旨を記録する。

### 5-4. チームPCのフリーズ・故障

（2026-09-05 更新: チェックポイント導入）予備PCで**同一チームコード**を使って再入室すれば、**ステージ進行・経過時間・罠と罰の状況・AIチャットの会話ログが自動で復帰する**（§1の📌・§5-1と同じ）。ファシリテーターが現在地を組み直す必要は無い。**チーム名は入力し直してもらう**（同一PCなら自動復元されるが、PCが替わると保存が引き継がれない）。戻らないのはステージ内の未提出の作業（グリッドの編集内容・入力途中の提出文・生成済みポスター）だけで、罰ゲームの途中だった場合は復帰後に最初からやり直しになる。入室画面にメッセージが出て入れないときと、自動復帰が効かないときは§5-1を参照する。
