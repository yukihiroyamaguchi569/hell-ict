## 0. この台本の前提

このテストプレイは、企画書§8「P0とP2で必ず実測テストプレイ」にあたる。以下は**設計ドキュメントより新しい確定事項**であり、docsの記述と食い違う場合はこちらを優先する（食い違いの一覧は本ファイル末尾§7）。

1. **範囲**: Prologue〜Stage 5完走まで（レースのゴール。Stage 5通過で完走演出が出る）。**Final は
   レース外の判定なし振り返りとして実施する**（2026-08-22再設計）——ゴール演出後に任意で「振り返りへ
   進む」を選び、対応の全体図ボードへ一言を書き込む。所要目安5分、Debriefの30分枠に組み込む（§2）。
2. **Stage 1は新設計**: 3ラウンド×6通＋前任ICNの引き継ぎメモを使う。R1はそっけない返信で失敗（判定は分量70字＋丁寧語）。R2はAI下書きありだが1分締切に間に合わず失敗。苅部さんが「引き継ぎメモをコンテキスト欄へ丸ごと貼る」を指南し、R3で即クリア。
3. **Stage 3は疥癬版**。平尾台医療センターからの転院患者3名（通常疥癬・治療完了済み）を巡り、過剰対応（角化型向け対策）へ誘導する罠。
4. **Stage 3.5（新情報の解釈）を実施する**。原因不明の発熱急増→海外速報論文の要約→眼痛・羞明の抽出→夜勤者確認提案でクリア。
5. **Stage 5には判定がある**（docsの「判定なし」から変更）。textheavy/default候補の提出は差し戻し、pictogram/multilingual候補＋プロンプトにマスク・面会時間が入っていれば通過。
6. **Stage 4は再設計版（2026-08-22）**。「家族への返信」を廃止し「保健所への発熱患者一覧（14名）提出」へ変更、画面呼称は「回答」→「報告」。患者相談窓口・近藤さんはStage 4から退場しStage 5で初登場。氏名（14名分）を含む送信はPIIブロック＋罰（黒塗り・AI使用ロック）、**患者IDのみはPII扱いしない**。**保健所への提出期限（可視カウントダウン）は維持**し、超過時の着信ポップアップは話者を近藤さん→事務長（保健所からの督促を取り次ぐ）へ差し替え。
7. **リーダーボードは手動運用**。画面のレース表示は当てにせず、ファシリテーターが目視で記録する（§4）。
8. AIチャットは実AI（GPT-4o）接続。Stage 2以降で使用可、Stage 4は氏名等のPIIを送るとブロック＋罰（AI使用ロック）。
9. 判定閾値・締切秒数は仮値。当日朝の通しプレイで較正した値に置き換える。

> 📌 **実行環境について**: このテストプレイは `docs/ui/mock/index.html`（ブラウザ内状態のみ）に、Workers経由の実OpenAI API（GPT-4o）を接続した構成で動く。`pnpm build:testplay` が `docs/ui/mock/index.html` と `assets/images/production/` を `apps/worker/public/` へ書き出し、`wrangler dev`（または実デプロイ）が配信する。**ゲーム進行の状態（どのステージのどこまで進んだか）はブラウザ内のみに保持され、リロードで消える。** 一方、AIチャットの会話ログはサーバ（Durable Object）側に保存されるため、リロードしても消えない。この非対称性が§5のトラブル対応の前提になる。

## 3. ステージ別進行メモ

各ステージ、①参加者に見える課題 ②裏で起きること（罠・仕掛け） ③詰まったときの介入台詞（苅部さんの流儀：答えを言わず在り処を指す） ④絶対に先に言ってはいけないこと、の順で記す。

### Prologue（着任）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | チームコード入室→ウェルカム画面→受信トレイ3通を読む。提出・判定なし |
| ② 裏で起きること | メール3（夜勤師長の申し送り）末尾に未知ウイルスの種「原因不明の発熱の患者さんが数名」を仕込んである。2分経過（または3通とも開封）で事務長ブリーフィングへ自動遷移し、Stage 1が始まる |
| ③ 介入台詞 | 基本的に苅部さんは登場しない。ファシリテーターは操作の最小限の案内のみ（AI体験はまだ先） |
| ④ 言ってはいけないこと | メール3の発熱の一文を指差さない。「これは伏線です」と匂わせない。この後に事務処理を命じられることも予告しない——**何も起きていないのに理不尽が来る**、という驚きがこのステージの核 |

### Stage 1（平常運転・3ラウンド新設計）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | 事務長ブリーフィング（他職員5分、派遣は1分）を読んで了解。R1で6通の平時事務メールに手打ちで返信する。判定は分量70字以上＋丁寧語 |
| ② 裏で起きること | **R1はほぼ確実に失敗する**（そっけない返信のまま時間切れになる想定）。失敗結果はメールスレッド形式のオーバーレイで表示し、OKボタンで閉じる。直後に苅部さんが登場しAIを渡す。**R2はAI下書きが使えるが、要点を自分で手打ちする手間があり、1分の締切に間に合わず失敗する**設計。ここで苅部さんが「前任ICNの引き継ぎメモをまるごとAIのコンテキスト欄へ貼る」を指南する。**R3でそのとおりにやると即クリア**する |
| ②-例外 | R1を丁寧語の長文で全通完走してしまう（AI無しで速いチームが実在する）場合は、そのまま苅部さんのオチ台詞で通過させる。ズルとして止めない |
| ③ 介入台詞 | R1失敗後: 「……全部は無理でしたね。1人でやる量じゃないです」「……ああ、あれ本当ですよ。派遣の方だけ1分。去年、事務長が決めました」「うち、AI入ってます。使えるようにしました」。R2失敗後: 引き継ぎメモの在り処と使い方（丸ごとコンテキストへ貼る）を指す。文面そのものは書かない |
| ④ 言ってはいけないこと | 返信メールの文面を代わりに書かない。「70字」「丁寧語」という判定基準の数値を先に明かさない（体感で掴ませる）。1分ルールを「バグ」と言わない——組織が決めた理不尽として扱う。R1・R2が失敗する設計であることを事前に明かさない |

> 観察の重点: **R1が本当に「ほぼ全チーム失敗」するか**（判定閾値70字が実文例に対して妥当か）、R2が「AI下書き＋手打ちの要点入力」で本当に間に合わないボリュームか、R3の「引き継ぎメモ貼り付け」で本当に一気にクリアできるか。3点ともP0で最優先の確認事項。

### Stage 2（火の手）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | 5A病棟のMRSA記録（汚いExcel/23行）を統一ラインリストへ整形し提出。締切5分（可視カウントダウン）。超過すると追加10行が着弾するが提出はロックされない |
| ② 裏で起きること | 患者`005`/`6`/`008`（MRSA陰性・発熱あり）が伏線として紛れ込んでいる（Stage 4で回収）。苅部さんは追加分着弾より**先**にAI活用を促すトリガーで登場する。AIに貼ればおよそ3分、手作業のみだと締切に間に合わず追加分を浴びる |
| ③ 介入台詞 | 「また師長のExcelですか。あれ、日付の書き方が5種類くらいありますよね」「そういうの、手で直すもんじゃないですよ。……で、そっちにAIあるんでしょ? うちには無いのに」——整形の観点を促すのみ |
| ④ 言ってはいけないこと | 正規化ルール（列の書式）の詳細をファシリテーターから教えない。患者005/6/008を指して「これが伏線です」と言わない。完成した表を渡さない |

### Stage 3（疥癬・本研修の心臓部）💀罠

| | 内容 |
|---|---|
| ① 参加者に見える課題 | ステージ開始時、「病棟に疥癬が出ているらしい」というオーバーレイの一報が入る。詳細は3B病棟師長のメール＋転院患者3名（平野・遠藤・三浦）のサマリ添付で届く。PPE・隔離／解除基準／環境消毒の3欄で対応方針をまとめ提出する |
| ② 裏で起きること | カワイさんの添付「疥癬対応早見表」（汚染教材）と、Stage 3中のAI（システムプロンプト注入）が、**角化型（痂皮型）疥癬向けの過剰対応**（個室隔離・予防衣常時着用・殺虫剤/熱処理・解除は当面継続）を断定的に返す。だが3名は**通常疥癬**で、治療完了＋最終治療から24時間以上経過済み——正典マニュアル（第7版第5章）は「通常疥癬は治療完了後24時間で標準予防策のみに戻す」と明記している。転院患者サマリ（治療完了の事実）と正典マニュアル（解除基準）を突き合わせて初めて「過剰対応を退け標準予防策に戻す」という正解に到達する。罠発火は「罠語があり、かつ正解語が無い」場合のみ——正しく否定して書いた提出は誤爆しない |
| ②-罰 | 罠発火で画面暗転→罰ゲーム「消毒液ボトルの補充」（単調作業）。15本目で追加が湧き、全数終わると「継ぎ足し禁止」の掲示が出て全数破棄させる |
| ③ 介入台詞 | 「その基準、どこ情報ですか」「マニュアル、去年PDFにしたの私ですよ。読みました?」——**数字ではなく基準の出所**を問う。正解値は絶対に言わない（知らないので言えない、という設定） |
| ④ 言ってはいけないこと | 「角化型」「通常型」という病型の言葉、24時間ルールの中身を先に明かさない——**罠を踏んだ場合、気難しい皮膚科医の叱責台詞で初めて病型が明かされる**構成なので、ここを先出しすると罠の効きが死ぬ。「早見表は嘘です」「マニュアルが正しいです」と名指ししない。転院患者サマリの「治療完了・24時間経過」に気づかせるヒントを求められても、「サマリ、全部ちゃんと読みました?」程度に留める |

> 観察の重点: **半数以上のチームが罠にハマるか**（企画書§10の成功条件）。ハマらなければ罠が易しすぎる。ハマったチームがDebriefで笑えているか。

### Stage 3.5（新情報の解釈）

| | 内容 |
|---|---|
| ① 参加者に見える課題 | 幹部から転送された東陵国の英語速報論文をAIで要約し報告する。要約に眼痛（`眼窩部痛`/`羞明`/`眼の奥の痛み`も可）が含まれないと差し戻し。要約後、幹部から「それで、あなたたちはこれからどうしたいの?」と一度だけ問われる。夜勤者への眼痛・羞明確認を提案するとクリア |
| ② 裏で起きること | 罰ゲームはない。夜勤者確認の結果、発熱はないが眼痛を訴える応援看護師が見つかり、複数病棟への配置が見合わせになる（接点をひとつ減らす、という報酬演出） |
| ③ 介入台詞 | 苅部さんの発言は最小限（「要約にして送るんですよね」程度）。論文の中身や正解語（眼痛）は出さない |
| ④ 言ってはいけないこと | 「眼痛を探せばいい」と直接教えない。病原体名・感染経路を断定する発言をしない（未知ウイルスの正体は最後まで保留する設計） |

## 5. トラブル対応

### 5-1. ページのリロードでステージ状態が消えたとき

**前提**: モックはブラウザ内状態のみでステージ進行（どのメールに返信したか・グリッドの編集内容・提出物）を保持する。リロードするとこれらは消える。一方、AIチャットの会話ログはサーバ（Durable Object）側に保存されるため、リロードしても消えない。

対応手順:

1. リロード前にそのチームがどのステージのどこまで進んでいたかを、直前の観察かチームへの聞き取りで確認する。
2. `#devbar`（画面内の開発用パネル）またはURLハッシュ（`#s1` `#s2` `#s3` `#s4` `#s5` 等）から、該当ステージへジャンプする。
3. **ジャンプするとそのステージの最初からやり直しになる**（提出済みの内容は復元されない）。既に通過済みのステージへ戻さないよう、必ずそのチームの現在地に対応するボタン/ハッシュを選ぶ。
4. 復帰後、経過時間の扱いはファシリテーター判断とする（§4の記録表に「リロードあり」と一言添える）。

> ⚠️ devbarのボタン構成（`STEPS`テーブル）は開発の進行に伴って変わりうる。**当日朝の通しプレイで、実際に使うdevbarのボタン名とURLハッシュの対応を一度確認し、紙にメモしておく。**

### 5-2. AI応答が遅い・失敗するとき

このテストプレイは実際のOpenAI API（GPT-4o）を呼ぶため、本物の遅延・タイムアウト・レート制限が起こりうる。

- 応答待ちが数秒〜十数秒かかることは正常。参加者には「少し待ってください」と案内する。
- 30秒以上応答が返らない、または複数チームで同時に遅延・失敗が起きている場合は、OpenAI側かネットワーク側の障害を疑う。ファシリテーターPCから疎通確認し、必要なら**全チーム同条件でレース時計を止めて**復旧を待つ（企画書§9のWi-Fi停止対応と同じ扱い）。
- 個別チームのみ失敗する場合は、同じ内容で再送してもらう。連続して失敗するなら予備PC・別ブラウザタブでの再入室を案内する。

### 5-3. PIIブロック（Stage 4）が誤爆したと思われるとき

検知対象は発熱患者一覧14名分の氏名・生年月日・電話番号の固定パターン（`packages/domain/src/pii.ts`
`feverLinelistPatientNames` が単一の情報源。**患者IDそのものは検知対象外**）。

1. 送信しようとした文面を確認し、上記の固有情報（生年月日・電話番号は表記ゆれも含む汎用書式で拾う）が含まれていないか照合する。患者IDのみの送信でブロックされた場合は、それ自体が実装側の不具合である。
2. 含まれていれば正しい発火であり、誤爆ではない。参加者には「個人情報が入っていた」ことを事実として伝える。
3. 含まれていないのにブロックされた場合は、実装側の検知パターンの問題である可能性が高い。その場ではチームに詫び、内容を少し変えて再送するよう案内しつつ、**発生時刻・チーム・送信文面を必ず記録する**（観察メモ§6・開発チームへのフィードバック用）。罰ゲームを免除するかどうかは運営判断とし、免除した場合もその旨を記録する。

### 5-4. チームPCのフリーズ・故障

状態はDurable Object側に永続化されているため、予備PCで**同一チームコード**を使って再入室すれば、サーバ側の情報（チーム進度・AIチャットログ）は復帰する。ただしステージ内の未提出の作業（§5-1と同じ理由）は失われるため、devbarで現在地へ復帰させる。
