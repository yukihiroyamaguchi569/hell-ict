# 2026-09-09 見た目改善提案

## 目的と前提

9月の開催で、3〜4人が1台のPCを囲んでも、いま何をする場面か、誰がどこへ入力しているかをひと目で共有できる見た目にする。9月は配信版モックを使う。本番Reactへの移植は対象にしない。

UI改修フェーズでは `docs/ui/mock/index.html` が正典である。ここに記す案をモックへ反映する際、企画書、シナリオ、UI設計書、教材の整合確認や更新は行わない。

## 見た目の改善案

### 1. 危機画面で読むべき小さな文字だけ、十分に読める色へ寄せる

危機画面では、課題の補足、判定理由、操作上の案内など、参加者が次の判断に使う小さな文字を背景とのコントラスト比4.5:1以上を目安に調整する。通常サイズの文字についての基準は[WCAG 1.4.3: Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)を参照する。

ただし、発熱の伏線、共有フォルダ、紙の罫線は対象外とする。これらは目立たなさ自体が演出または2003年製の院内文書らしさに関わるためである。

### 2. ステージ名と課題文を案件カードとしてまとめる

ワークスペースの先頭に、薄い背景の案件カードを置く。`Stage N` を22px、課題文を16pxにし、カード左端の3px線で現在の課題を示す。ステージ名と本文を分け、中央ペインの上部へ視線を置くだけで「いまの仕事」と提出までの方向が分かるようにする。

カードを足しても縦方向の密度を増やさないよう、現行の `.work` の隙間や先頭要素の余白を相殺して調整する。カードが説明を増やす場所にならないことが大切である。

### 3. AIペインに固定ヘッダーを置く

幅380pxのAIペイン上部へ、高さ36〜40pxの固定ヘッダーを追加する。見出しは「AIアシスタント」、補助表示は「このステージ」とする。

会話ログだけで始まる現在の構成より、横から画面を見る参加者にも右ペインの役割と、会話が現在のステージに限られることが伝わりやすい。ログ領域を圧迫しないよう、既存の余白を調整して増分を最小限にする。

### 4. 入力中の提出枠を中立色で強調する

提出枠などの `.box` に、`.box:not(.warn):focus-within` を使った入力中の輪郭を加える。`--accent` などの中立的な案内色と細い影で、現在入力している場所を示す。

`warn` は誤りや不足の警告を表すため、この強調を適用しない。チームの操作担当以外も、いま話し合っている欄を追えるようにする。

### 5. 入室画面と感謝状は余力があれば磨く

入室画面は、病院名、タイトル、チームコード入力の大小と余白を整え、辞令・受付票のように端正な最初の一画面にする。感謝状は同じ紙と罫線の語彙を使い、最後に「自分たちの仕事が病院を助けた」と感じられる見せ方を検討する。

この二つはゲーム進行中の可読性を改善する1〜4より優先度を下げる。時間が足りない場合は、触らない。

## 根拠と実装時の確認箇所

行番号は `index.html` が継続的に変わるため、2026-09-09時点の目安である。実装時はセレクタ名で検索して位置を確認する。

| 改善案 | 現在の確認箇所（目安） | 根拠 |
| --- | --- | --- |
| 危機画面の小文字 | テーマトークンと `--fg-muted`、補助文の各セレクタ | 危機時にも判断に必要な案内は、離れた席から読める必要がある。 |
| 案件カード | `.work`（約294行）、`.stage-title`（約299行）、`.brief`（約301行） | 現在のステージ名は20px、課題文は18pxで、枠としてのまとまりはない。 |
| AI固定ヘッダー | `.pane-r`（約186行）、`.ai` と `.ai .log`（約447行）、`#pane-r`（約1358行） | ペイン幅は380pxで固定され、会話ログが上端から始まる。 |
| 入力中の強調 | `.box` と `.box.warn`（約306〜313行）、`.submit-area` | `warn` の橙は判定上の意味を持つため、入力中の案内と混ぜない。 |
| 入室・感謝状 | `.entry`（約589行）と感謝状の表示部分 | 開始と終了の印象を整えられるが、進行の妨げを直接減らす変更ではない。 |

肖像の額装、主要ボタンの寸法、左右ペインの比率は現状で十分に機能している。今回の変更案には含めない。

## 優先順位

1. 危機画面で重要な小文字を読めるようにする。
2. 案件カードで現在の課題を一つにまとめる。
3. AIペインの固定ヘッダーを追加する。
4. 提出枠の入力中強調を加える。
5. 入室画面と感謝状を磨く。

1〜4は、会場で1画面を囲むときの読み取りと会話に直接効く。5は余力枠とする。

## 今回は実装しない範囲と検証

この文書は見た目の改善提案であり、モック本体の変更、ゲームルール、ステージ内容、AIの応答、文書正典の改訂は行わない。

実装する場合は、少なくとも次を確認する。

- 通常、alert、crisisの各テーマで、重要な補助文字が背景に埋もれないこと。
- 標準・大・特大の文字サイズで、案件カード、AIヘッダー、提出欄が重ならず、横スクロールを生まないこと。
- `.box.warn` が従来どおり警告として見え、入力中の案内色が混ざらないこと。
- Stage 1からFinalまでを通し、AIログ、提出、オーバーレイ、感謝状の表示が崩れないこと。
- 会場で想定する画面サイズで、3〜4人が課題と入力中の欄を確認できること。
