## 発見1: 閻魔大王がイベント終盤を支配した

11:15以降の30分間はほぼ全チームが閻魔への連戦に費やした。yamagutiは5回、まさにぃは4回、大西ライオンズは3回挑戦してようやく勝利。1回で通ったのはchateaubriand・amakita・jsyのみで、3チームは1回挑んだまま時間切れになった。登録から閻魔クリアまでの中央値は82分で、**制限時間80分をわずかに超えており、コース全体が時間予算ギリギリに較正されていた**ことが分かる。

## 発見2: 閻魔の判定にブレがあり、「攻略」が発見されると機械化する

閻魔は「5回の発言で生きた人間だと納得させれば勝ち」で、発言ごとに%が加算される。ログを読み比べると:

- **勝ちパターン**: 「くうふくをかんじる」「みゃくがある」「しんぞうがうごいてる」…と**短い身体感覚を5連発すると各+20%で確実に100%到達**（yamagutiの勝利がまさにこれ。全部ひらがな短文）
- **負けパターン**: 「呼吸を止められるが生命維持衝動で再開する」のような論理的な長文は「身体感覚に10点」と**同カテゴリ扱いで+10%しか進まない**（Narazumonoは良い主張を重ねて20%止まりで敗北）
- 80%まで到達しても最後に「むかつく」と雑に打つと即defeat（ハッピー）

LLM判定の採点が主張の質と相関しておらず、むしろ簡潔な列挙が有利という逆転が起きている。

## 発見3: 監禁鬼が体験時間の大黒柱（かつ設計通りに機能）

脱出ゲームの監禁鬼は全チーム勝利したものの25〜59ターンを要し、登録からクリアまでの中央値52分。**80分イベントの中盤〜後半の大半はこの1体が占有**している。逆に険面鬼は写真送信1ターンで終わるため、鬼ごとの重さの分散が極端である。

## 地獄のICTへの示唆

1. **終盤ボスの較正**: 「最後の関門に全チームが同時滞留し、1/3が時間切れ」はレース形式のクライマックスとしては盛り上がる一方、閻魔の勝敗が主張の質でなく形式（短文連発）で決まるのは研修目的と乖離する。地獄のICTで判定にLLMを使う箇所は、**良い入力が確実に良い評価を得るかを事前較正する**工程が必要。
2. **時間予算**: コース中央値がちょうど制限時間に一致する較正は、半数完走を狙うなら理想的だが、全員完走を狙うなら10〜15分の余裕が要る。
3. **1コンテンツの重さの分散**: 1ターンの鬼と50ターンの鬼が混在すると、体感の山谷は作れるがボトルネック依存度が上がる。ステージ所要時間の設計時に、時間シンクをどの位置に何個置くかを意識的に決める。

## 再現方法

```bash
cd apps/worker
npx wrangler d1 execute hell-ai-conversation --remote --json \
  --command "SELECT * FROM conversations WHERE event_number=91 ORDER BY id"
npx wrangler d1 execute hell-ai-conversation --remote --json \
  --command "SELECT m.* FROM messages m JOIN conversations c ON c.id=m.conversation_id WHERE c.event_number=91 ORDER BY m.conversation_id, m.id"
npx wrangler d1 execute hell-ai-conversation --remote --json \
  --command "SELECT tp.*, t.name FROM team_progress tp JOIN teams t ON t.id=tp.team_id WHERE tp.event_number=91 ORDER BY tp.cleared_at"
```

補足: `messages.created_at` は会話内で同一時刻になっており（保存時に一括記録）、会話ごとの所要時間は `conversations.timestamp`（終了時刻）と `team_progress.cleared_at` から推定する。
